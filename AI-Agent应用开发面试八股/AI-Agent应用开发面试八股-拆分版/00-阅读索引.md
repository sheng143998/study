## 1. 为什么要拆分

原来的根目录 `../AI-Agent应用开发面试八股.md` 更像一本总复习手册，优点是完整，缺点是：

- 临面前不容易快速定位重点。
- LangChain、RAG、MCP、Python 等内容混在一个长文档里，复习节奏容易被打断。
- 后续继续补充牛客/Boss/JD 面经时，不方便按专题维护。
- 系统设计题和基础八股放在一起，容易分不清“背诵题”和“表达题”。

拆分后建议这样理解：

```text
总览与复习方法
  -> Agent / RAG / Prompt / Tool / 微调 / 协议 / Python 专题
  -> 系统设计与项目表达
  -> 大厂面试题库
  -> 参考资料与检索关键词
```

## 3. 推荐复习路线

### 3.1 只有 1 天突击

临战时不要在索引里继续横向浏览。按下面三条分流后，立刻离开 `00`：

```text
只剩 2 小时：去 `48 -> 80 -> 74 -> 78`，禁止继续读索引。
半天：去 `48 -> 55 -> 80 -> 74 -> 78`，先产出本次 JD 上场包。
1 天：去 `48 -> 55 -> 80 -> 74 -> 69 -> 52 -> 41 -> 77 -> 66 -> 78`，先按 `74` 减负，再完成模拟、评分、弱点登记和验收。
想查全量文件：才留在 `00`。
```

下面清单只适合“还有余力查漏”时使用，不是临战必读顺序。

1. 先打开 `48-面试通知速查导航卡.md`，再按剩余时间进入 `80`、`74`、`78`；半天及以上用 `55` 做分流，`66` 只作为验收口径，有余力再打开，不插入半天主路径。
2. 看 `01-总览-知识地图与复习方法.md` 的概念关系和 30 个速背答案。
3. 看 `18-自我介绍与项目包装.md`，先准备开场和项目 2 分钟版。
4. 看 `12-标准回答三件套.md`，背核心问题的 30 秒版。
5. 看 `04-RAG与向量数据库.md` 的 RAG 流程、召回不准、幻觉治理、评估。
6. 看 `14-系统设计图与伪代码.md`，背一个企业知识库或客服 Agent 架构；如果系统设计题被加约束，用 `67-系统设计变体与约束应对手册.md` 调整答题重心。
7. 用 `13-大厂连续追问链.md` 做一轮模拟追问。
8. 如果目标公司明确，看 `22-公司专项标准回答.md` 对应章节。
9. 如果是主管面或项目深挖，看 `24-项目答辩讲稿版.md`。
10. 如果要刷题，看 `27-P0P1P2题库扩容版.md` 的 P0 部分。
11. 知道题目但不知道看哪份时，用 `63-高频问题到文件定位索引.md` 快速定位主文件和补强文件。
12. 如果要练开口，看 `28-P0标准回答扩展版.md` 的 1-70 题。
13. LangChain/LangGraph 和后端 P0 看 `29-P0标准回答-LangGraph后端版.md`；如果被问 Transformer、token、embedding、temperature 等模型基础，用 `72-大模型基础与Embedding面试手册.md` 补齐。

## 6. 建议使用方式

不要从头到尾硬背。更有效的方式是按场景只选 1-3 个文件：

```text
收到通知：48 -> 80 -> 74/78。
不知道看哪份：36 或 63。
投递前：37/61/49。
项目表达：50/59/70。
模拟复盘：69/52/41/77。
维护资料库：47/79，仅维护者使用。
```

面试里最有区分度的不是名词解释，而是你能不能把问题讲成工程闭环：

```text
问题是什么
  -> 为什么会发生
  -> 怎么定位
  -> 怎么优化
  -> 怎么评估
  -> 线上怎么兜底
```
