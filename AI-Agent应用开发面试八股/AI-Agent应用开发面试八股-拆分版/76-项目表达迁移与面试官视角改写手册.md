# 76-项目表达迁移与面试官视角改写手册

> 目标：把同一个 AI Agent / RAG 项目，改写成不同岗位、不同公司、不同轮次都能听懂且愿意追问的表达。  
> 核心原则：项目不是背一篇固定稿，而是根据面试官关心的问题重新排序。

适用场景：

- 简历只有一个主项目，但投递了 RAG、Agent、后端、平台、Data Agent、ToB 等不同岗位。
- 面试官听完项目后没有追问，说明表达没有钩子。
- 项目真实做过，但讲起来像 Demo 或课程作业。
- 同一套回答在腾讯、阿里、百度、字节面试里显得“不对味”。

配合文件：

- `18-自我介绍与项目包装.md`：基础口播。
- `24-项目答辩讲稿版.md`：5 分钟项目答辩。
- `42-项目深挖追问防守库.md`：三层追问防守。
- `50-个人项目素材库模板.md`：项目素材收集。
- `58-简历逐行追问预案手册.md`：简历 bullet 防守。
- `59-项目分轮次口播稿模板.md`：按轮次切换口播。
- `70-项目作品集与Demo证据包手册.md`：证据包。
- `75-公司风格模拟面评分矩阵.md`：公司专项评分。

## 1. 项目表达的底层公式

项目表达不是“我做了什么功能”，而是这条链：

```text
业务问题
  -> 为什么普通方案不够
  -> 我负责哪一段
  -> 技术链路怎么跑
  -> 难点在哪里
  -> 我怎么定位和解决
  -> 结果如何验证
  -> 有哪些边界和下一步
```

任何岗位都可以用这个公式，但排序不同：

| 岗位/方向 | 优先讲 | 少讲 |
|---|---|---|
| RAG / 知识库 | 数据、切分、召回、rerank、引用、评测 | 过多工具平台细节 |
| Agent / Workflow | 状态、工具、终止条件、人工接管、trace | 只讲检索 |
| Python 后端 | FastAPI、异步、流式、限流、缓存、日志、异常 | 大段 Prompt 技巧 |
| 平台 / LLMOps | 模型网关、Prompt 版本、评测、观测、权限、成本 | 单点 Demo 效果 |
| Data Agent / NL2SQL | schema linking、指标口径、SQL 安全、权限、图表 | 泛泛“能查数据库” |
| ToB / 私有化 | 多租户、数据不出域、脱敏、审计、部署边界 | 只讲公网 API |
| 算法应用 | embedding、rerank、微调边界、评测集、bad case | 只讲业务页面 |

## 2. 一份项目素材，拆成 8 个面试钩子

把你的项目先拆成这 8 张卡：

| 卡片 | 你要准备什么 | 面试官会怎么追 |
|---|---|---|
| 背景卡 | 用户是谁，原流程痛点是什么 | 这个需求真实存在吗？ |
| 职责卡 | 你负责的模块、接口、策略、数据 | 这部分具体是不是你做的？ |
| 链路卡 | 请求从入口到输出怎么走 | 画一下架构图 |
| 难点卡 | 召回、幻觉、工具、权限、延迟、成本 | 你怎么定位？ |
| 证据卡 | 日志、trace、评测、bad case、README、字段 | 怎么证明？ |
| 指标卡 | 质量、延迟、成本、稳定性、安全 | 提升多少？没上线怎么办？ |
| 边界卡 | 没做什么、不能展示什么、下一步补什么 | 是不是 Demo？ |
| 迁移卡 | 面向不同岗位怎么重排 | 和我们岗位有什么关系？ |

如果一张卡没有内容，面试官追到那里就会断。

## 3. 同一项目的岗位改写

假设基础项目是：

```text
企业知识库 + 工具调用 Agent：支持用户自然语言提问，系统通过 RAG 检索企业文档，并在权限允许时调用订单/工单/API 工具，最后生成带引用和操作建议的回答。
```

### 3.1 改写成 RAG / 知识库岗

表达重点：

```text
这个项目我会重点讲 RAG 链路。离线侧我们做文档解析、清洗、结构化切分、embedding 入库和 metadata 管理；在线侧做 query rewrite、hybrid search、rerank、上下文构造和引用式生成。难点主要是召回不准、证据噪声和引用不可信，所以我用 trace 拆分召回、排序、生成三层定位，并通过 golden set 和 bad case 回流评估优化。
```

追问钩子：

- chunk 为什么这样切？
- hybrid search 为什么比纯向量稳？
- rerank 的收益和成本怎么评估？
- 引用怎么校验？
- 权限过滤放在检索前还是检索后？

### 3.2 改写成 Agent / LangGraph 岗

表达重点：

```text
这个项目我会重点讲 Agent 编排。系统不是让模型自由行动，而是把流程拆成意图识别、RAG、工具选择、参数校验、工具执行、结果校验和人工确认几个节点。状态里保存 user_id、intent、retrieved_docs、tool_result、risk_level 和 trace_id。查询类工具可以自动执行，高风险写操作必须确认，并且有最大步数、超时、fallback 和审计。
```

追问钩子：

- Agent 和 workflow 的边界是什么？
- state 里放什么，不放什么？
- 工具失败怎么恢复？
- 如何避免循环调用？
- 人工接管节点怎么设计？

### 3.3 改写成 Python 后端岗

表达重点：

```text
这个项目我会重点讲后端链路。入口用 FastAPI 提供对话接口和流式输出，内部把鉴权、限流、会话、检索、模型调用、工具调用和 trace 记录拆成独立模块。流式响应要处理客户端断连、模型超时、工具失败和重试；工具调用要做参数校验、幂等 key、超时和异常归一化。我的重点不是只调模型，而是把 AI 链路做成可观测、可降级的后端服务。
```

追问钩子：

- SSE / streaming 怎么实现？
- 异步任务和同步接口怎么拆？
- 限流、缓存、超时怎么做？
- 工具异常怎么统一处理？
- trace_id 怎么贯穿一次请求？

### 3.4 改写成平台 / LLMOps 岗

表达重点：

```text
这个项目我会抽象成一个 AI 应用平台：底层是模型网关，负责多模型路由、配额、限流和 fallback；中间是 Prompt 和工具注册中心，负责版本、权限、schema 和审计；上层是 RAG/Agent 编排和评测监控。业务方接入时不直接写死模型和工具，而是通过配置选择知识库、工具、Prompt 版本和评测集。
```

追问钩子：

- 多业务线如何复用？
- Prompt 怎么灰度和回滚？
- 模型网关如何做 fallback？
- 评测集如何接入发布流程？
- 成本怎么分摊到租户/业务线？

### 3.5 改写成 Data Agent / NL2SQL 岗

表达重点：

```text
如果岗位偏 Data Agent，我会把项目改写成自然语言查数助手。重点不是让模型直接生成 SQL，而是先做意图识别、schema linking、指标口径匹配，再生成 SQL。SQL 执行前要经过 AST 校验、只读限制、表字段白名单、行列权限、limit、超时和 cost 估算。结果返回时要给出 SQL、指标口径、时间范围、图表解释和不确定性。
```

追问钩子：

- schema linking 怎么做？
- 指标口径冲突怎么办？
- SQL 怎么防注入和危险操作？
- 结果错了怎么定位？
- 图表怎么保证可信？

### 3.6 改写成 ToB / 私有化岗

表达重点：

```text
如果岗位偏 ToB，我会重点讲安全、部署和交付。知识库、向量库、日志和对象存储要按租户隔离；文档 chunk 带 tenant_id、acl、doc_version，检索时权限下推；日志不能保存全量敏感 prompt，要做脱敏和访问控制。私有化部署时要说明模型、向量库、数据库、对象存储、日志系统分别放在哪里，以及哪些数据不能出域。
```

追问钩子：

- 数据不出域怎么保证？
- 缓存会不会串租户？
- 日志如何脱敏又能排障？
- 客户内部系统工具怎么授权？
- 私有化版本如何升级和回滚？

### 3.7 改写成算法应用岗

表达重点：

```text
如果岗位偏算法应用，我会重点讲 embedding、rerank、生成参数和评测。比如为什么只用向量检索不够，为什么要混合召回和 rerank；temperature、top_p 对稳定性的影响；什么时候考虑微调，什么时候只做 RAG；以及如何用 golden set、人工评分、faithfulness、citation accuracy 评估效果。
```

追问钩子：

- embedding 模型怎么选？
- rerank 为什么有效？
- RAG vs 微调怎么选？
- 如何构造评测集？
- 幻觉怎么量化？

## 4. 同一项目的公司改写

### 4.1 腾讯版

```text
我会先从用户体验讲：这个项目解决的是用户查知识、查订单和处理问题时反复切系统的痛点。技术上用了 RAG 和 Agent，但我更关注用户看到错答案、超时、工具失败时怎么办。我们通过引用、拒答、人工接管、工具确认和反馈闭环降低风险。
```

关键词：体验、反馈、兜底、人工接管、用户影响。

### 4.2 阿里 / 阿里云版

```text
我会把这个项目讲成平台化能力：模型网关、工具注册、权限中心、Prompt 版本、评测监控和审计日志。单个业务只是一个接入方，平台要支持多租户、私有化、配额、灰度和复用。
```

关键词：平台化、多租户、权限、审计、私有化、复用。

### 4.3 百度版

```text
我会重点讲 RAG 和 trace。每次请求都能拆到召回、排序、生成和后处理四层，bad case 可以判断是数据问题、召回问题、排序问题、生成问题还是权限/口径问题。如果岗位涉及 Data Agent，我会补 NL2SQL、指标口径和 SQL 安全。
```

关键词：搜索、RAG、trace、评测、Data Agent。

### 4.4 字节版

```text
我会重点讲指标和实验。这个项目的优化会拆成质量、延迟、成本和安全四组指标，通过 prompt_version、model_version、tool_version 和 trace_id 关联实验结果。线上出问题时要能灰度、回滚和定位。
```

关键词：指标、实验、成本、延迟、快速迭代、回滚。

### 4.5 ToB / 云厂商版

```text
我会重点讲交付边界。客户关心的不只是效果，而是数据是否出域、权限是否隔离、日志是否合规、工具是否可审计、系统是否可运维。模型只是组件，安全和治理决定能不能上线。
```

关键词：数据不出域、合规、审计、部署边界、运维。

## 5. 按轮次改写

| 轮次 | 项目表达目标 | 讲法 |
|---|---|---|
| 一面 | 证明你真做过，基础扎实 | 讲职责、模块、接口、代码、边界 |
| 二面 | 证明你能设计和排障 | 讲架构、难点、bad case、指标、取舍 |
| 交叉面 | 证明可迁移 | 讲通用问题、不同场景怎么改 |
| 主管面 | 证明业务价值和 owner 意识 | 讲价值、优先级、资源、风险、复盘 |
| HR 面 | 证明表达可信和不夸大 | 讲真实经历、协作、成长、边界 |

同一项目的 30 秒版：

```text
这是一个企业知识库和业务 Agent 项目，目标是把分散文档和内部工具统一成自然语言入口。我主要负责 RAG 检索、工具调用治理和后端接口。难点是召回、幻觉、工具安全和评测，我们用 hybrid search、rerank、引用校验、权限控制、trace 和 bad case 回流做治理。
```

同一项目的主管面版：

```text
这个项目的价值不是多一个聊天入口，而是降低业务人员查资料和跨系统操作的成本。技术上我关注效果，管理上我更关注边界：哪些场景能自动化，哪些必须人工确认；哪些指标已经验证，哪些还只是 Demo 阶段；如果上线，优先补权限、评测、监控和回滚。
```

## 6. 面试官视角改写

面试官听项目时通常在判断：

| 面试官心里问题 | 你的回答要证明 |
|---|---|
| 这个项目真实吗？ | 有具体模块、字段、日志、bad case |
| 你做了多少？ | 有职责边界和个人贡献 |
| 技术难点是真难还是包装？ | 有定位过程和失败样例 |
| 能不能上线？ | 有权限、评测、监控、成本、兜底 |
| 和岗位匹配吗？ | 关键词和 JD 方向一致 |
| 能不能继续追？ | 留出架构、指标、取舍、bad case 钩子 |

改写前后对比：

| 弱表达 | 强表达 |
|---|---|
| 我做了一个 RAG 问答系统 | 我负责了 RAG 检索链路，从文档切分、hybrid search、rerank 到引用校验和 bad case 评测 |
| 我接了工具调用 | 我把工具按查询、低风险写、高风险写分级，高风险工具需要确认、幂等和审计 |
| 效果还不错 | 我们用 Recall@K、引用准确率、人工评分和 bad case 回流评估；没有线上数据的部分我会明确说明 |
| 用了 LangGraph | 我用图结构把意图识别、检索、工具调用、确认、fallback 拆成节点，状态可恢复、可观测 |
| 支持数据分析 | 我把 NL2SQL 拆成 schema linking、指标口径、SQL AST 校验、权限过滤、结果解释 |

## 7. 项目表达自检表

每次改写后检查：

- [ ] 30 秒能讲清项目目标。
- [ ] 2 分钟能讲清背景、职责、链路、难点、结果。
- [ ] 5 分钟能画架构并讲 bad case。
- [ ] 至少有 3 个真实证据：接口、字段、日志、评测、README、Demo、bad case。
- [ ] 能说明没有做什么，不能展示什么，下一步补什么。
- [ ] 能按目标岗位重排重点。
- [ ] 能按目标公司换表达口径。
- [ ] 能接住“是不是 Demo”“是不是你做的”“效果怎么证明”三类追问。

## 8. 最终速背

1. 项目表达不是固定稿，而是按岗位、公司和轮次重新排序。
2. 一面讲真实职责和代码，二面讲架构和排障，主管面讲价值和边界。
3. 腾讯版讲用户和兜底，阿里版讲平台和多租户，百度版讲 RAG/trace/Data Agent，字节版讲指标和实验，ToB 版讲安全和交付。
4. 每个项目至少准备 8 张卡：背景、职责、链路、难点、证据、指标、边界、迁移。
5. 面试官不是听你背项目，而是在判断真实度、贡献度、难度、上线能力和岗位匹配。
