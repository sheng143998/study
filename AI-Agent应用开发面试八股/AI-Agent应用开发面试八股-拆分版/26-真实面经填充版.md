# 真实面经填充版

> 用法：本文件用于把公开面经/JD 线索沉淀成可维护证据库。  
> 注意：公开面经存在样本偏差，本文件只用于判断题型趋势，不把任何单条面经当作公司官方题库。

## 1. 使用原则

整理面经时坚持三点：

1. 面经负责判断“可能问什么”。
2. 官方文档和工程经验负责校准“应该怎么答”。
3. 不因一条面经就改变复习方向，只有重复出现或与 JD 高度匹配的题才提权。

可信度规则沿用 `21-面经证据库与错题本模板.md`：

- S：公司、岗位、轮次、时间、题目链路明确，且和 JD 高度匹配。
- A：公司和岗位明确，题目具体。
- B：题目具体，但公司/岗位/时间不完整。
- C：泛题单，仅作参考。
- D：明显拼接或概念错误，不纳入。

## 3. 题型趋势结论

### 3.1 P0 高频趋势

这些题和 JD/面经都高度匹配，必须能 2 分钟讲清楚：

| 题型 | 典型问法 | 为什么高频 |
|---|---|---|
| RAG 完整链路 | 离线和在线流程是什么？ | 大模型应用岗基础盘 |
| RAG 召回优化 | 召回不准怎么办？ | 能区分 Demo 和工程能力 |
| Agent 生产治理 | 如何防止死循环、误调用、失败恢复？ | 大厂关注稳定性 |
| Tool Calling 安全 | 参数错了、越权、重复执行怎么办？ | 真实业务落地核心 |
| 项目深挖 | 你做了什么、难点是什么、怎么评估？ | 所有公司都会问 |
| 后端流式与并发 | SSE、限流、超时、降级怎么做？ | AI 应用仍是后端系统 |
| 权限与审计 | RAG 权限过滤、工具审计怎么做？ | 企业场景必问 |

### 3.2 P1 中高频趋势

这些题常在二面或专项岗位出现：

| 题型 | 典型问法 | 目标岗位 |
|---|---|---|
| LangGraph | State、Node、Edge、checkpoint 怎么设计？ | Agent 工程师 |
| MCP | MCP 和 OpenAPI/RPC 区别？ | 工具平台/插件方向 |
| 模型路由 | 多模型接入、降级、成本怎么控制？ | 平台/后端 |
| 向量库索引 | HNSW、IVF、PQ 区别？ | RAG/搜索方向 |
| 微调 | RAG 和微调怎么选？LoRA 是什么？ | 算法偏应用 |
| SQL Agent | 自然语言转 SQL 如何防越权？ | 数据分析 Agent |

### 3.3 P2 低频但加分

这些不是每轮都问，但答好会显得更完整：

- LLM-as-judge 如何评估。
- Parent-child chunk。
- HyDE / multi-query retrieval。
- Prompt 版本化和 A/B。
- OpenAPI 自动转 Tool 的 schema 简化。
- 多 Agent 冲突处理。
- 长上下文摘要和结构化记忆。
- 英文项目表达。

## 4. 公司证据归纳

### 腾讯：风险治理和业务安全

公开线索中，腾讯类 AI 应用面试容易把 Agent 放到真实业务风险里问，例如资金安全、工具超时、失败中断、多 Agent 编排。

优先准备：

- Agent 失败恢复。
- 非幂等工具幂等设计。
- 高风险操作人工确认。
- RAG 热更新。
- 后端稳定性。

对应材料：

- `22-公司专项标准回答.md` 腾讯章节。
- `05-Prompt与ToolCalling.md`。
- `23-手撕题强化版.md` 的限流、重试、缓存。

### 阿里/阿里云：平台化和可扩展

公开线索中，阿里/阿里云类问题常把 AI 应用当平台系统问：Agent 循环、工具注册发现、状态上下文、多模型接入、SSE、RAG 切分。

优先准备：

- Tool registry。
- Model gateway。
- Prompt/model/tool 版本化。
- LangGraph 状态设计。
- SSE 和后端异步。

对应材料：

- `22-公司专项标准回答.md` 阿里章节。
- `03-LangChain与LangGraph.md`。
- `14-系统设计图与伪代码.md`。

### 百度：检索、Agent skill 和 Python 基础

公开线索中，百度类问题常覆盖 Python 基础、Agent skill、计划模式、检索策略、向量匹配指标。

优先准备：

- Python 基础和 asyncio。
- Agent skill/schema。
- Planner-Executor。
- embedding 相似度指标。
- 检索策略对比。

对应材料：

- `07-Python后端工程.md`。
- `22-公司专项标准回答.md` 百度章节。
- `04-RAG与向量数据库.md`。

### 字节：项目指标、性能和手撕

公开线索中，字节类问题更容易追问项目指标、性能瓶颈、QPS、成本、trade-off 和代码题。

优先准备：

- 项目难点按“现象、根因、方案、效果”讲。
- QPS 提升 10 倍。
- token 成本优化。
- 手撕限流、缓存、TopK。
- RAG pipeline 伪代码。

对应材料：

- `22-公司专项标准回答.md` 字节章节。
- `23-手撕题强化版.md`。
- `24-项目答辩讲稿版.md`。

## 5. 高频追问证据链

### RAG 召回不准

证据来源：

- JD 普遍要求 RAG、向量数据库、知识库。
- 面经反复出现 chunk、embedding、召回、rerank。
- 真实项目中这是最常见 badcase。

标准回答路径：

```text
badcase 评测集
  -> 文档解析
  -> chunk
  -> embedding
  -> query rewrite
  -> hybrid search
  -> rerank
  -> metadata filter
  -> Recall@K/MRR/NDCG
```

### Agent 工具安全

证据来源：

- Agent 岗位 JD 常要求工具调用、外部系统接入。
- 公开面经常追问失败、中断、高风险操作。
- 大厂业务系统关注权限、幂等、审计。

标准回答路径：

```text
模型只生成意图
  -> schema 校验
  -> 用户鉴权
  -> 风险等级判断
  -> 人工确认
  -> 幂等 key
  -> 超时/状态查询
  -> 审计日志
```

### 多模型和流式输出

证据来源：

- AI 应用后端 JD 常要求模型接入和流式响应。
- 面经中常出现 SSE、多模型架构、模型切换。

标准回答路径：

```text
model gateway
  -> adapter
  -> 统一 chat/embed/rerank/stream/tool 接口
  -> 灰度
  -> A/B
  -> fallback
  -> token/cost/latency 监控
```
