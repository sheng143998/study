# 面试通知速查导航卡

> 目标：收到面试通知后，5 分钟内决定该看哪些文件、练哪些题、准备哪些表达。  
> 这份文件是临战入口，不讲新知识，只做决策导航。

## 1. 先读面试通知里的 4 个变量

拿到通知后，先填：

```markdown
# 面试通知速查

- 公司：
- 岗位：
- 轮次：
- 面试时间：
- 剩余准备时间：
- JD 关键词：
- 是否代码面：
- 是否主管/HR 面：
```

然后按下面顺序决策：

```text
公司
  -> 岗位
  -> 轮次
  -> 剩余时间
  -> 5分钟行动卡
  -> `80` 生成 JD 实战转化工单
```

硬规则：

```text
收到通知后，先用本文件定方向，再用 `80-JD实战转化闭环工单.md` 生成交付物。
没有工单，不开始随机刷题。
```

## 2. 5分钟行动卡

5分钟内只做一件事：把通知压进 `80`。不要按公司、岗位、轮次横向打开文件。

```markdown
# 5分钟行动卡

- 剩余时间：2 小时 / 半天 / 1 天 / 3 天
- 轮次：一面 / 二面 / 代码 / 系统设计 / 主管HR
- JD top3：
  1.
  2.
  3.
- 公司口径一句话：
- 最高风险题 30 秒版：
- 只允许补 1 个专题候选：
```

决策规则：

| 情况 | 只给 `80` 填什么 |
|---|---|
| 刚拿到 JD | 填 JD top3 和最高风险题，不打开 `37/38/46` |
| 公司明确 | 填公司口径一句话，不打开公司资料 |
| 岗位明确 | 填 1 个专题候选，不打开专题 |
| 轮次明确 | 填轮次和面试官可能关注点 |
| 想模拟或闭环 | 先完成 `80` 本轮目标；半天只口述自评，1 天及以上再进入 `69/77/66` |

## 3. 按剩余时间选择

### 3.1 只剩 2 小时

不要系统复习，直接保命：

```text
80：只填 2小时极速包和 10分钟迷你题单
74：只执行 2 小时路线，不打开新专题
78：最后启动
```

唯一补弱文件按面试类型选，不要多开：

| 面试类型 | 只允许补 1 个文件 |
|---|---|
| 技术一面 | `28` 或 `29` |
| 代码面 | `44` 或 `45` |
| 系统设计 / 平台 | `51` 或 `67` |
| Data Agent / NL2SQL | `73` |
| 安全 / ToB | `71` |
| 主管 / HR | `43` 或 `40` |

2 小时硬停规则：

```text
只允许补 1 个最弱文件。
如果 80 的 2小时极速包：8项已填完，禁止继续扩展专题。
如果距离面试不足 30 分钟，直接去 78，不再打开 74。
```

### 3.2 只剩半天

通用路线：

```text
48：确认公司 / 岗位 / 轮次 / 剩余时间
55：只看目标公司和轮次的分流
80：生成本次 JD 工单和一页上场包
74：执行半天路线，只按轮次选专题
78：最后启动
```

半天不要横向打开专题文件。需要补 `18/42/28/29/40/46` 时，只在 `74` 的半天路线里按轮次选择，不把它们写进主路径。

### 3.3 只剩 1 天

1 天主链：

```text
48 -> 55 -> 80 -> 74 -> 69 -> 52 -> 41 -> 77 -> 66 -> 78
```

时间盒：

```text
上午：55 定公司/轮次口径 -> 80 写 1 天闭环工单 -> 74 执行时间盒。
下午：只按 74 的 1 天时间盒补 1-2 个专题，不横向打开文件矩阵。
晚上：69 生成题单 -> 52 模拟 -> 41 自评 -> 77 登记 Top2 -> 66 验收 -> 78 启动。
```

可替换专题只在 `74` 的时间盒里使用：

```text
项目/JD：37 / 38 / 18 / 20
P0/基础：28 / 29
RAG：04 / 30
Agent：02 / 03
Tool/MCP：05 / 08 / 31
后端/代码：07 / 44
平台/系统设计：32 / 14
```

### 3.4 有 3 天

按这条 3 天主链：

```text
Day 1: 48 -> 55 -> 80 -> 74 -> 项目/P0
Day 2: 专题补强 -> 69 -> 52 -> 41 -> 77
Day 3: 复测/公司专项 -> 66 -> 78
```

可选插槽：`39` 做日程、`46` 看趋势、`40` 校准公司打法、`75` 做公司专项评分；不要替代上面的 Day 1/2/3 主链。

## 5. 按岗位选择

### 5.1 RAG / 知识库岗

最短组合：

```text
04 + 30 + 14 + 42
```

候选问题：

- RAG 完整链路。
- chunk 怎么切。
- 图片/表格/PDF 怎么处理。
- 召回不准怎么定位。
- rerank 有什么价值。
- 引用溯源和幻觉治理。
- 权限过滤和增量更新。

### 5.2 Agent / LangGraph 岗

最短组合：

```text
02 + 03 + 05 + 29 + 42
```

候选问题：

- Agent 和普通 Chatbot 区别。
- ReAct 流程。
- LangGraph 为什么适合有状态流程。
- state 怎么设计。
- checkpoint 有什么价值。
- Agent 死循环怎么办。
- 工具调用失败怎么办。

### 5.3 Tool / MCP / 平台岗

最短组合：

```text
08 + 31 + 32 + 42
```

候选问题：

- OpenAPI、RPC、MCP 区别。
- MCP Server 暴露什么。
- OpenAPI 如何转 Tool。
- Tool schema 怎么设计。
- 工具权限和审计。
- 工具版本兼容。
- 工具平台系统设计。

### 5.4 Python 后端岗

最短组合：

```text
07 + 29 + 44 + 45
```

候选问题：

- FastAPI 为什么适合 LLM 应用。
- asyncio 适合什么场景。
- SSE 怎么实现。
- 用户断连怎么办。
- 限流、缓存、重试。
- LRU、限流、并发执行器。

### 5.5 平台 / 模型网关岗

最短组合：

```text
32 + 14 + 40 + 43
```

候选问题：

- 模型网关。
- 多模型路由。
- Prompt 版本管理。
- 评测平台。
- 成本治理。
- 多租户权限。
- 灰度和回滚。

## 6. 按公司选择表达重心

| 公司 | 开口重心 | 避免 |
|---|---|---|
| 腾讯 | 用户体验、业务场景、线上 bad case | 只讲框架名 |
| 阿里 | 平台化、治理、复用、抽象 | 只讲单点功能 |
| 百度 | RAG、检索、模型效果、评测 | 只讲业务包装 |
| 字节 | 指标、实验、代码、迭代 | 只说感觉变好 |
| 美团/京东 | 业务流程、成本效率、稳定性 | 只讲技术炫技 |
| 华为/云厂商 | 标准化、权限、审计、交付 | 忽略企业级治理 |
| 初创 | 端到端交付、MVP、成本控制 | 只讲大平台架构 |

## 8. 最短闭环

如果你已经慌了，就按这个：

```text
2 小时：48 -> 80 -> 74 -> 78
半天：48 -> 55 -> 80 -> 74 -> 78
1 天：48 -> 55 -> 80 -> 74 -> 69 -> 52 -> 41 -> 77 -> 66 -> 78
```

半天只在 `80/74` 内口述自评；`69/52/41/77/66` 只放进 1 天及以上闭环。

代码面加：

```text
44 + 45
```

主管/HR 面加：

```text

```

最后一句：

```text
临面前不要追求看完资料，只追求让这一轮最可能问的问题有答案。
```
