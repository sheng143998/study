# 真实 JD 案例填充版

> 目标：把公开招聘描述里的岗位语言，拆成“岗位类型、面试重点、简历改法、复习路径”。  
> 本文件适合配合 `37-JD关键词匹配与投递策略.md` 使用。

边界说明：

- 本文件只放“完整 JD 类型案例”和对应简历/复习路径。
- 近期趋势权重放 `68`。
- 公司轮次题型矩阵放 `46`。
- 可直接陪练的题单放 `69`。

## 1. 使用说明

每看到一个 JD，都按下面 6 步处理：

```text
摘关键词
  -> 判岗位类型
  -> 估面试权重
  -> 改简历 bullet
  -> 选复习文件
  -> 反推 10 个高频追问
```

不要被 JD 里的技术名词带着跑。真正重要的是：

- 职责里反复出现的词。
- “负责、设计、优化、上线、建设”后面的对象。
- 任职要求里的必备项。
- 加分项是否会影响一面。
- 这个岗位到底是做业务应用、平台工程、算法优化，还是后端服务。

## 2. 案例 1：企业知识库 RAG 应用岗

### 2.1 模拟 JD 摘录

```text
负责企业内部知识库问答系统建设，支持文档解析、知识切片、向量检索、重排序、答案生成、引用溯源和效果评估。
熟悉 LangChain、向量数据库、embedding/reranker，有 RAG 项目经验优先。
```

### 2.2 关键词拆解

| 关键词 | 类型 | 面试含义 |
|---|---|---|
| 企业内部知识库 | 业务场景 | 会问权限、文档更新、部门隔离 |
| 文档解析 | 数据处理 | 会问 PDF/Word/HTML 解析和清洗 |
| 知识切片 | RAG 核心 | 会问 chunk size、overlap、语义切分 |
| 向量检索 | 检索核心 | 会问 embedding、索引、metadata filter |
| 重排序 | 效果优化 | 会问 reranker 成本、位置、收益 |
| 引用溯源 | 幻觉治理 | 会问答案如何绑定证据 |
| 效果评估 | 生产落地 | 会问 golden set、召回率、人工评估 |

### 2.3 岗位判断

主方向：RAG 应用开发。  
副方向：Python 后端、检索优化、效果评估。  
不是纯 Agent 岗，也不是纯算法微调岗。

### 2.4 面试 P0

1. RAG 完整链路是什么？
2. chunk 怎么切？
3. 召回不准怎么优化？
4. rerank 为什么有用？
5. 如何减少幻觉？
6. 如何做引用溯源？
7. 向量数据库怎么选？
8. 知识库如何增量更新？
9. 权限过滤在召回前还是召回后？
10. 如何评估 RAG 效果？

### 2.5 简历改法

弱：

```text
使用 LangChain 搭建企业知识库问答系统。
```

强：

```text
负责企业知识库 RAG 问答链路，完成文档解析、语义切分、向量召回、rerank、引用溯源和无答案识别；构建离线评测集定位召回与生成问题，优化核心问题命中率和答案可追溯性。
```

## 3. 案例 2：AI Agent 工作流开发岗

## 11. 从 JD 反推出反问

### RAG 岗反问

- 当前知识库主要文档类型是什么？
- 效果评估更关注召回、准确率、引用，还是用户满意度？
- 是否有线上 bad case 回流机制？

### Agent 岗反问

- Agent 主要执行哪些高风险工具？
- 哪些步骤允许自动执行，哪些需要人工确认？
- 当前更关注任务成功率、成本，还是执行稳定性？

### 工具平台岗反问

- 工具接入主要来自 OpenAPI、内部 RPC，还是 MCP Server？
- 是否已有统一工具 schema 和调用审计？
- 插件生态是内部使用还是面向外部开发者？

### 后端岗反问

- 线上流式响应主要用 SSE 还是 WebSocket？
- 模型调用是否有统一网关、限流和成本统计？
- 当前最大稳定性问题是延迟、失败率，还是并发峰值？

### 微调岗反问

- 当前效果瓶颈更偏知识缺失、指令遵循，还是输出格式？
- 是否已有人工标注数据和离线评测集？
- 微调结果如何和 RAG/Prompt 优化做对比？

### 平台岗反问

- 平台服务几个业务线或租户？
- Prompt、模型、工具是否都有版本管理和灰度机制？
- 目前成本治理和效果评测是独立系统还是平台内置？
