# 面试官陪练脚本手册

> 目标：把模拟面从“刷题”变成“真实追问演练”。  
> 适合自己录音练，也适合让同学/朋友按脚本扮演面试官。

## 1. 陪练规则

陪练不要急着给提示。面试官脚本要做到：

```text
先问开放题
  -> 再追细节
  -> 再追取舍
  -> 再追指标
  -> 最后追复盘
```

记录时只记 4 类问题：

- 答不上。
- 答得虚。
- 答偏了。
- 没有项目证据。

评分用 `41-面试官评分Rubric与回答自检表.md`。

## 2. 15 分钟一面脚本

### 2.1 面试官开场

```text
我们先简单聊一下你的项目和基础。你先用 1 分钟介绍一下自己，以及你做过的 AI Agent / RAG 相关项目。
```

追问分支：

```text
你在项目里具体负责什么？
这个项目现在是什么阶段，Demo、内部试点还是线上？
项目里最核心的技术难点是什么？
```

通过标准：

- 能在 1-2 分钟讲清项目。
- 能明确自己的职责。
- 不夸大项目阶段。
- 能说出 1 个真实难点。

### 2.2 RAG 基础追问

```text
你讲到了知识库/RAG。那你说一下 RAG 的完整链路。
```

追问分支：

```text
chunk 怎么切？
召回不准怎么定位？
rerank 放在哪一层？
如何减少幻觉？
引用溯源怎么做？
```

通过标准：

- 能按解析、切分、embedding、召回、rerank、生成、引用讲。
- 能分层定位问题。
- 能提到评测指标。

### 2.3 Agent / Tool 基础追问

```text
如果这个系统需要调用外部工具，你会怎么设计 Tool Calling？
```

追问分支：

```text
Tool schema 包含什么？
参数校验在哪里做？
工具失败怎么办？
高风险工具如何确认？
Agent 死循环怎么办？
```

通过标准：

- 明确模型不直接执行工具。
- 能讲 schema、权限、审计、失败恢复。
- 能讲 max steps、timeout、human confirm。

### 2.4 Python / 代码基础追问

```text
如果要做流式输出，你后端怎么实现？
```

追问分支：

```text
SSE 和 WebSocket 怎么选？
用户断连怎么办？
模型调用超时怎么办？
写一个简单限流器你会怎么写？
```

通过标准：

- 能解释 SSE 适合 LLM token streaming。
- 能提到 async generator、断连取消、超时、限流。
- 至少能口述一种限流算法。

## 3. 45 分钟项目深挖脚本

### 3.1 项目入口

```text
你选一个最熟的大模型应用项目，按背景、方案、你的贡献、结果讲 3 分钟。
```

追问分支：

```text
用户是谁？
为什么这个问题需要大模型？
如果不用大模型，传统方案怎么做？
你负责的代码或模块有哪些？
```

通过标准：

- 有业务背景。
- 有技术方案。
- 有个人贡献。
- 有结果或试点评估。

### 3.2 真实性拷打

```text
我想确认一下细节。你们数据规模大概多大？文档/工具/接口分别是什么量级？
```

追问分支：

```text
文档怎么入库？
向量库选型依据是什么？
接口 QPS 或调用量多少？
日志里记录哪些字段？
```

通过标准：

- 不编造。
- 能说大致量级或说明没有线上量。
- 能讲字段、接口、模块边界。

### 3.3 Bad Case 深挖

```text
讲一个你们遇到过的 bad case，最好是真实定位过的。
```

追问分支：

```text
这个 bad case 表现是什么？
根因在哪一层？
你怎么定位出来的？
改完后怎么验证？
有没有加入回归测试？
```

通过标准：

- 能把问题归因到解析/切分/召回/rerank/生成/工具/权限某一层。
- 有定位过程。
- 有验证方式。

### 3.4 贡献度追问

```text
这个项目里哪些是你亲自做的？哪些是团队其他同学做的？
```

追问分支：

```text
你写过的核心代码是什么？
你参与过哪些方案取舍？
有没有你推动的优化？
如果把你拿掉，这个项目会少什么？
```

通过标准：

- 清楚区分主责和参与。
- 能讲自己实现的模块。
- 不把团队成果都说成自己的。

## 4. 60 分钟系统设计脚本

### 4.1 企业知识库题

```text
设计一个企业内部知识库问答系统，支持权限控制、引用溯源和效果评估。你先澄清需求，然后画核心架构。
```

追问分支：

```text
权限过滤在召回前还是召回后？
PDF 表格怎么处理？
文档增量更新怎么做？
如何评估 RAG 效果？
如果答案错了怎么排查？
如果 QPS 提升 10 倍怎么改？
如果要求 2 秒内返回首字怎么改？
如果同一个系统服务多个租户怎么隔离？
```

通过标准：

- 先澄清再设计。
- 离线入库和在线问答分清楚。
- 有权限、评测、bad case、日志。
- 被追加高并发、低延迟、多租户约束时，能说明影响层、模块调整和指标。

### 4.2 Agent 工具平台题

```text
设计一个 Agent 工具调用平台，支持 OpenAPI/MCP 工具接入、权限、审计和失败恢复。
```

追问分支：

```text
OpenAPI 如何转 Tool？
MCP 和 OpenAPI 怎么配合？
Tool Registry 里存什么？
工具版本怎么兼容？
Prompt 注入诱导工具调用怎么办？
如果高风险工具要执行退款/删除/审批怎么办？
如果工具 schema 很差，模型老是传错参数怎么办？
如果几十个业务系统都要接入，工具太多怎么选？
```

通过标准：

- 能分工具接入、运行时、治理三层。
- 能讲 schema、auth、audit、version。
- 能讲高风险工具人工确认。
- 能区分 OpenAPI、RPC wrapper、MCP server、SDK adapter 的接入边界。

### 4.3 模型网关题

```text
设计一个公司内部模型网关，支持多业务线、多模型路由、限流、成本统计和降级。
```

追问分支：

```text
路由策略有哪些？
限流按什么维度？
成本怎么统计？
供应商挂了怎么 fallback？
Prompt 版本和模型版本怎么关联？
如果要求成本降低 50% 怎么做？
如果某个模型 fallback 后质量明显变差怎么办？
如果客户要求私有化和敏感数据不出域怎么办？
```

通过标准：

- 能讲入口鉴权、路由、provider adapter、观测、成本。
- 能讲 fallback 风险。
- 能讲灰度和回滚。
- 能同时回答 SLA、成本、数据边界和灰度评测。

## 5. 30 分钟代码面脚本

### 5.1 LRU / 限流

```text
我们写一道小题。实现一个 LRU Cache 或滑动窗口限流器，你先讲思路再写。
```

追问分支：

```text
复杂度是多少？
并发下安全吗？
分布式怎么做？
如果用于大模型网关，还要加什么？
```

通过标准：

- 主逻辑能写出来。
- 能自测。
- 能讲生产增强。

### 5.2 RAG 小工程

```text
写一个多路召回合并去重函数，输入向量召回和关键词召回结果，输出 top-k。
```

追问分支：

```text
两路分数能直接加吗？
为什么用排名融合？
如何处理重复文档？
如何做 rerank？
```

通过标准：

- 能解释分数不可比。
- 能用 doc_id 去重。
- 能讲 RRF 或简化排名融合。

## 6. 30 分钟主管面脚本

### 6.1 项目价值

```text
你做的这个项目，对业务有什么价值？
```

追问分支：

```text
怎么证明不是 Demo？
如果效果不好怎么办？
如果重新做，你会改什么？
你推动了哪些协作？
```

通过标准：

- 不只讲技术。
- 能讲业务目标、结果、复盘。
- 有 ownership。

### 6.2 职业规划

```text
你未来 1-3 年想往哪个方向发展？
```

追问分支：

```text
为什么是 AI 应用开发？
你更想做业务落地、平台工程还是模型算法？
你觉得自己的短板是什么？
```

通过标准：

- 方向清晰。
- 和岗位匹配。
- 不空喊“想学 AI”。

## 7. 公司风格变体

### 腾讯问法

```text
这个功能对用户体验有什么改善？有没有真实用户反馈？线上 bad case 怎么处理？
```

重点记录：

- 是否讲用户。
- 是否讲体验。
- 是否讲线上兜底。

### 阿里问法

```text
如果这个能力要给多个业务线复用，你会怎么抽象？权限、审计、版本怎么做？
```

重点记录：

- 是否讲平台化。
- 是否讲多租户。
- 是否讲治理。

### 百度问法

```text
检索和模型效果怎么评估？召回和排序分别怎么优化？RAG 和微调怎么选？
```

重点记录：

- 是否讲检索细节。
- 是否讲评测。
- 是否讲模型边界。

### 字节问法

```text
你怎么定义指标？怎么做实验？如何证明优化有效？代码题写一下。
```

重点记录：

- 是否讲 baseline。
- 是否讲 A/B。
- 是否能写代码。

## 9. 陪练结束后的复盘动作

```text
先用 41 打分
  -> 用 35 记录错题
  -> 用 42 补项目防守
  -> 用 44/45 补代码
  -> 用 51 补系统设计口播
  -> 下次只练最弱的 3 个点
```

## 10. 最后速记

```text
好陪练不是问更多题，
而是把一个问题追到：

是否真实
  -> 是否清楚
  -> 是否能落地
  -> 是否有指标
  -> 是否能复盘
```

一句话：

```text
模拟面要练的不是“背得顺”，而是“被追问时不散”。
```
