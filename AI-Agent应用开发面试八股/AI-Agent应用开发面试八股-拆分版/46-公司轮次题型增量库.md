# 公司轮次题型增量库

> 目标：把公开面经、JD 和真实复盘里的零散信号，整理成“公司 × 轮次 × 题型 × 准备动作”。  
> 注意：本文件是公开线索归纳，不是任何公司的官方题库。单条面经有噪声，必须看趋势，不要迷信原题。

## 1. 使用原则

不要把面经当答案背。正确用法是：

```text
看公开线索
  -> 提炼题型
  -> 映射到专题文件
  -> 准备项目例子
  -> 模拟连续追问
  -> 面后回流更新
```

判断可信度：

| 可信度 | 信号来源 | 使用方式 |
|---|---|---|
| 高 | 多篇面经反复出现、JD 也明确要求 | 作为 P0 准备 |
| 中 | 单篇面经出现，但和岗位职责高度相关 | 作为 P1 准备 |
| 低 | 单个帖子、无上下文、题目过于离散 | 只作参考 |

## 4. 腾讯题型增量

### 4.1 一面

高频题型：

1. 讲一个你做过的大模型应用项目。
2. RAG 项目怎么评估效果？
3. 召回不准怎么定位？
4. Agent 工具调用失败怎么办？
5. Python 后端如何处理流式输出？
6. 你项目里的真实用户是谁？
7. 有没有线上 bad case？

准备动作：

- 用 `18` 准备 2 分钟项目入口。
- 用 `42` 准备三层项目追问。
- 用 `04` 背 RAG 链路。
- 用 `44` 默写 SSE / 限流 / LRU。

### 4.2 二面

2. 如何做权限过滤和引用溯源？

4. Agent 误调用工具怎么兜底？
5. 如何在体验、准确率、成本之间取舍？

准备动作：

- 用 `14` 背企业知识库架构。

- 用 `40` 切换成腾讯表达：用户体验、真实场景、线上兜底。

## 10. 轮次题型趋势

### 10.1 一面越来越像“项目 + 基础 + 小代码”

准备优先级：

1. 项目是否真实。
2. RAG/Agent/Python P0 是否能开口。
3. 是否能写小工程题。
4. 是否能解释复杂度和生产增强。

推荐组合：

```text
18 + 28 + 29 + 44 + 45
```

### 10.2 二面越来越像“系统设计 + 追问链”

准备优先级：

1. 能否设计企业知识库 / Agent 工具平台 / 模型网关。
2. 能否处理 bad case。
3. 能否讲指标和权衡。
4. 能否从单点功能上升到平台治理。

推荐组合：

```text
13 + 14 + 30 + 31 + 32 + 42
```

### 10.3 主管面越来越看“业务闭环”

准备优先级：

1. 项目为什么有价值。
2. 你具体推动了什么。
3. 失败或效果不好怎么复盘。
4. 和产品/业务/算法怎么协作。

推荐组合：

```text
24 + 40 + 41 + 43
```

### 12.1 2026 新增专项题型


### Agent 成功率专项

典型追问：

1. 一个 Agent 任务怎样才算成功？
2. 失败样本如何分类：规划错、工具错、检索错、权限错、模型幻觉？
3. 如何用 trace 做 replay/debug？
4. 自动评测和人工评审怎么结合？
5. 成功率提升后，成本和延迟是否恶化？

准备动作：

- 用 `54` 准备指标。
- 用 `77` 建模拟面总账本。
- 用 `32` 准备平台化评测。

### MCP / A2A 协议边界专项

典型追问：

1. MCP 解决什么，A2A 解决什么？
2. MCP server 暴露工具和资源时，权限在哪里做？
3. A2A 的 agent-to-agent delegation 如何避免责任不清？
4. 多 Agent 协作的身份、授权、审计怎么落？
5. 协议层是否能替代业务安全？
6. MCP 里 resources、prompts、tools 的边界分别是什么？
7. sampling/模型调用由谁授权，客户端还是 server？
8. 工具返回的资源是否需要再次做 ACL 和脱敏？

准备动作：

- 用 `08` 先校准协议概念。
- 用 `71` 准备安全边界。
- 用 `32` 准备企业 Agent 平台设计。

一句话答案：

```text
MCP 连接上下文和动作：resources 给上下文，prompts 给模板，tools 做动作；它不替代业务鉴权、审批、审计和数据脱敏。
MCP 是 agent-to-tool/resource，A2A 是 agent-to-agent delegation；面试里要补 scope、caller_agent、delegate_agent、result_schema。
```

## 14. 参考线索
