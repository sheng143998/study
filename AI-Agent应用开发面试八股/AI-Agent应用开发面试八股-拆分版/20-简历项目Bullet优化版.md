# 简历项目 Bullet 优化版

> 用法：把这里的 bullet 当成“写法模板”，不要照抄虚构指标。真实指标不知道就写“构建了评测集”“支持了链路追踪”“完成了原型/灰度”，别硬编 DAU、QPS、准确率。

## 1. 简历项目的基本原则

AI Agent / RAG 项目在简历上最怕写成：

```text
使用 LangChain 实现了一个智能问答系统。
```

这个写法太薄，面试官看不出：

- 你解决了什么业务问题。
- 你负责哪一块。
- 系统链路是否完整。
- 有什么工程难点。
- 是否做过效果评估。
- 是否考虑线上稳定性。

更好的 bullet 应该包含：

```text
业务场景 + 技术动作 + 工程难点 + 结果/指标/可验证产出
```

推荐结构：

```text
动词 + 模块 + 技术方案 + 解决的问题 + 结果
```

例如：

```text
负责企业知识库 RAG 检索链路，完成文档解析、结构化切分、Embedding 入库、混合召回与 Rerank，解决制度文档召回不准和答案缺少引用的问题。
```

## 2. RAG 项目简历模板

### 版本 A：企业知识库问答

```text
项目：企业知识库智能问答系统

- 负责 RAG 检索生成链路设计，构建文档采集、解析清洗、结构化切分、Embedding 入库、向量召回、Rerank 和答案生成流程。
- 基于文档标题层级、段落结构和 token 长度设计 chunk 策略，保留 doc_id、page、section、tenant_id、permission、version 等元数据，支持引用溯源和权限过滤。
- 引入向量检索 + BM25 混合召回，并在粗召回后接入 Reranker，提高专有名词、制度条款、错误码等场景的召回稳定性。
- 设计基于证据的 Prompt 和引用校验逻辑，要求模型无依据时拒答，降低无依据生成和引用编造风险。
- 建立 badcase 分析流程，记录 query、召回 chunk、rerank 分数、模型答案和用户反馈，用于迭代切分、召回和 Prompt 策略。
```

### 版本 B：客服知识库

```text
项目：智能客服知识库问答与工单辅助系统

- 参与智能客服 RAG 模块建设，将售后政策、产品 FAQ、历史工单等资料接入知识库，支持客服通过自然语言查询规则和处理建议。
- 设计文档切分与元数据体系，按业务线、产品、地区、版本和权限标记 chunk，避免不同业务规则混淆。
- 优化检索链路，结合 query rewrite、hybrid search、rerank 和 top_k 控制，提升长尾问题和口语化问题的召回质量。
- 在回答生成阶段加入引用约束、敏感信息过滤和无答案策略，减少模型幻觉和不合规回复。
- 接入 trace 日志，记录检索、重排、Prompt、模型输出和用户反馈，支持客服 badcase 复盘。
```

### 版本 C：代码/技术文档 RAG

```text
项目：研发知识库与代码文档问答系统

- 构建面向研发文档和代码仓库的 RAG 问答系统，支持对接口文档、设计文档、错误日志和代码片段进行语义检索。
- 针对 Markdown、代码块和 API 文档设计结构化切分策略，保留标题路径、函数名、文件路径和版本信息，提升技术问题定位能力。
- 使用向量召回结合关键词检索处理函数名、错误码、类名等精确匹配问题，并通过 Rerank 提升候选文档排序质量。
- 设计回答 Prompt，要求模型基于检索片段给出解释、引用路径和后续排查建议，避免编造不存在的 API 或配置项。
```

## 3. Agent 项目简历模板

### 版本 A：客服 Agent

```text
项目：客服业务处理 Agent

- 设计客服 Agent 编排流程，将用户意图识别、知识库检索、订单查询、退款规则判断、工单创建和人工转接拆分为可控节点。
- 基于工具 schema 封装订单查询、工单查询、创建工单等能力，统一进行参数校验、权限检查、超时控制和调用日志记录。
- 对退款、改地址、取消订单等高风险操作加入用户确认、幂等 key 和审计记录，避免模型误调用导致重复或越权操作。
- 使用状态字段维护 intent、retrieved_docs、tool_results、pending_action、approval_status 和 final_answer，支持多轮任务上下文管理。
- 设计 fallback 策略，在工具失败、模型输出不合法或连续多步未完成时转人工或返回可解释错误。
```

### 版本 B：数据分析 Agent

```text
项目：自然语言数据分析 Agent

- 构建面向业务人员的数据分析 Agent，支持基于自然语言生成 SQL、查询数据、解释指标并输出图表建议。
- 设计 schema 检索模块，根据用户问题召回相关表、字段和指标口径，减少全量 schema 输入带来的上下文噪声。
- 对模型生成 SQL 进行 AST 级安全校验，限制只读查询、表白名单、字段权限、limit 和执行超时，降低越权与高成本查询风险。
- 对查询结果进行脱敏和采样后再交给模型解释，避免敏感字段泄露和大结果集导致的上下文膨胀。
- 记录 question、schema context、SQL、执行耗时、结果规模和模型解释，用于审计和 badcase 复盘。
```

### 版本 C：办公自动化 Agent

```text
项目：办公自动化 Agent

- 设计面向日常办公场景的 Agent 流程，支持邮件草拟、会议纪要整理、文档检索、任务创建和日程查询等能力。
- 将外部能力封装为 Tool，并通过 schema、description 和 risk_level 管理工具选择、参数校验和风险控制。
- 对发送邮件、创建任务、修改日程等写操作加入预览确认，模型只生成草稿和动作建议，最终执行由用户确认触发。
- 增加会话摘要和任务状态管理，支持多轮上下文中持续跟踪待办、收件人、时间和确认状态。
```

## 4. LangChain / LangGraph 简历写法

### 不推荐

```text
熟悉 LangChain，使用 LangChain 搭建 Agent。
```

### 推荐

```text
- 使用 LangChain Runnable/LCEL 组合 Prompt、Retriever、Model 和 OutputParser，实现可流式、可观测的 RAG 问答链路。
- 基于 LangChain Tool 抽象封装业务 API，定义工具名称、描述、参数 schema 和返回结构，降低模型误调用概率。
- 使用 LangGraph 将复杂 Agent 流程拆分为 router、retrieve、tool_call、validate、human_review 和 final_answer 等节点，显式管理状态、条件分支和终止条件。
- 接入 checkpoint 机制保存任务状态，支持长任务恢复、人工确认后继续执行和异常回放分析。
```

## 5. MCP / OpenAPI / 工具平台简历写法

```text
项目：大模型工具接入平台 / MCP 工具服务

- 设计 AI 工具接入层，将内部 OpenAPI/RPC 服务封装为模型可调用工具，统一管理工具描述、参数 schema、鉴权、限流和审计。
- 基于 OpenAPI 解析接口路径、方法、请求参数和响应 schema，筛选只读或低风险接口生成工具定义，避免将全部内部 API 直接暴露给模型。
- 探索 MCP Server 形式暴露知识库、工单、数据库查询等 tools/resources，使不同 AI 客户端能够通过统一协议发现和调用外部能力。
- 在工具执行链路中加入用户授权、租户隔离、敏感字段脱敏、幂等 key 和 tool_call trace，提升工具调用安全性和可观测性。
```

## 6. Python / FastAPI 后端简历写法

```text
- 基于 FastAPI 构建大模型应用后端接口，支持普通问答、SSE 流式输出、RAG 检索和工具调用等能力。
- 使用 asyncio 和异步 HTTP 客户端并发调用模型、向量库、Rerank 服务和外部工具，提升 IO 密集场景吞吐。
- 设计模型调用超时、重试、限流、熔断和降级策略，避免上游模型波动影响整体服务稳定性。
- 对用户请求、模型调用、检索结果、工具参数、token 成本和异常进行结构化日志记录，支持 trace 排查和成本统计。
- 将文档解析、Embedding 入库、索引更新等重任务异步化，避免阻塞在线问答链路。
```

## 7. 指标写法

### 有真实指标时

```text
- 支持约 X 份文档、Y 万个 chunk 的知识库检索，平均问答延迟控制在 Z 秒以内。
- 基于标注评测集优化召回策略，使 Recall@5 从 A 提升到 B。
- 通过缓存和上下文压缩，将单次请求平均 token 成本降低约 X%。
- 接入 trace 和 badcase 复盘流程，覆盖检索、Rerank、生成和工具调用全链路。
```

### 没有真实线上指标时

不要硬编，可以写：

```text
- 构建离线评测集，对典型问题的召回结果、答案相关性和引用准确性进行人工评估。
- 完成端到端原型验证，覆盖文档入库、检索、Rerank、生成、引用校验和日志追踪链路。
- 沉淀 badcase 复盘表，对召回错误、上下文噪声、无依据生成和格式错误进行分类分析。
```

## 8. 简历项目反问预警

写了这些，就要准备好被问：

| 简历写法 | 面试官可能追问 |
|---|---|
| 混合召回 | 权重怎么调？BM25 和向量结果如何融合？ |
| Rerank | 用什么模型？放在 top_k 多少之后？延迟多少？ |
| 引用校验 | 怎么判断引用是真的？模型编引用怎么办？ |
| 权限过滤 | 元数据如何设计？过滤在召回前还是召回后？ |
| LangGraph | State 字段有哪些？checkpoint 怎么用？ |
| 工具调用 | 参数错了怎么办？非幂等工具怎么处理？ |
| SSE | 断连、超时、异常怎么处理？ |
| badcase | badcase 怎么分类？如何证明优化有效？ |

## 9. 简历项目完整示例

```text
企业知识库问答与业务 Agent 系统

- 负责 RAG 检索生成链路建设，完成文档解析清洗、结构化切分、Embedding 入库、向量检索、BM25 混合召回、Rerank 和引用式答案生成。
- 设计 chunk 元数据体系，保留 doc_id、page、section、tenant_id、permission、version 等字段，支持权限过滤、文档热更新和答案引用溯源。
- 基于 LangChain Runnable 组合 Prompt、Retriever、Model 和 OutputParser，并通过 SSE 实现模型回答流式返回，降低用户体感延迟。
- 将订单查询、工单创建等内部 API 封装为 Tool，统一进行参数 schema 校验、用户鉴权、超时控制、幂等处理和 tool_call trace 记录。
- 对高风险写操作加入用户确认节点，避免模型误调用导致越权或重复操作；对工具失败和输出格式错误设计重试、降级和转人工策略。
- 建立 badcase 复盘流程，按召回错误、排序错误、上下文噪声、无依据生成和工具错误分类，持续优化 chunk、召回、Rerank 和 Prompt 策略。
```

## 10. 简历自检清单

写完后逐项检查：

- 是否写清业务场景，而不是只写技术名词。
- 是否写清自己负责的模块。
- 是否体现 RAG 离线和在线链路。
- 是否体现 Agent 工具调用安全。
- 是否提到评估、日志、trace 或 badcase。
- 是否有可验证产出。
- 是否没有硬编不存在的指标。
- 每个 bullet 是否都能承受 3 层追问。
