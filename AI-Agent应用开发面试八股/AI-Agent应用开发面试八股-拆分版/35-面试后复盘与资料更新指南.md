# 面试后复盘与资料更新指南

> 用法：每次真实面试或模拟面后，用这份把经验沉淀回整套资料。  
> 目标：让资料不是一次性背诵材料，而是越面越准的个人面试系统。

## 1. 面试后 15 分钟内要做什么

刚面完记忆最完整，先不要急着刷别的资料，按这个顺序记录：

```text
1. 公司、岗位、轮次、面试时长。
2. 自我介绍是否被打断。
3. 项目被追问了哪些点。
4. 八股题有哪些。
5. 系统设计题是什么。
6. 代码题是什么。
7. 哪些题答得卡。
8. 面试官明显关注什么。
9. 哪些题以前资料里没有。
10. 下次最该补什么。
```

建议直接复制到 `21-面经证据库与错题本模板.md` 的“真实面试复盘模板”里。

## 2. 面试题进入资料库的流程

每个新题按这个流程处理：

```text
真实题目
  -> 记录到面经证据库
  -> 判断模块归属
  -> 判断可信度和频率
  -> 是否进入题库
  -> 是否需要补标准回答
  -> 是否影响最终冲刺清单
```

## 3. 题目提权规则

不是所有新题都要放进 P0。按下面规则提权：

### 提到 P0

满足任一条件：

- 同一题在 3 家以上公司出现。
- 目标公司连续出现。
- JD 明确写相关能力。
- 面试官围绕它连续追问 3 层以上。
- 你的项目简历里写了这个点。

例子：

```text
RAG 召回不准怎么办
工具调用如何防越权
LangGraph checkpoint 有什么用
SSE 流式输出怎么做
```

### 提到 P1

满足任一条件：

- 专项岗位高频，但不是所有岗位都会问。
- 二面深挖常见。
- 能体现工程判断。
- 是 P0 题的自然追问。

例子：

```text
HyDE 是什么
LLM-as-judge 有什么问题
MCP 和 OpenAPI 的关系
Prompt 如何 A/B
```

### 留在 P2

满足任一条件：

- 主要用于加分。
- 三面/主管面才常问。
- 只在少量公司出现。
- 更偏平台 owner 或架构视角。

例子：

```text
设计 Agent 评测平台
设计成本看板
英文解释 MCP
```

## 4. 错题流转规则

错题不要只写“不会”，要流转到具体文件。

```text
错题
  -> 写入 `21`
  -> 找到对应答案文件
  -> 如果答案文件没有，新增到对应专题
  -> 如果是 P0/P1，补标准回答
  -> 如果影响临面，加入 `34`
```

### 示例 1：RAG 权限过滤答崩

处理：

- 写入 `21` 错题本。
- 回看 `28` 第 34 题。
- 回看 `30` 第 114/119 题。
- 如果目标公司是云厂商，再回看 `32` 跨租户隔离。
- 在 `34` 公司冲刺里标记“权限过滤必须复习”。

### 示例 2：SSE 被问细节答崩

处理：

- 写入 `21` 错题本。
- 回看 `29` 第 87/88 题。
- 回看 `23` 和 `33` 的 SSE 代码。
- 如果是阿里/字节，加到公司定向冲刺。

### 示例 3：项目没上线被追问答虚

处理：

- 回看 `18` 的“项目有什么指标”。
- 回看 `24` 的“如果项目没有真实上线，怎么说”。
- 把自己的真实验证方式写成固定话术。
- 更新简历，避免写出无法支撑的指标。

## 6. 一次真实面试的复盘示例

```text
公司：字节
岗位：大模型应用开发
轮次：技术二面
时长：50 分钟

项目追问：
1. RAG 召回不准怎么定位？
2. 有没有评测集？
3. QPS 提升 10 倍怎么办？
4. token 成本怎么降？

八股：
1. LangGraph 和 AgentExecutor 区别。
2. SSE 怎么实现。
3. asyncio 适合什么场景。

代码：
1. 写一个 TopK。

答得不好的点：
1. Recall@K 和 MRR 解释不够顺。
2. QPS 10 倍只说了缓存，没说模型网关和降级。

更新动作：
1. 错题写入 `21`。
2. 回看 `28` 第 37/38 题。
3. 回看 `22` 字节专项。
4. 回看 `32` 模型网关和成本看板。
5. 把 QPS 题加入 `34` 字节冲刺重点。
```

## 7. 每周维护节奏

如果你持续投递，建议每周做一次资料维护：

```text
周一：收集 3-5 条新面经/JD，更新 `26`。
周二：把新题归类到 P0/P1/P2。
周三：补 3 道标准回答。
周四：做一套 `16` 模拟面试。
周五：更新错题本和 `34` 冲刺清单。
周末：重讲项目 5 分钟版。
```

## 8. 什么时候应该改简历

出现这些情况要改简历：

- 面试官连续追问某个 bullet，但你讲不出细节。
- 简历写了“上线/优化/提升”，但没有指标或验证方式。
- 写了 LangChain/LangGraph，但讲不清具体用在哪。
- 写了微调，但其实只是 Prompt 或 RAG。
- 写了 Agent，但只是固定 Chain。
- 写了向量数据库，但只用过本地 FAISS demo。

修改原则：

```text
宁可少写，也要每个 bullet 能抗 3 层追问。
```

## 9. 什么时候应该更新最终冲刺清单

更新 `34` 的条件：

- 目标公司连续问某个题。
- 自己连续两次模拟面答崩某个题。
- JD 明确要求但清单没有覆盖。
- 新增了更强的标准回答文件。
- 面试前发现清单太长，需要删减。

`34` 的原则：

```text
只放最影响面试结果的行动项，不放百科知识。
```

## 10. 复盘后的最终输出

每次复盘结束，应该产出 3 个东西：

```text
1. 新增或更新的面经证据。
2. 新增或修正的错题答案。
3. 下一场面试前优先看的 1-5 个文件。
```
