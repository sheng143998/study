# 79-资料库总验收与维护看板

> 目标：让这套资料后续继续迭代时不失控。  
> 核心原则：新增内容必须进入使用路径；不能只新增文件，不接索引、不接练习、不接验收。

使用边界：本文件给维护者和资料迭代时使用；临面用户不用执行这里的检查，直接走 `48 -> 80 -> 74 -> 78` 或对应时间路线。

## 0. 本次修改先问 4 个问题

| 问题 | 如果答案是否定 |
|---|---|
| 用户能从 `README`、`00` 或 `36` 找到它吗？ | 先补入口，不要继续扩内容 |
| 它能帮助用户产出一个可上场成品吗？ | 改成模板、题单、检查表或口述稿 |
| 它会不会和已有文件重复？ | 合并到已有文件，或只改索引 |
| 临面时是否会增加认知负担？ | 接入 `74` 做取舍，或接入 `78` 做压缩 |

最小验收标准：

```text
能找到 -> 知道何时用 -> 用完有产出 -> 修改后有复盘入口
```

适用场景：

- 新增了一个专题文件。
- 修改了上场包成品数量。
- 新增了公司、岗位、轮次或专项题型。
- 做了一轮大规模扩充后，需要检查资料是否变臃肿。
- 面试后想把真实问题沉淀回资料库。

配合文件：

- `00-阅读索引.md`：主入口。
- `36-总目录导航图与学习地图.md`：关系图。
- `47-资料库维护规范与去臃肿指南.md`：维护原则。
- `63-高频问题到文件定位索引.md`：问题倒排。
- `66-面试上场包与成品验收清单.md`：成品验收。
- `74-减负版复习路线与抽题清单.md`：减负路线。
- `77-模拟面闭环数据看板与弱点修复手册.md`：训练闭环。
- `78-临面当天作战面板.md`：最后入口。

## 1. 新增文件验收

本节只适用于新增或重构资料；普通复习不需要执行。

每新增一个文件，必须回答：

| 问题 | 必须有答案 |
|---|---|
| 这个文件解决什么具体场景？ | 不能只是“补充更多题” |
| 它属于哪一层？ | 基础 / 答案 / 项目 / 练习 / 公司 / 复盘 / 临面 |
| 谁会在什么时候打开它？ | 投递前 / 一面前 / 二面前 / 模拟后 / 临面前 |
| 它和已有文件有什么区别？ | 防止重复 |
| 它接入哪些入口？ | 至少接入 `00` 和一个使用路径 |
| 它是否增加上场成品？ | 如果增加，必须同步 `66` |
| 它是否需要进入减负路线？ | 如果临面会用，必须同步 `74` 或 `78` |

最低接入要求：

```text
新增文件 -> `00` 主索引
        -> `36` 学习地图或对应路径
        -> 至少一个业务入口：`66` / `69` / `74` / `75` / `77` / `78`
```

## 5. 去臃肿规则

出现下面情况，不要新增文件，优先合并或改索引：

| 现象 | 处理 |
|---|---|
| 只是多了 10 道同类题 | 放进现有题库或押题增量 |
| 只是某公司多了 3 个问题 | 放进 `46`、`68` 或 `75` |
| 只是某项目多了一个讲法 | 放进 `76` |
| 只是某系统设计多了一个约束 | 放进 `67` |
| 只是某个概念口径更新 | 放进对应专题和 `56` |
| 只是模拟后发现一个弱点 | 放进 `77`，不要新建 |
| 只是临面一句救场 | 放进 `62` 或 `78` |

可以新增文件的情况：

- 新场景需要独立使用路径。
- 新内容横跨多个旧文件，且已有文件难以承载。
- 面试准备流程里出现了新的关键节点。
- 新文件能显著降低查找成本或训练成本。

## 6. 上场包一致性验收

如果修改 `66` 的成品数量，必须同步检查：

| 检查位置 | 要看什么 |
|---|---|
| `66` 顶部 | “至少准备 N 个成品” |
| `66` 总览表 | 是否真的有 N 行成品 |
| `66` 3 天及以上完整包验收表 | 是否有对应验收行 |
| `74` 分层上场包 | 是否需要同步增加 |
| `78` 临面面板 | 最后 30 分钟是否仍可执行 |

原则：

```text
当前基准：2小时 = 2小时极速包 8项；半天 = 标准上场包 13 项最低线；1 天 = 标准上场包 13 项标准线；3 天及以上 = 完整上场包 19 项。完整包通过标准为至少 13 个 A、最多 6 个 B、不能有 C。
上场包成品越多，越要保证 `74` 和 `78` 能压缩。
`66` 负责分层成品验收，完整验收只对应 3 天及以上；`74` 负责减负，`78` 负责最后启动。
```

## 7. 模拟闭环一致性验收

练习相关文件要形成闭环：

```text
`80` 生成 JD 实战转化工单
  -> `69` 生成题单
  -> `52` 追问
  -> `41` 打分
  -> `57` 录音复盘
  -> `77` 登记弱点卡
  -> `69` 生成复测题
  -> `41` 复测评分
  -> `77` 关闭 / 未关闭
  -> 1 天及以上进入 `66` 验收上场包；半天只做 `80` 摘要自检
  -> `78` 临面启动
```

实战闭环红线：

```text
收到明确 JD / 面试通知后，必须能进入 `80` 生成工单。
新增练习材料如果不能接入 `80 -> 69 -> 52 -> 41 -> 57 -> 77 -> 69复测 -> 41复测 -> 77关闭 -> 66(1天及以上) -> 78`，不要新增。
```

如果新增练习材料，要问：

- 它是生成题单，还是追问？
- 它是评分，还是复盘？
- 它是否生成弱点卡、复测题、复测评分或关闭状态？
- 它是修复弱点，还是临面启动？
- 它是否能进入上面闭环的一环？

不能进入闭环的练习材料，容易变成“看了但没用”。

## 10. 每周维护节奏

如果持续维护资料库，每周做一次；普通备考者不需要执行本节：

| 动作 | 文件 |
|---|---|
| 更新真实 JD / 面经 | `26`、`38`、`46`、`68` |

| 更新公司路径 | `55`、`75`、`65` |
| 清理重复和旧计数 | `47`、`79` |

每周只做 3 个产出：

1. 新增或修正 3 个高可信面经/JD 信号。
2. 修正 3 个 B/C 弱点。
3. 删除或合并 1 个重复表达。

## 11. 维护者口径速记

1. 新增文件建议接入使用路径，否则容易变成资料负担。
2. 主索引、学习地图、上场包、减负路线、模拟闭环是维护者优先检查的入口。
3. 能合并就合并，只有新场景、新流程、新闭环才新增文件。
4. `66` 负责分层验收，`74` 负责取舍，`78` 负责最后启动。
5. 资料库越大，越要用维护看板保证它仍然服务面试，而不是服务收集癖。
