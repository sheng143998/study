# 74-减负版复习路线与抽题清单

> 目标：当资料已经很多时，帮你决定“今天到底看什么、不看什么、练什么”。  
> 核心原则：面试前不是把所有文件读完，而是把高概率问题变成能说出口、能追问、能举项目证据的答案。

适用场景：

- 面试还剩 2 小时 / 半天 / 1 天 / 3 天，不知道从哪里开始。
- 已经看过很多资料，但口述仍然散。
- JD 很长，关键词很多，担心越复习越焦虑。
- 想做模拟面，但不知道抽哪些题。

配合文件：

- `00-阅读索引.md`：全量文件入口。
- `36-总目录导航图与学习地图.md`：理解资料关系。
- `48-面试通知速查导航卡.md`：收到通知后的路线选择。
- `55-公司轮次面试路径卡.md`：按公司和轮次调权。
- `80-JD实战转化闭环工单.md`：已经确定 JD 后，把复习变成交付物。
- `69-JD到模拟面题单生成器.md`：生成完整模拟题单。
- `75-公司风格模拟面评分矩阵.md`：按目标公司做专项追问和评分。
- `76-项目表达迁移与面试官视角改写手册.md`：把项目改写成目标岗位、公司和轮次版本。
- `77-模拟面闭环数据看板与弱点修复手册.md`：多轮模拟后判断弱点趋势和下一轮训练。
- `78-临面当天作战面板.md`：面试当天最后 30 分钟只看这一份。
- `66-面试上场包与成品验收清单.md`：分层验收口径。

## 1. 先判断你现在缺什么

复习前先做 5 分钟自检：

| 自检问题 | 如果答案是否定 | 先看 |
|---|---|---|
| 我能 60 秒说清自己方向和项目吗？ | 开场会散 | `18`、`59` |
| 我能 2 分钟讲一个项目闭环吗？ | 项目不稳 | `24`、`42`、`70` |
| 我能答 RAG/Agent/Tool 的 P0 问题吗？ | 一面风险高 | `28`、`29` |
| 我能画一个 AI 应用系统设计吗？ | 二面风险高 | `14`、`32`、`51` |
| 我能讲安全、权限、评测、成本吗？ | 大厂深挖风险高 | `54`、`60`、`67`、`71` |
| 我能解释模型基础和 embedding 吗？ | 算法应用岗风险高 | `72` |
| 我能设计 Data Agent / NL2SQL 吗？ | 数据分析 Agent 风险高 | `73` |
| 我能边写代码边讲边界吗？ | 代码面风险高 | `23`、`44`、`45` |

速判：

```text
一面优先：自我介绍 + P0 + 后端/代码 + 项目真实性
二面优先：项目深挖 + 系统设计 + bad case + 技术取舍
三面/主管面优先：业务价值 + owner + 风险边界 + 复盘
平台/ToB 优先：权限 + 多租户 + 评测 + 观测 + 安全合规
```

## 2. 2 小时极限路线

只做能立刻上场的内容：

如果你是从 `48 -> 80` 进入本节，下面表格不是逐个打开文件；除 `78` 外，只能按最高风险选 1 个补弱文件，其余产物直接写回 `80`。

| 时间 | 动作 | 文件 |
|---|---|---|
| 0-10 分钟 | 填 `80` 极速工单：公司/岗位/轮次/JD top3/最高风险 | `80` |
| 10-35 分钟 | 写 1 分钟自我介绍和 2 分钟项目入口 | `18`、`59` |
| 35-55 分钟 | 挑 3-5 个和 JD top3 相关的 P0，说出主干即可；代码面替换为代码模板 | `28`、`29` / `44`、`45` |
| 55-80 分钟 | 准备 1 个真实 bad case | `42`、`54` |
| 80-100 分钟 | 只按 JD 或轮次替换 1 个专题 | `14`/`51` 或 `60`/`67`/`71` 或 `73` |
| 100-115 分钟 | 准备 2 个反问和 2 句救场 | `65`、`62` |
| 115-120 分钟 | 看 `78` 启动，不再翻新资料 | `78` |

2 小时产物只验收 8 项，和 `66/80` 保持一致：

```text
1. 公司 / 岗位 / 轮次
2. JD top3
3. 1 分钟开场第一句
4. 2 分钟项目第一句
5. 最高风险题 30 秒版
6. 1 个真实 bad case
7. 2 个反问
8. 2 句救场
```

如果这 8 项没填完，不允许打开新专题；如果填完了，也只允许口述和纠错，不继续扩展资料。

替换规则：

```text
系统设计轮：把 P0 或 bad case 的一半时间换成 `14` / `51`。
平台/ToB/安全 JD：把专题替换成 `60` / `67` / `71`。
Data Agent / NL2SQL JD：把专题替换成 `73`。
代码面：把 P0 替换成 `44` / `45`。
```

此时不要看：

- 大段源码实现细节。
- 低频算法题。
- 你简历里完全没写过的项目蓝图。
- 和 JD 无关的模型训练细节。

## 3. 半天路线

半天目标：从“能答概念”变成“能撑住追问”。

先完成 `80` 的 10分钟最小上场包和半天标准工单。下面表格只用于“80 已填完后”的补弱选择，每次最多选 1-2 个模块，不按表横向打开所有文件。

| 模块 | 产物 | 补弱规则 |
|---|---|---|
| 开场 / 项目 | 1 分钟自我介绍 + 2 分钟项目入口 | 如果 `80` 写不出来，只补 `18` 或 `59` 之一 |
| P0 / 代码 | 10 个 30 秒答案或 1 道代码模板 | 一面选 `28/29`，代码面选 `44/45`，只选一组 |
| 系统设计 / 工程治理 | 1 张架构图 + 1 个指标证据 | 二面选 `51/67` 或 `54/60`，只选一组 |
| 安全 / Data Agent | 1 个最高风险安全回答 | ToB 选 `71`，Data Agent 选 `73` |
| 公司校准 / 模拟 | 1 次口述自评 + 1 条公司口径 | 优先用 `80` 迷你题单或本文件抽题口述；不打开完整 `69/41`，除非主动升级为 1 天闭环 |

半天不要追求“看完所有文件”，只追求每个模块都有可说出口的答案。

半天路线收束：补弱后只做 1 次口述模拟，把 Top2 弱点写回 `80`，最后直接去 `78`。

## 6. 抽题清单

每次模拟面从下面抽题，不要按文件顺序背。

### 6.1 开场和项目

1. 60 秒自我介绍。
2. 2 分钟介绍你最相关的项目。
3. 你在项目里具体负责哪一块？
4. 这个项目为什么需要 AI Agent / RAG，而不是普通搜索或规则系统？
5. 你怎么证明这个项目有效？
6. 讲一个真实 bad case。
7. 如果让你重做一遍，你会怎么改？

### 6.2 RAG

1. RAG 完整链路是什么？
2. chunk 怎么切？overlap 怎么选？
3. embedding、BM25、rerank 分别解决什么问题？
4. 召回不准怎么定位？
5. 答案引用不可信怎么处理？
6. 多租户权限过滤放在哪里？
7. RAG vs 微调怎么选？

### 6.3 Agent / LangGraph

1. Agent 和 workflow 的区别是什么？
2. LangGraph 适合解决什么问题？
3. state 里应该放什么，不应该放什么？
4. 工具调用失败怎么恢复？
5. 多步调用如何避免无限循环？
6. 人工接管节点怎么设计？
7. Agent 成功率怎么评估？

### 6.4 Prompt / Tool / MCP

1. Prompt engineering 在生产里怎么管理版本？
2. Tool Calling 的 schema 怎么设计？
3. 工具误调用怎么办？
4. OpenAPI、RPC、MCP 的关系是什么？
5. MCP Host、Client、Server 各自负责什么？
6. MCP 安全边界在哪里？
7. 高风险工具如何确认、审计、回滚？

### 6.5 Data Agent / NL2SQL

1. 设计一个自然语言查数系统。
2. NL2SQL 为什么难？
3. schema linking 怎么做？
4. 指标口径冲突怎么办？
5. SQL 怎么做只读校验和 AST 校验？
6. 如何防止越权查库和敏感字段泄露？
7. 结果图表怎么保证可信？

### 6.6 系统设计

1. 设计企业知识库问答系统。
2. 设计客服 Agent。
3. 设计工具接入平台。
4. 设计模型网关。
5. 设计评测和 bad case 回流平台。
6. 如果 QPS 提升 10 倍怎么办？
7. 如果要求私有化部署怎么办？

### 6.7 代码和后端

1. 写一个 TTL cache。
2. 写一个流式输出接口。
3. 写一个 rate limiter。
4. 写一个 SQL 只读校验。
5. 写一个 ensure limit。
6. 写一个 retry with backoff。
7. 如何给这些代码加日志、超时、异常和并发保护？

## 8. 停看规则

出现下面情况，要停止继续读资料，转为口述或模拟：

1. 同一个概念看了 3 份文件，但还不能 30 秒解释。
2. 已经看完系统设计，但画不出架构图。
3. 已经背了 P0，但回答没有项目例子。
4. 看了很多公司 JD，但没有生成自己的题单。
5. 资料越看越焦虑，开始追求“全部看完”。
6. 已经知道目标公司，但还在按通用题单练，没有做公司专项评分。
7. 已经知道目标岗位，但项目口播还是通用版本，没有用 `76` 改写。
8. 已经做过两轮模拟，但没有用 `77` 判断弱点趋势。

正确动作：

```text
停看 -> 口述 -> 录音 -> 打分 -> 找一个最弱点补文件 -> 再口述
```

### 8.1 新趋势插入规则：只替换，不加量

看到新的 JD 热词时，不要在原计划外继续加文件。只允许“替换”当前低相关内容。

| 新趋势信号 | 替换掉 | 插入 |
|---|---|---|
| Data Agent / NL2SQL / ChatBI | 泛泛多 Agent 文章 | `73` + `23` 的 SQL 安全 |
| MCP / A2A / 工具生态 | 低频框架横向比较 | `08` + `71` 的协议边界和安全 |
| Agent 成功率 / trace / replay | 继续刷新题 | `54` + `77` 的指标和总账本 |
| 浏览器 / 终端 / 代码执行 Agent | 普通 Tool Calling 复习 | `71` 的高风险工具安全 |
| LLMOps / 模型网关 / 成本 | 微调算法细节 | `32` + `60` 的平台治理和取舍 |
| RAG faithfulness / golden set | 向量库品牌比较 | `54` 的评测和 bad case 回归 |

硬规则：

```text
新趋势只改变题单权重，不增加总复习时长。
如果插入 1 个新模块，必须删掉 1 个低相关模块。
如果 JD 没写在职责或必备项，只放 P2，不挤占 P0。
```

## 9. 分层上场包

不同剩余时间用不同上场包，不要把 1 天标准压到 2 小时里。

| 剩余时间 | 上场包口径 | 来源 |
|---|---|---|
| 2小时 | 2小时极速包：8项 | `80` 的 2小时极速包、`66` 的 8项极速包验收口径 |
| 半天 | 标准上场包：13 项最低线 | `66` 的半天验收口径 |
| 1 天 | 标准上场包：13 项标准线 | `66` 的 1 天验收口径 |
| 3 天及以上 | 可扩展到 19 项完整池 | 先稳 13 项，再按 JD 加项 |

半天 / 1 天的 13 项字段以 `66` 为唯一标准，本文件不另起一套数量口径；区别只在完成度，不在字段数量。

执行时只做三件事：

1. 按 `66` 的 13 项口径压进 `80` 的本次 JD 上场包；半天可只用本节摘要，有余力再打开 `66`。
2. 在本文件前面的时间盒里，只按轮次补 1-2 个最弱专题。
3. 最后 30 分钟只看 `80` 和 `78`，不再扩展新资料。

如果 JD 是 Data Agent / NL2SQL，再额外保证：

1. NL2SQL 主链路。
2. schema linking。
3. 指标口径。
4. SQL 安全。
5. 权限和脱敏。

## 10. 最终速背

1. 资料很多时，先按轮次、JD、简历和风险项选择文件。
2. 一面保 P0、代码和项目真实性；二面保系统设计、bad case 和取舍；主管面保业务价值和复盘。
3. 每次复习都要产出一个可上场成品，而不是只留下“我看过”。
4. Data Agent / NL2SQL 要单独准备，因为它会同时考 Agent、数据库、安全、指标和可视化。
5. 面试前最后一小时，只做口述、抽题、公司专项评分、闭环看板、救场和反问；最后 30 分钟只看 `80` 的本次 JD 上场包和 `78`，不再扩展新资料。
