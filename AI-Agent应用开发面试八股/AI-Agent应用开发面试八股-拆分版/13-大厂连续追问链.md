# 大厂连续追问链

> 用法：把每一组当成一次 10 到 20 分钟模拟面试。不要只背单点答案，要练“被连续追问时还能把链路讲完整”。

## 1. RAG 知识库追问链

### Q1：什么是 RAG

短答：

RAG 是检索增强生成。它先从外部知识库检索相关内容，再让模型基于这些内容生成答案，适合私有知识、频繁更新知识和需要引用溯源的场景。

### Q2：RAG 的完整链路是什么

追问要点：

- 离线：文档采集、解析、清洗、切分、embedding、建索引、存元数据。
- 在线：query rewrite、召回、过滤、rerank、上下文拼接、生成、引用校验。

更好的答法：

我会分离线和在线讲。离线保证数据质量和索引质量，在线保证召回、排序和生成质量。线上效果差时，也按这两条链路排查。

### Q3：chunk 怎么切

追问要点：

- 固定 token 切分。
- 递归切分。
- 按标题/段落/语义切分。
- parent-child chunk。
- overlap。

高分回答：

chunk 不只是参数问题，要结合文档结构和问题类型。制度文档适合按标题层级切，FAQ 适合按问答对切，代码文档要保护代码块和函数边界。小 chunk 召回准但上下文不足，大 chunk 信息完整但噪声和成本高。

### Q4：召回不准怎么办

追问要点：

- 数据解析是否丢内容。
- chunk 是否破坏语义。
- query 是否需要改写。
- embedding 模型是否适合中文/领域。
- top_k 是否合理。
- 是否需要 BM25 + vector。
- 是否需要 rerank。
- metadata filter 是否有问题。

面试表达：

我不会一上来只调 top_k，而是先用 badcase 建评测集，记录 query、期望文档、实际召回、rerank 分数和最终答案，再逐项优化。

### Q5：为什么要混合检索

短答：

向量检索擅长语义相似，BM25 擅长关键词、编号、错误码、专有名词。企业知识库里两类问题都很多，所以混合检索更稳。

### Q6：rerank 为什么有效

短答：

向量召回是粗召回，只比较 query 向量和 doc 向量，排序不一定精准。reranker 通常同时看 query 和 doc 文本，相关性判断更细，因此能把真正相关的文档排到前面。

### Q7：权限过滤放召回前还是召回后

高分回答：

理想情况下要在检索阶段就做 metadata filter，避免无权限文档进入候选集。但具体取决于向量库能力和过滤选择性。如果先召回再过滤，可能 top_k 被无权限文档占满导致漏召；如果先过滤再召回，过滤条件太复杂可能影响性能。生产中一般会把 tenant_id、department、acl 等权限元数据写入索引，并做租户级隔离。

### Q8：RAG 怎么评估

指标：

- 检索：Recall@K、Precision@K、MRR、NDCG。
- 生成：faithfulness、answer relevance、citation accuracy。
- 工程：延迟、成本、失败率、缓存命中率。

高分回答：

我会把评估分成检索和生成两层。否则只看最终答案，很难定位到底是没召回、排错了，还是模型生成时没用证据。

### Q9：RAG 还会幻觉怎么办

治理：

- 提升召回。
- rerank。
- Prompt 要求基于证据回答。
- 无证据拒答。
- 引用校验。
- groundedness 检测。
- 高风险人工审核。

面试收束：

RAG 只能降低幻觉，不是消灭幻觉。生产里要用检索质量、生成约束、后处理校验和人工兜底共同治理。

## 2. Agent 生产治理追问链

### Q1：Agent 和 Chatbot 有什么区别

短答：

Chatbot 主要是对话生成；Agent 能围绕目标进行多步规划、工具调用、状态更新和结果反馈。

### Q2：Agent 的核心组成是什么

要点：

- LLM。
- Tools。
- State/Memory。
- Planner。
- Executor。
- Observer。
- Guardrails。

### Q3：Agent 为什么容易不稳定

原因：

- 模型输出随机性。
- 工具描述不清。
- 多步误差累积。
- 上下文漂移。
- 工具失败。
- 终止条件不明确。
- 权限没有硬约束。

### Q4：怎么防止 Agent 死循环

回答：

- 最大步数。
- token budget。
- 超时。
- 状态中的 step_count/error_count。
- 条件边终止。
- fallback。
- human review。
- 工具调用去重。

LangGraph 项目版：

我会把循环写成显式图结构，让每个循环节点都更新 step_count，并通过 conditional edge 判断继续、结束或进入错误处理。

### Q5：怎么防止工具乱调

回答：

- 工具名和描述清晰。
- 参数 schema 结构化。
- 工具白名单。
- 用户权限校验。
- 危险操作人工确认。
- 执行前做参数验证。
- 执行后记录 trace。

重点：

Prompt 只能辅助工具选择，真正的安全必须在应用层和工具层实现。

### Q6：工具调用失败怎么办

处理层次：

- 参数错误：返回校验错误，让模型修正。
- 网络超时：重试、熔断、降级。
- 业务错误：把错误码转成可理解 observation。
- 连续失败：停止任务或转人工。
- 写操作失败：保证幂等和回滚。

### Q7：Agent 如何评估

指标：

- 任务成功率。
- 平均步骤数。
- 工具调用准确率。
- 失败恢复率。
- 人工介入率。
- 成本和延迟。
- 用户满意度。

高分回答：

Agent 评估不能只看最终回答，还要看过程质量，比如是否调用了正确工具、是否少走弯路、是否遵守权限和终止条件。

## 3. LangChain / LangGraph 追问链

### Q1：你用过 LangChain 吗

答法：

我把 LangChain 当成 LLM 应用组件库使用，主要用过 model、prompt、retriever、vectorstore、tool、output parser、callback 和 Runnable/LCEL。

### Q2：LCEL 是什么

答法：

LCEL 是 LangChain 的组合表达方式，可以把 prompt、model、parser、retriever 等 Runnable 用管道组合，支持 async、stream、batch 和并行组合。

### Q3：Chain 和 Agent 区别

答法：

Chain 是固定流程，Agent 是动态决策。Chain 可控性强，Agent 灵活但不稳定。生产里我会优先固定流程，只有确实需要动态工具选择和多步规划时才用 Agent。

### Q4：什么时候用 LangGraph

答法：

当流程需要状态、分支、循环、人工确认、恢复和回放时用 LangGraph。它比普通 AgentExecutor 更适合复杂生产 Agent。

### Q5：LangGraph 的 State 怎么设计

答法：

State 里放流程控制必需的信息，比如 messages、task_id、retrieved_docs、tool_results、step_count、approval_status、final_answer。大对象尽量存外部，只在 state 里存引用。

### Q6：checkpoint 有什么用

答法：

checkpoint 用来保存执行状态，支持长任务恢复、人工审批后继续、故障恢复、调试回放和多轮会话持久化。

## 4. Prompt 与工具调用追问链

### Q1：Prompt Engineering 是什么

答法：

Prompt Engineering 是通过设计模型输入来控制行为，包括角色、任务、上下文、示例、约束和输出格式。

### Q2：如何让模型稳定输出 JSON

答法：

优先用模型原生 structured output 或 tool/function calling；其次用 JSON schema、few-shot、低 temperature、输出解析、校验和重试。关键链路不能只靠自然语言要求。

### Q3：Prompt injection 怎么防

答法：

不能只靠 Prompt 防。要区分系统指令和外部内容，不把检索文档当指令执行；工具层做权限和白名单；高风险操作人工确认；日志审计和敏感信息脱敏。

### Q4：Tool schema 怎么设计

答法：

工具名语义明确，description 写清什么时候用和什么时候不用，参数类型结构化，枚举优于自由文本，required 字段明确，返回值稳定。危险操作需要额外确认参数。

### Q5：非幂等工具如何处理

答法：

非幂等操作，比如下单、退款、删除、发送邮件，要加用户确认、幂等 key、防重复提交、审计日志和失败补偿。模型最多提出调用意图，执行必须受系统控制。

## 5. 微调追问链

### Q1：微调解决什么问题

答法：

微调适合让模型学习稳定任务模式、输出格式、业务风格和领域话术，不适合记住频繁变化的事实知识。

### Q2：微调和 RAG 怎么选

答法：

缺知识优先 RAG，行为模式不稳定考虑 Prompt 或微调。知识更新频繁、需要引用，用 RAG；输出风格和格式长期稳定、有高质量样本，用微调。

### Q3：LoRA 为什么省资源

答法：

LoRA 冻结原模型权重，只在部分线性层旁边训练低秩适配矩阵，因此训练参数少、显存需求低、adapter 可切换。

### Q4：微调数据怎么准备

答法：

高质量比数量重要。样本要覆盖真实分布，格式一致，包含边界样本和困难样本，去重、脱敏，划分训练/验证/测试集，并保留 baseline。

### Q5：微调能解决幻觉吗

答法：

不能完全解决。微调可以改善任务行为，但事实正确性仍需要 RAG、工具查询、引用校验和评估。

## 6. MCP / OpenAPI / RPC 追问链

### Q1：MCP 是什么

答法：

MCP 是 Model Context Protocol，是 AI 应用连接外部工具、资源和 Prompt 的标准协议。

### Q2：MCP、OpenAPI、RPC 区别

答法：

OpenAPI 描述 HTTP API，RPC 是远程调用抽象，MCP 是面向 AI 应用的工具和上下文连接协议。MCP server 内部可以包装 OpenAPI、RPC、数据库或文件系统。

### Q3：MCP 有哪些核心对象

答法：

主要有 tools、resources、prompts，也涉及 sampling、roots、elicitation 等能力。tools 用于动作，resources 用于上下文数据，prompts 用于复用模板。

### Q4：MCP 安全怎么做

答法：

MCP 协议本身不是完整安全系统。要结合 Host、Client、Server 和底层工具做权限边界，包括 roots 限制、用户授权、工具白名单、参数校验、人工确认、审计和敏感信息保护。

### Q5：如何把内部 API 接成 Agent 工具

答法：

可以从 OpenAPI 解析接口，但不能无脑全暴露。要筛选接口、改写工具描述、简化参数 schema、接入鉴权、设置限流和审计，对写操作加确认，必要时包装成 MCP server。

## 7. Python 后端追问链

### Q1：GIL 是什么

答法：

GIL 是 CPython 的全局解释器锁，使同一进程中通常只有一个线程执行 Python 字节码。它限制 CPU 密集型多线程性能，但 IO 密集型仍可以通过线程或 asyncio 提高吞吐。

### Q2：LLM 应用适合 asyncio 吗

答法：

适合。LLM 应用大量调用模型 API、向量库、数据库和外部工具，是典型 IO 密集场景。asyncio 能在等待 IO 时切换任务，提高并发。

### Q3：CPU 密集任务怎么办

答法：

不要放在事件循环里。可以用进程池、任务队列、独立推理服务、GPU batch，或把重计算下沉到 C++/Rust/Go 服务。

### Q4：FastAPI 如何做流式输出

答法：

可以用 StreamingResponse 或 SSE，把模型 token/chunk 增量返回。要处理断连、超时、异常、日志、token 统计和客户端重连。

### Q5：线上怎么限流和降级

答法：

按用户、租户、模型和接口做限流；设置超时、重试、熔断；高峰期降级到小模型或缓存答案；对长任务进入队列；记录成本和延迟指标。
