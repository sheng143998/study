# 77-模拟面闭环数据看板与弱点修复手册

> 目标：把多次模拟面的结果沉淀成可执行的弱点修复计划。  
> 核心原则：一次模拟面只暴露问题，连续 3 次模拟面的趋势才决定你真正该补什么。

适用场景：

- 做了模拟面，但每次复盘都只写“不会”“答得散”。
- 不知道下一轮模拟面应该练项目、八股、系统设计还是代码。
- A/B/C 打了分，但没有转成补强文件和训练动作。
- 临近面试，想快速判断自己是否可以上场。

配合文件：

- `41-面试官评分Rubric与回答自检表.md`：单次评分。
- `52-面试官陪练脚本手册.md`：模拟面追问。
- `57-模拟面录音复盘与迭代训练手册.md`：录音复盘。
- `64-每日口述训练打卡表.md`：日常训练。
- `69-JD到模拟面题单生成器.md`：下一轮题单。
- `75-公司风格模拟面评分矩阵.md`：公司专项评分。
- `66-面试上场包与成品验收清单.md`：最终上场验收。
- `78-临面当天作战面板.md`：最后 30 分钟只看这一份。

## 1. 单次模拟面记录表

每次模拟面后，不要只写感受，按这个表记录：

| 字段 | 示例 |
|---|---|
| 日期 | 2026-06-08 |
| 目标公司 | 字节 / 阿里云 / 腾讯 |
| 目标岗位 | AI Agent 应用开发 |
| 轮次 | 一面 / 二面 / 主管面 |
| 模拟时长 | 30 / 45 / 60 分钟 |
| 使用题单 | `69` 生成 / `75` 公司专项 / 手动抽题 |
| 总评分 | raw_score 1-5 + grade，按 `41` 换算 |
| 最大短板 | 项目真实性 / RAG / Agent / 系统设计 / 代码 / 表达 |
| 下轮目标 | 把项目真实性从 B 提到 A |
| 修正文件 | `42`、`54`、`76` |

模板：

```markdown
# 模拟面记录

- 日期：
- 公司/岗位/轮次：
- 题单来源：
- 总体评分：
- 最大短板：
- 最高风险题：
- 需要补的文件：
- 下一轮模拟目标：
```

评分口径：

```text
统一使用 `41` 的 raw_score / grade / display：
5=A，4=A-，3=B，2=C，1=C-。
B+ 只表示 3 分项经过复测后连续两次满足通过标准，允许关闭；不是新的原始分数。
```

## 2. 模拟面总账本 / Interview Training Log

每轮模拟面必须登记一行。没有填总账本，不算完成一次模拟面。

| 日期 | 公司/轮次 | 题单来源 | 项目真实性 | 技术主干 | 工程闭环 | 系统设计 | 代码 | 表达 | 最大短板 | 下一轮只练什么 | 是否复测 |
|---|---|---|---|---|---|---|---|---|---|---|---|
|  |  | `69` / `75` / 手动 | A/B/C | A/B/C | A/B/C | A/B/C | A/B/C | A/B/C |  |  | 是/否 |

使用规则：

```text
同一短板连续 2 次 B/C：停止看新资料，只做专项复测。
同一维度从 C 到 B：下一轮继续练同主题，直到稳定到 A。
连续 3 次都没有复测：说明复盘没有闭环，要回到 `57` 重做训练单。
```

## 3. 七维数据看板

连续模拟面建议固定用 7 个维度：

| 维度 | A | B | C |
|---|---|---|---|
| 项目真实性 | 有职责、证据、bad case、边界 | 主干能讲，证据弱 | 像背模板或像编的 |
| 技术主干 | 概念、链路、取舍清楚 | 会概念，缺落地 | 关键词堆砌 |
| 工程治理 | 权限、评测、监控、成本、兜底成体系 | 能说几个点 | 只会 Demo |
| 系统设计 | 能澄清、画图、讲演进和约束 | 有图但缺治理 | 链路散 |
| 代码后端 | 能写主干、讲边界和生产增强 | 能写功能 | 卡语法或无边界 |
| 公司匹配 | 项目能贴合公司风格 | 有公司关键词 | 通用回答 |
| 临场表达 | 先结论、能收束、能澄清 | 偶尔跑散 | 长、绕、虚 |

每次模拟面填一行：

| 日期 | 公司/轮次 | 项目 | 技术 | 治理 | 系设 | 代码 | 公司 | 表达 | 下轮目标 |
|---|---|---|---|---|---|---|---|---|---|
|  |  | A/B/C | A/B/C | A/B/C | A/B/C | A/B/C | A/B/C | A/B/C |  |

## 4. 趋势判断规则

单次 C 不可怕，连续趋势才关键。

| 现象 | 判断 | 处理 |
|---|---|---|
| 同一维度连续 2 次 B | 还没稳定 | 下一轮必须专项训练 |
| 同一维度连续 2 次 C | 高风险 | 暂停全套模拟，先补文件 |
| 总分上升但项目仍 B | 表面进步 | 优先补项目证据 |
| 一面模拟 A，二面模拟 C | 深挖能力不足 | 补系统设计和 bad case |
| 公司匹配连续 B/C | 回答太通用 | 用 `75` 和 `76` 改写 |
| 表达连续 B/C | 不是知识问题 | 用 `62`、`64` 做短答训练 |

红线：

```text
临面前如果项目真实性、系统设计、公司匹配任一项是 C，不建议继续扩展新资料。
先把 C 补到 B，再考虑看新文件。
```

## 5. 弱点到修复文件映射

| 弱点 | 典型表现 | 先补 | 再练 |
|---|---|---|---|
| 项目真实性弱 | 说不清自己做了什么 | `58`、`70`、`76` | `42` 三层追问 |
| 项目证据弱 | 没有日志、字段、评测、bad case | `50`、`54`、`70` | 2 分钟项目口播 |
| RAG 弱 | 只会向量库检索 | `04`、`30`、`72` | RAG 5 连问 |
| Agent 弱 | Agent vs workflow 讲不清 | `02`、`03`、`29` | 工具失败追问 |
| Tool/MCP 弱 | 协议和安全边界混乱 | `05`、`08`、`71` | 工具接入系统设计 |
| Data Agent 弱 | NL2SQL、指标、SQL 安全没闭环 | `73`、`23`、`71` | Data Agent 设计题 |
| 系统设计弱 | 画不出主链路 | `14`、`32`、`51` | 8 分钟白板复述 |
| 约束应对弱 | 一加多租户/低延迟就推翻 | `67`、`60` | 约束变体训练 |
| 代码弱 | 只会写功能，不讲边界 | `44`、`45`、`23` | 20 分钟代码面 |
| 公司匹配弱 | 腾讯/阿里/百度/字节都讲一套 | `55`、`75`、`76` | 公司专项模拟 |
| 表达弱 | 长、绕、没有结论 | `12`、`62`、`64` | 30 秒短答 |

### 5.1 弱点修复卡

每个 B/C 项都必须生成修复卡。没有复测题，不算修复动作。

```markdown
# 弱点修复卡

- 弱点名称：
- 暴露来源：模拟面 / 真实面 / 自评
- 原始问题：
- 扣分原因：知识缺口 / 项目证据 / 表达结构 / 追问层级 / 临场稳定 / 工程闭环
- 当前等级：A / B / C 或 1-5 分
- 修复文件：
- 训练动作：
- 复测题：
- 通过标准：
- 复测结果：
- B+ 证据：连续两次复测题号 / 日期 / 结果
- 是否关闭：
```

关闭规则：

```text
C 必须先复测到 B，进入继续训练；不能直接关闭。
B 必须复测到 A 或连续两次稳定 B+ 才能关闭。
没有复测结果，不能关闭。
```

## 6. 下一轮训练单生成器

复盘后用这个公式生成下一轮：

```text
下一轮训练 = 最高风险维度 50% + 目标公司风格 20% + JD top2 关键词 20% + 反问/救场 10%
```

如果最大短板是项目真实性：

```text
下一轮只练：
1. 60 秒项目入口。
2. 你具体负责什么？
3. 讲一个真实 bad case。
4. 怎么证明效果？
5. 如果面试官质疑这是 Demo，你怎么回答？
```

如果最大短板是系统设计：

```text
下一轮只练：
1. 1 分钟澄清需求。
2. 3 分钟画主链路。
3. 2 分钟讲核心模块。
4. 2 分钟讲评测、权限、成本、观测。
5. 追加一个约束：多租户 / 低延迟 / 私有化 / 成本降低 50%。
```

如果最大短板是公司匹配：

```text
下一轮只练：
1. 同一项目的腾讯版 / 阿里版 / 百度版 / 字节版改写。
2. 目标公司 3 个专项追问。
3. 1 个贴合公司的反问。
4. 按 `75` 打公司专项分。
```

## 7. 三轮模拟面节奏

### 第 1 轮：暴露问题

目标：不要追求答得漂亮，先找到最大短板。

建议：

- 用 `69` 生成 30 分钟题单。
- 全程录音。
- 只记录 1 个最大短板和 3 个高风险题。

### 第 2 轮：专项修复

目标：只打一个短板。

建议：

- 不做全套模拟。
- 只练项目 / 系统设计 / 公司专项 / 代码中的一个。
- 结束后比较该维度是否从 C 到 B 或 B 到 A。

### 第 3 轮：上场模拟

目标：模拟真实节奏。

建议：

- 用 `52` 做 45-60 分钟完整面。
- 用 `75` 做目标公司评分。
- 用 `66` 验收上场包。

## 8. 面试前 24 小时看板

最后 24 小时只看这张表：

| 项目 | 状态 | 不通过就补 |
|---|---|---|
| 1 分钟自我介绍 | A/B/C | `18`、`59` |
| 2 分钟项目入口 | A/B/C | `24`、`76` |
| 项目真实性 | A/B/C | `58`、`70` |
| P0 主干 | A/B/C | `28`、`29` |
| 系统设计 | A/B/C | `51`、`67` |
| 公司专项 | A/B/C | `55`、`75` |
| 安全/权限 | A/B/C | `71` |
| 代码/后端 | A/B/C | `44`、`45` |
| 反问 | A/B/C | `65` |
| 救场 | A/B/C | `62` |

上场规则：

```text
全部 A：正常上场。
1-3 个 B：只补 B，不看新资料。
任意 C：先补 C 对应文件，再做 15 分钟专项模拟。
```

## 9. 常见复盘误区

| 误区 | 后果 | 正确做法 |
|---|---|---|
| 每次都换新题 | 看似练很多，弱点没修 | 连续两轮打同一短板 |
| 只补知识点 | 开口仍然散 | 补完立刻 30 秒口述 |
| 复盘写太多 | 没有下一步动作 | 只写最大短板和下一轮目标 |
| 分数全靠感觉 | 难以判断进步 | 固定 7 维 A/B/C |
| 临面前继续扩展资料 | 焦虑上升 | 只补 C 和关键 B |

---

## 10. 最终速背

1. 模拟面的价值不是做完题，而是定位下一轮最该练什么。
2. 单次分数只能参考，连续 3 次趋势才决定真实短板。
3. 项目真实性、系统设计、公司匹配任一项为 C，都不该继续扩展新资料。
4. 弱点要映射到文件和下一轮训练题，否则复盘没有闭环。
5. 最后一小时不看新东西，只看最高风险 B/C、救场、反问和目标公司专项；最后 30 分钟切到 `78`。
