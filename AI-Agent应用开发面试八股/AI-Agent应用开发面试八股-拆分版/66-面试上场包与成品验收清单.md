# 面试上场包与成品验收清单

> 目标：面试前最后确认自己手里有哪些“可直接上场”的成品。  
> 资料看完不等于准备好了。真正准备好，是你能拿出一套稳定的口播、项目、防守、代码、系统设计和反问。

最小配合文件：

- `80-JD实战转化闭环工单.md`：本次 JD 压缩上场包；`66` 只提供分层验收口径，完整包只用于 3 天及以上。
- `78-临面当天作战面板.md`：面试当天最后 30 分钟/10 分钟/3 分钟只看这一份。
- `48-面试通知速查导航卡.md`、`55-公司轮次面试路径卡.md`：收到通知后确定时间路线、公司口径和轮次重点。
- `77-模拟面闭环数据看板与弱点修复手册.md`：1 天及以上有模拟记录时，用来确认 Top2 弱点。

候选补充文件只在对应短板出现时打开：`65` 反问、`70` 项目证据、`71` 安全、`72` 模型基础、`73` Data Agent、`75` 公司专项、`76` 项目迁移。`34` 是旧版余力查漏，不作为最后复习路线。

## 1. 上场包总览

19 项是 3 天及以上的完整成品池；只剩 2 小时或半天时，先看 `1.0 分层验收`，不要按本表补全：

| 成品 | 用途 | 合格标准 |
|---|---|---|
| 1 分钟自我介绍 | 开场 | 不背稿，30 秒内说清方向和项目 |
| 2 分钟项目入口 | 项目深挖入口 | 背景、职责、链路、难点、指标 |
| 5 分钟项目答辩 | 二面/主管面 | 能讲业务价值、架构、难点、结果 |
| 1 套项目迁移表达 | 多岗位/多公司投递 | 同一项目能按 RAG、Agent、平台、Data Agent、ToB 等方向改写 |
| 1 份项目证据包 | 项目真实性 | README、架构图、Demo、API/schema、评测、脱敏说明 |
| 简历逐行防守 | 项目真实性 | 每条 bullet 能答 3 层 |
| 20 道 P0 口述 | 一面保底 | 30 秒主干，2 分钟展开 |
| 5 个 bad case | 二面防守 | 现象、定位、修复、验证 |
| 1 张系统设计图 | 二面/三面 | 五层架构、关键模块、治理 |
| 1 套安全风控回答 | 二面/三面/ToB | Prompt injection、RAG 越权、危险工具、MCP/Data Agent 安全 |
| 1 套模型基础回答 | 一面/算法应用 | Transformer、token、embedding、rerank、temperature、RAG vs 微调 |
| 1 套 Data Agent 回答 | 数据分析/平台/ToB | NL2SQL、schema linking、指标口径、SQL 安全、图表解释 |
| 1 次公司专项模拟评分 | 临面前校准 | 能按目标公司风格回答，不把所有公司都讲成同一套 |
| 1 张模拟面闭环看板 | 复盘与修复 | 连续模拟面能看出弱点趋势，并生成下一轮训练动作 |
| 1 张临面当天作战面板 | 最后 30 分钟 | 只看开场、项目入口、最高风险题、救场和反问 |
| 2 道代码模板 | 代码面 | 能边写边讲复杂度和边界 |
| 3 个技术取舍 | 深挖/系统设计 | 收益、代价、兜底、指标 |
| 1-3 个反问 | 收尾 | 至少 1 个贴合公司、岗位、轮次 |
| 6 句救场话术 | 临场卡壳 | 听不清、不会、答散、被质疑、代码卡住、收尾都能接住 |

如果完整包里任意 3 项没有成品，不要再随机翻资料，先按剩余时间补 `1.0` 的最低上场线。

## 1.0 分层验收

完整上场包是 19 项，但不同剩余时间不要用同一个验收标准。

| 剩余时间 | 验收范围 | 通过标准 |
|---|---|---|
| 2小时 | 2小时极速包：8项 | 优先保证 8 项都有一句可说；允许占位句，空白项只补最高风险 1-2 项 |
| 半天 | 标准上场包：13 项 | 核心 8 项无空白；13 项允许草稿；Top2 风险题至少有 30 秒救场句 |
| 1 天 | 标准上场包：13 项 | 至少 8 个 A，最多 5 个 B；C 只允许出现在非本轮高风险补充项 |
| 3 天及以上 | 完整上场包：19 项 | 至少 13 个 A，最多 6 个 B，不能有 C |

2小时极速包：

1. 公司 / 岗位 / 轮次。
2. JD top3。
3. 1 分钟自我介绍第一句。
4. 2 分钟项目入口第一句。
5. 最高风险题 30 秒版。
6. 1 个真实 bad case。
7. 2 个反问。
8. 2 句救场。

半天 / 1 天标准上场包：

1. 公司 / 岗位 / 轮次。
2. JD top3。
3. 1 分钟自我介绍第一句。
4. 2 分钟项目入口第一句。
5. 最高风险题 30 秒版。
6. 1 个真实 bad case。
7. 2 个反问。
8. 2 句救场。
9. 10 分钟迷你题单。
10. 1 次口述模拟记录。
11. Top2 弱点和修正文件。
12. 1 个评测 / 观测 / 安全证据，按本轮 JD 最高风险选择。
13. `78` 最后 30 分钟启动确认。

候选补充项只按轮次选 0-2 项，是 13 项之外的加分项：

- 系统设计 / 代码面：补 1 张系统设计图或 1 个代码模板。
- ToB / 平台 / 安全面：补 1 个评测、观测或安全证据。
- 明确目标公司：补 1 次公司专项风格校准。

## 1.1 本次 JD 上场包一页版

参考文件：`80`、`78`。

`80` 的一页版是“本次 JD 压缩上场包”，用于临面前快速启动；本文件是分层成品验收标准，其中完整成品验收只适用于 3 天及以上。

临面前不要重新翻全库，把本次公司、岗位、轮次压成一页：

```markdown
# 本次 JD 上场包

- 公司 / 岗位 / 轮次：
- 面试时间：
- 面试官可能关注：
- 1 分钟自我介绍第一句：
- 2 分钟项目入口第一句：
- 最高风险题 30 秒版：
- 真实 bad case：
- 系统设计主图：
- 技术取舍：
- 安全/权限回答：
- 目标公司反问：
- 救场句：
```

- [ ] 所有内容来自本次 JD、简历项目或模拟面复盘。
- [ ] 最高风险题优先来自 `77` 的 B/C；未做模拟时，用 `80` 自评最高风险。
- [ ] 最后 30 分钟只看这一页和 `78`。

## 2. 1 分钟自我介绍验收

参考文件：`18`、`19`、`59`。

成品模板：

```text
我主要关注 [方向]，做过 [项目类型]，熟悉 [技术栈]。
项目里我主要负责 [模块]，关注 [RAG/Agent/工具/后端/评测]。
我比较看重的是把大模型能力做成可评估、可追踪、可兜底的工程系统。
```

验收：

- [ ] 60 秒以内。
- [ ] 不超过 3 个技术关键词堆叠。
- [ ] 能自然过渡到项目。
- [ ] 不夸大经历。

## 3. 2 分钟项目入口验收

参考文件：`18`、`24`、`59`。

完整项目入口建议包含；半天只保证前 4 项能说清：

```text
业务背景
目标用户
我的职责
核心链路
最大难点
验证方式
```

验收问题：

- [ ] 面试官能听出你主责哪一块吗？
- [ ] 是否出现真实模块、数据、接口或日志？
- [ ] 是否有一个可追问的 bad case？
- [ ] 是否能在 2 分钟自然停下？

## 4. 简历逐行防守验收

参考文件：`58`。

每条 bullet 都要能回答：

```text
这条是你主责还是参与？
具体做了哪一步？
为什么这么做？
怎么验证有效？
出过什么问题？
边界是什么？
```

危险项：

- [ ] 写了“负责整体”，但其实只做模块。
- [ ] 写了“优化效果”，但没有指标。
- [ ] 写了“上线”，但说不清用户和日志。
- [ ] 写了“Agent”，但说不清 state、tool、权限和终止条件。

## 4.1 项目证据包验收

参考文件：`70`。

最低上场线：

- [ ] 任选 2 类真实性证据：README、架构图、Demo 说明、API / Tool schema、trace 字段、评测表、bad case。
- [ ] 1 句脱敏说明：哪些内容不能展示，能展示什么替代证据。

充足时间下再补：

- [ ] 1 个项目 README。
- [ ] 1 张架构图。
- [ ] 1 个 Demo 脚本或截图说明。
- [ ] 3 个 API / Tool schema / trace 字段样例。
- [ ] 1 张评测表。
- [ ] 3 个 bad case。
- [ ] 1 份脱敏说明。

- [ ] 面试官问“有 Demo 吗”时，能诚实说明项目阶段和可展示内容吗？

- [ ] 是否避免展示公司源码、客户数据、token、内部域名和生产日志？

## 5. P0 口述验收

参考文件：`27`、`28`、`29`、`64`。

完整包建议准备 20 题；半天只选和 JD top3 最相关的 5-10 题：

```text
项目 5 题
RAG 5 题
Agent/Tool 5 题
LangGraph/后端 5 题
```

合格标准：

- [ ] 每题 30 秒能说主干。
- [ ] 至少 10 题能接项目例子。
- [ ] 不出现概念混淆。
- [ ] 被追问一次不重复原句。

快速不合格信号：

```text
我知道但是讲不出来。
这个框架自动处理。
我们没有遇到 bad case。
准确率提升很多但没有指标。
```

## 6. Bad Case 上场包

参考文件：`42`、`54`、`57`。

完整包建议准备 5 个；半天只准备 1-2 个最能证明真实性的 bad case：

| 类型 | 示例 |
|---|---|
| RAG 召回失败 | 正确文档没进 topK |
| RAG 引用错误 | 引用片段不支持答案 |
| Agent 工具失败 | 参数错、超时、权限拒绝 |
| 成本/延迟问题 | topK 太大、rerank 太慢 |
| 项目协作问题 | 需求变化、评测口径不一致 |

每个 bad case 的口播结构：

```text
现象
影响
定位
根因
修复
验证
复盘
```

验收：

- [ ] 不是虚构问题。
- [ ] 有 trace / 日志 / 评测 / 人工反馈中的至少一种证据。
- [ ] 能讲修复代价。
- [ ] 能讲下次怎么避免。

```text
入口层
  -> 编排层
```

验收：

- [ ] 1 分钟能澄清需求。
- [ ] 3 分钟能画主链路。
- [ ] 5 分钟能讲关键模块。
- [ ] 2 分钟能讲权限、评测、成本、兜底。

- [ ] 面试官追加多租户、低延迟、私有化、强审计等约束时，不推翻原架构，能说明影响层、模块调整、指标和兜底。

## 8. 安全风控上场包

参考文件：`71`。

至少准备 6 题：

```text
Prompt injection 怎么防
RAG 怎么防越权召回
高风险工具怎么确认和审计
MCP 安全边界在哪里
Data Agent 怎么防危险 SQL
日志和 Demo 怎么脱敏
```

验收：

- [ ] 不说“靠 system prompt 保证安全”。
- [ ] 能区分软约束和硬约束。
- [ ] 能讲权限、schema、确认、幂等、审计。
- [ ] 能讲安全评测集和指标。
- [ ] 能诚实说明项目里已做和未做的安全能力。

## 9. 模型基础上场包

参考文件：`72`。

至少准备 8 题：

```text
Transformer / Attention 是什么
token 和上下文窗口是什么
embedding 是什么
向量相似度怎么理解
rerank 为什么有效
temperature / top_p / max_tokens 怎么影响输出
为什么会幻觉
RAG vs 微调怎么选
```

验收：

- [ ] 能用 30 秒解释，不讲成算法论文。
- [ ] 能把模型基础落到 RAG、Agent、模型网关或项目里。
- [ ] 能讲清 token 成本、上下文噪声和长上下文局限。
- [ ] 能讲 embedding、BM25、rerank 的配合。
- [ ] 能承认自己不是预训练方向，但理解应用边界。

## 9.1 Data Agent / NL2SQL 上场包

参考文件：`73`、`71`、`23`。

成品模板：

```text
我会把 Data Agent 拆成语义理解、schema linking、指标口径、SQL 生成、SQL 校验、权限过滤、查询执行、结果解释和图表生成几层。模型不直接连生产库，SQL 先过 AST 校验、表字段白名单、limit、超时、cost 和权限检查；指标必须走统一口径，结果要给出 SQL、口径、时间范围和不确定性。
```

验收：

- [ ] 能解释 NL2SQL 为什么难，不只说“模型生成 SQL”。
- [ ] 能讲 schema linking、指标口径、权限、SQL 安全、图表解释五件事。
- [ ] 能把 `23` 里的 SQL 只读校验和 limit 题接到生产设计。
- [ ] 能说明 Data Agent 与 RAG/普通 Agent 的关系。
- [ ] 至少能给 1 个 SQL / 指标 / 权限 / 图表 bad case，并说清 execution accuracy、metric accuracy 或 security pass rate 中至少 2 个指标。
- [ ] 至少能展示 1 个指标口径或 SQL 安全证据：SQL 样例、Metric Contract、权限校验、validator 测试用例任选。

## 11. 技术取舍上场包

参考文件：`60`。

至少准备 3 个：

```text
RAG vs 微调
Agent vs workflow
SSE vs WebSocket
MCP vs OpenAPI
pgvector vs 专用向量库
外部 API vs 私有化模型
准确率 vs 延迟 vs 成本
```

回答结构：

```text
看场景约束
  -> 比较候选方案
  -> 说明选择理由
  -> 承认代价
  -> 给兜底和指标
```

验收：

- [ ] 不说“绝对更好”。
- [ ] 能讲适用场景。
- [ ] 能讲代价。
- [ ] 能讲验证方式。

## 12. 反问上场包

参考文件：`65`。

准备 3 个：

```text
1 个问岗位实际工作
1 个问团队当前挑战
1 个问前三个月期望
```

示例：

```text
这个岗位实际工作中，RAG、Agent、工具平台、后端工程这几块权重如何？
```

```text
团队当前大模型应用线上化最大的挑战是什么？
```

```text
如果我加入，前三个月最希望我补上的能力或负责的模块是什么？
```

不要问：

- 面试一上来问薪资。
- 直接问加班多不多。
- 问官网能查到的信息。
- 问“你觉得我表现怎么样”。

## 13. 临场救场上场包

参考文件：`62`。

至少背 6 句：

```text
我确认一下，您是想问概念区别，还是项目落地？
```

```text
这个点我没有完整做过，但我会按这几层拆。
```

```text

```

```text

```

```text

```

```text
我先保证正确性，再优化复杂度。
```

验收：

- [ ] 说出来不僵硬。
- [ ] 不像背模板。
- [ ] 能接回项目或工程思路。

判定：

```text
A：能自然说，能接追问。

```

完整包要求：

```text
至少 13 个 A
最多 6 个 B
不能有 C
```

如果还有 C，不要继续刷新资料，先把 C 补到 B；2 小时和半天仍以前面的分层验收为准。
