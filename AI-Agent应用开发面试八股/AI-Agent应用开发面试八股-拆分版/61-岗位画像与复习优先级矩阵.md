# 岗位画像与复习优先级矩阵

> 目标：同样叫“AI Agent / 大模型应用开发”，不同岗位真正考察点完全不同。  
> 这份文件帮你判断自己投的是 RAG 岗、Agent 岗、平台岗、Python 后端岗、算法应用岗，避免平均用力。

配合文件：

- `37-JD关键词匹配与投递策略.md`：从 JD 提取关键词。
- `39-个人复习计划生成器.md`：按剩余时间排计划。
- `55-公司轮次面试路径卡.md`：按公司和轮次行动。
- `60-技术选型与取舍防守手册.md`：准备技术取舍。

## 1. 岗位画像总表

| 岗位画像 | 面试主线 | 最容易被追问 | 最优先文件 |
|---|---|---|---|
| RAG / 知识库应用 | 检索增强、引用、评测 | chunk、召回、rerank、权限、bad case | `04`、`30`、`54`、`60` |
| AI Agent 工程 | 状态、工具、编排、失败恢复 | LangGraph、Tool schema、权限、环路控制 | `02`、`03`、`05`、`42` |
| MCP / 工具平台 | API 接入、协议、工具治理 | OpenAPI 转 Tool、MCP、审计、风险分级 | `08`、`31`、`53`、`60` |
| 模型网关 / 平台 | 多模型、Prompt、成本、灰度 | 路由、fallback、观测、评测、SLA | `32`、`53`、`54`、`60` |
| Python AI 后端 | FastAPI、异步、SSE、工程稳定性 | asyncio、限流、任务队列、日志、代码题 | `07`、`44`、`45`、`60` |
| 算法应用 / 微调 | 数据、embedding、rerank、LoRA | RAG vs 微调、模型基础、数据构造、评测、过拟合 | `06`、`30`、`31`、`54`、`72` |
| AI 产品 / 解决方案 | 场景闭环、Demo 到交付 | 需求拆解、MVP、ROI、业务指标 | `53`、`55`、`59`、`43` |

判断原则：

```text
JD 里出现最多的不是岗位名，而是岗位真实考点。
```

比如标题写“AI Agent 工程师”，但 JD 里反复出现“知识库、文档解析、向量检索、召回排序、引用溯源”，实际更像 RAG 岗。

## 2. RAG / 知识库应用岗

### 2.1 必须会

- RAG 全链路：解析、清洗、切分、embedding、索引、召回、rerank、生成、引用。
- chunk 策略：标题、段落、token、overlap、表格、代码、FAQ。
- 召回策略：向量、BM25、混合召回、query rewrite、多查询。
- 向量库：metadata filter、索引、增量更新、多租户。
- 评测：Recall@K、MRR、NDCG、faithfulness、citation accuracy。
- bad case：召回不到、排序靠后、幻觉、引用错误、权限越权。

### 2.2 可加分

- 表格/PDF/OCR 处理。
- 父子 chunk、层级索引。
- query rewrite / HyDE / multi-query。
- rerank 成本和延迟控制。
- RAG 自动评测和 bad case 回流。

### 2.3 可以少花时间

- 多 Agent 协作。
- 复杂 MCP 平台。
- LoRA 训练细节。
- 大规模模型部署。

### 2.4 项目表达重点

```text
我做的不是简单向量库问答，而是围绕企业知识可信做了文档结构化、权限过滤、混合召回、引用校验和评测回流。
```

### 2.5 面试 2 小时冲刺

```text
40 分钟：`04` RAG 基础
30 分钟：`30` RAG 进阶
25 分钟：`54` 指标和 bad case
15 分钟：`60` RAG vs 微调、混合召回、rerank 取舍
10 分钟：准备一个项目 bad case
```

## 3. AI Agent 工程岗

### 3.1 必须会

- Agent 基本循环：观察、思考、行动、反馈、终止。
- Tool Calling：schema、参数校验、权限、审计、超时、重试、幂等。
- 状态管理：messages、intent、slots、tool_calls、risk_level、final_answer。
- LangGraph：StateGraph、node、edge、checkpoint、interrupt、human-in-the-loop。
- 失败控制：最大步数、循环检测、fallback、人工接管。
- 评测：任务完成率、工具选择准确率、参数准确率、人工接管率。

### 3.2 可加分

- Agent + 工作流混合设计。
- 多 Agent 分工边界。
- 工具风险分级。
- Agent trace 回放。
- 长短期 memory 的边界。

### 3.3 可以少花时间

- HNSW/IVF/PQ 细节。
- LoRA 训练超参数。
- 大规模 embedding 训练。

### 3.4 项目表达重点

```text
我的 Agent 不是让模型自由乱跑，而是把模型放在意图识别、工具选择和参数补全上，关键业务动作仍然通过状态机、权限、确认和审计控制。
```

### 3.5 面试 2 小时冲刺

```text
30 分钟：`02` Agent 基础和治理
35 分钟：`03` LangGraph
25 分钟：`05` Tool Calling
20 分钟：`42` 项目追问
10 分钟：`60` Agent vs 工作流取舍
```

## 4. MCP / 工具平台岗

### 4.1 必须会

- OpenAPI：paths、methods、parameters、requestBody、response schema。
- OpenAPI 转 Tool：工具名、描述、input_schema、output_schema、风险等级。
- MCP：tools、resources、prompts、client/server 边界。
- 工具网关：鉴权、限流、权限、审计、幂等、错误码。
- 工具治理：版本、兼容、mock、灰度、调用 trace。

### 4.2 可加分

- MCP Server 原型。
- Tool Registry 设计。
- 工具市场/插件市场。
- 企业内部 RPC/HTTP 服务包装。
- 高风险工具确认和审批。

### 4.3 可以少花时间

- 复杂 RAG 评测指标细节。
- 微调训练。
- 多模态 OCR 细节。

### 4.4 项目表达重点

```text
我把工具接入看成企业 Agent 的基础设施：不是给某个 Agent 临时写函数，而是统一管理工具 schema、权限、审计、风险和复用。
```

### 4.5 面试 2 小时冲刺

```text
35 分钟：`08` 协议和 MCP
30 分钟：`31` OpenAPI/RPC/MCP 标准回答
25 分钟：`53` 工具平台蓝图
20 分钟：`60` MCP vs OpenAPI vs SDK
10 分钟：准备一个 tool schema 示例
```

## 5. 模型网关 / 大模型平台岗

### 5.1 必须会

- 模型网关：统一 API、provider adapter、路由、fallback。
- Prompt 管理：版本、灰度、回滚、评测。
- 观测：token、latency、error、cost、trace。
- 多租户：app_id、tenant_id、quota、权限。
- 稳定性：限流、熔断、重试、降级。
- 评测：离线集、线上抽样、A/B、bad case 回流。

### 5.2 可加分

- OpenAI-compatible API。
- 多模型 capability registry。
- 成本看板和异常排查。
- 模型质量和成本动态路由。
- Prompt/模型/工具版本联动。

### 5.3 可以少花时间

- 单个 RAG chunk 的细枝末节。
- 具体 LoRA 训练脚本。
- 复杂前端页面。

### 5.4 项目表达重点

```text
模型网关不是普通 SDK wrapper，它解决的是多个业务统一接模型后的鉴权、配额、路由、fallback、成本、Prompt 版本和评测治理。
```

### 5.5 面试 2 小时冲刺

```text
40 分钟：`32` 平台系统设计
30 分钟：`53` 模型网关蓝图
25 分钟：`54` 成本、灰度、观测
15 分钟：`60` 外部 API vs 私有化、成本 vs 准确率
10 分钟：准备一张模型网关架构口播
```

## 6. Python AI 后端岗

### 6.1 必须会

- FastAPI：路由、中间件、依赖注入、异常处理。
- async/await：I/O 密集、并发控制、超时取消。
- SSE/WebSocket：流式输出、断连处理。
- 限流：令牌桶、滑动窗口。
- 缓存：热点问题、embedding、检索结果。
- 任务队列：文档解析、embedding 入库、异步任务状态。
- 日志：trace_id、user_id、model、prompt_version、latency、cost。

### 6.2 可加分

- backpressure。
- 连接池和超时配置。
- 模型调用熔断。
- 文件上传和异步索引任务。
- 小工程题现场实现。

### 6.3 可以少花时间

- 多 Agent 理论。
- 复杂微调算法。
- 向量索引底层数学。

### 6.4 项目表达重点

```text
我偏后端落地，所以会重点讲大模型调用链路里的异步、流式、限流、超时、任务队列、日志和异常兜底，而不是只讲 Prompt。
```

### 6.5 面试 2 小时冲刺

```text
35 分钟：`07` Python 后端基础
35 分钟：`44` 手撕模板
25 分钟：`45` 代码面口播

```

### 7.3 可以少花时间

## 9. 混合型 JD 怎么排优先级

很多 JD 会同时写：

```text
RAG + Agent + MCP + FastAPI + 模型网关 + 微调
```

不要平均分配。按下面规则排：

### 9.1 权重判断

| 信号 | 权重 |
|---|---|
| 岗位职责第一条 | 最高 |
| 任职要求反复出现 | 高 |
| JD 写“熟悉/掌握/精通” | 高 |
| 加分项/优先 | 中 |
| 只出现一次的工具名 | 低 |

### 9.2 三主线法

每个 JD 最多选 3 条主线：

```text
主线 1：必须拿分
主线 2：被追问能防守
主线 3：加分项
```

示例：

```text
JD：负责企业知识库 Agent，基于 LangGraph 和 MCP 接入内部系统，支持权限、评测和模型网关。

主线 1：RAG 知识库。
主线 2：Agent + Tool/MCP。
主线 3：平台治理和模型网关。
```

对应复习：

```text
P0：`04`、`30`、`54`
P1：`03`、`05`、`08`
P2：`32`、`53`、`60`
```

## 10. 自我画像怎么补短板

### 10.1 后端强，AI 弱

优势：

- FastAPI、并发、接口、日志、稳定性。

短板：

- RAG/Agent 概念边界。
- Prompt/Tool Calling。
- 评测指标。

补法：

```text
先补 `04`、`05`、`56`
再用 `53` 把后端项目包装成大模型应用
最后用 `54` 补指标和 bad case
```

### 10.2 算法强，工程弱

优势：

- 模型、embedding、微调、评测。

短板：

- 工具权限、后端稳定性、系统设计。

补法：

```text
先补 `07`、`08`、`32`
再用 `60` 练工程取舍
最后用 `51` 练白板讲解
```

### 10.3 项目弱，八股强

优势：

- 概念能答。

短板：

- 简历和项目追问。

补法：

```text
先用 `53` 选项目蓝图
再用 `50` 填真实证据
用 `58` 压测简历 bullet
用 `59` 练分轮次口播
```

### 10.4 表达弱，内容会

优势：

- 知识储备够。

短板：

- 开口散、被追问慌。

补法：

```text
用 `12` 练三件套
用 `52` 做陪练
用 `57` 录音复盘
用 `41` 打分
```
