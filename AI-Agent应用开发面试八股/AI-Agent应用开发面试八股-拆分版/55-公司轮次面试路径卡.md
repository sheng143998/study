# 公司轮次面试路径卡

> 目标：拿到面试通知后，不再纠结“先看哪份”。  
> 这份文件把腾讯、阿里/阿里云、百度、字节、美团/京东、云厂商/企业服务等方向，拆成公司 × 轮次 × 时间预算的行动卡。

配合文件：

- `40-大厂公司轮次作战手册.md`：公司风格和轮次目标。
- `46-公司轮次题型增量库.md`：公开面经/JD 趋势。
- `48-面试通知速查导航卡.md`：收到通知后的 5 分钟决策。
- `80-JD实战转化闭环工单.md`：把本轮 JD、题单、模拟、弱点和上场包串成交付物。
- `69-JD到模拟面题单生成器.md`：按公司、轮次、JD 关键词生成模拟题单。
- `52-面试官陪练脚本手册.md`：按脚本模拟追问。
- `75-公司风格模拟面评分矩阵.md`：按目标公司风格追问和评分。
- `53-端到端项目蓝图库.md`：准备可讲项目。
- `54-项目指标与BadCase量化手册.md`：准备指标和 bad case。

## 1. 怎么使用这份路径卡

收到面试通知后，按这个顺序：

```text
确认公司和业务线
  -> 确认轮次：一面 / 二面 / 交叉 / 主管 / HR
  -> 确认剩余时间：2 小时 / 半天 / 1 天 / 3 天
  -> 先填 `80` 极速工单：公司/岗位/轮次/JD top3/最高风险
  -> 选对应路径卡
  -> 只决定替换哪 1 个专题
  -> 产出本轮候选材料
  -> 2 小时只用 `80` 迷你题单自测；半天只在 `80/74` 内口述自评；1 天及以上再进入完整 `69/52`
```

不要把所有文件都打开。路径卡只要求你交付本轮要用的几样东西。

2 小时场景的统一前置规则：

```text
先用 `80` 填 5 项：公司 / 岗位 / 轮次 / JD top3 / 最高风险。
本路径卡只决定“多看哪 1 个公司或岗位专题”，不要重新铺开全量资料。
各公司分节里的“2 小时专题替换槽”不是新路线，必须嵌入 `48 -> 80 -> 74 -> 78`，只替换 `74` 里 80-100 分钟的 1 个专题槽。
```

半天场景的统一前置规则：

```text
先走 `48 -> 55 -> 80 -> 74 -> 78`。
本路径卡只决定：1 个公司口径、1 个轮次专题、2 个反问。
不要把公司分节扩展成新路线；所有交付物回填到 `80`，并用 `66` 的半天最低线点检 13 项状态，不要求每项打磨到 A。
```

半天及以上本轮输出物。2小时只验收 `80` 的 2小时极速包：8项，不要求完成本表：

| 输出物 | 用途 | 最低标准 |
|---|---|---|
| 1 分钟自我介绍 | 开场稳定 | 能自然说完，不像背稿 |
| 2 分钟项目入口 | 项目深挖入口 | 背景、职责、链路、难点、指标 |
| 1 张架构图口播 | 系统设计/项目追问 | 能讲入口、编排、检索/工具、模型、治理 |
| 10 个 P0 标准回答 | 一面保底 | 30 秒能答出主干 |
| 5 个 bad case | 二面/主管面 | 能讲定位、修复、评估 |
| 1-3 个反问 | 收尾 | 至少 1 个贴合公司和轮次 |
| 本轮 JD 上场包 | 临面前只看一页 | 来自 `80`，包含最高风险 B/C、救场句和反问 |

## 2. 5分钟定位卡

任何公司都先做这一页，这是一张通用定位卡。

### 2.1 信息提取

从 JD/通知里提取：

```text
公司：
部门/业务线：
岗位名称：
轮次：
面试时长：
关键词：
是否代码面：
是否系统设计：
是否主管/HR：
```

5分钟内只产出下面这张卡，不打开专题文件：

```markdown
# 5分钟定位卡

- 公司 / 业务线：
- 轮次：
- 剩余时间：2 小时 / 半天 / 1 天 / 3 天
- JD top3：
  1.
  2.
  3.
- 本轮最像哪类面试：一面 / 二面 / 代码 / 系统设计 / 主管HR
- 候选替换专题，只选 1 个：
- 2 个公司口径词：
- 2 个反问方向：
```

写完立刻回 `80`。只有进入 `74` 的时间盒后，才允许打开候选专题。

关键词映射：

| JD 关键词 | 说明 | 候选池，不直接打开；最终只落 1 个到 `74` 替换槽 |
|---|---|---|
| RAG / 知识库 / AI Search | 检索增强是主线 | `04`、`30`、`54` |
| Agent / Workflow / LangGraph | 编排和状态是主线 | `03`、`29`；`52` 只在半天及以上模拟阶段使用 |
| Tool Calling / MCP / OpenAPI | 工具和协议是主线 | `05`、`08`、`31` |
| 模型网关 / LLMOps / 平台 | 治理和平台是主线 | `32`、`53`、`54` |
| FastAPI / Python / 后端 | 工程基础会被问 | `07`、`44`、`45` |
| 微调 / LoRA / PEFT | 算法应用会被问 | `06`、`31` |
| Data Agent / ChatBI | 查数、指标口径和 SQL 安全是主线 | `73`、`71` |
| 实时 / 语音 / SSE | 低延迟、可打断、流式和观测会被问 | `44`、`70`、`68` |
| A2A / 多 Agent 协作 | 委派、scope、结果验收和审计会被问 | `68`、`71`、`44` |

### 2.2 轮次目标判断

| 轮次 | 今天最重要的事 | 不要过度投入 |
|---|---|---|
| 一面 | P0 八股 + 项目真实性 + 代码基础 | 大而全平台架构 |
| 二面 | 项目深挖 + bad case + 系统设计 | 只背定义 |
| 交叉面 | 通用能力 + 迁移表达 | 只讲自己项目细节 |
| 主管面 | 业务价值 + owner 意识 + 取舍 | 过细代码实现 |
| HR 面 | 动机稳定 + 沟通成熟 | 技术细枝末节 |

## 3. 腾讯路径卡

腾讯风格关键词：

```text
真实业务、用户体验、稳定落地、效果指标、线上兜底
```

### 3.1 腾讯一面

2 小时专题替换槽：

```text
替换 `74` 的 80-100 分钟专题槽：
腾讯一面优先选 `04` 准备 RAG 可信度和召回失败。
如果是代码面，改选 `44` 默写 SSE / 限流 / LRU 中 1 题。
不要覆盖 `80` 极速工单、项目入口、bad case、反问和 `78` 启动。
```

1 天公司权重提示：

1 天仍执行 `80 -> 74 -> 69/52/41 -> 77 -> 66 -> 78`。本段只替换下午 1-2 个专题：

- 项目真实性风险最高：选 `18`、`20` 或 `50`。
- RAG / Agent 风险最高：选 `04` 或 `05`。
- 代码面风险最高：选 `44`。

候选回答：

1. 你的项目用户是谁？
2. RAG 链路是什么？
3. 召回不准怎么定位？
4. Agent 工具调用失败怎么办？
5. SSE 流式响应怎么实现？
6. 项目里有哪些线上 bad case？

腾讯表达句：

```text
这个项目我会先从用户场景讲，因为腾讯这类业务很看重真实体验。技术上我主要围绕准确率、响应速度和异常兜底做优化，避免只停留在 Demo。
```

### 3.2 腾讯二面/交叉面

2 小时专题替换槽：

```text
替换 `74` 的 80-100 分钟专题槽：
系统设计轮 -> `51`；项目真实性风险最高 -> `42`；bad case 风险最高 -> `54`。
三者只选一个，不得叠加。
```

候选输出：

- 一个完整 bad case：现象、定位、根因、修复、验证。
- 一个体验优化：延迟、引用、转人工、答案结构化。
- 一个取舍：准确率 vs 延迟，自动化 vs 人工确认。

可选追问：

```text
如果用户说答案不可信，你怎么改？
如果知识库更新后答案仍然旧，怎么查？
如果 Agent 误操作用户数据，怎么防？
如果 QPS 放大 10 倍，哪些模块先出问题？
```

### 3.3 腾讯主管/HR

候选素材，不是本轮主路径：

- `43-HR主管面行为面回答手册.md`
- `24-项目答辩讲稿版.md`
- `54-项目指标与BadCase量化手册.md`

候选表达点：

- 你怎么发现问题。
- 你怎么推动协作。
- 你怎么衡量价值。
- 你怎么复盘失败。

反问候选：

```text
团队当前 AI Agent 应用更关注提升用户体验，还是提升内部效率？
现在业务里大模型应用最大的挑战是效果、成本、稳定性，还是数据接入？
如果入职后参与相关项目，前 3 个月最希望新人补上的能力是什么？
```

## 4. 阿里 / 阿里云路径卡

阿里风格关键词：

```text
平台化、抽象、规模化复用、多租户、治理、工程体系
```

### 4.1 阿里一面

2 小时专题替换槽：

```text
只替换 `74` 的 80-100 分钟专题槽，下面只选 1 个：
- JD 写 LangGraph / workflow：选 `03` 或 `29`
- JD 写 MCP / OpenAPI / 工具平台：选 `08`
- 明确代码面 / 后端面：选 `07` 或 `44`
- JD 写 Prompt / 协议 / 微调边界：选 `31`

禁止在 2 小时内同时打开 4 份专题；其余时间仍按 `48 -> 80 -> 74 -> 78`。
```

候选回答：

1. LangChain 和 LangGraph 区别。
2. StateGraph 的 state 怎么设计。
3. checkpoint 的价值。
4. OpenAPI 怎么转 Tool。
5. MCP 和 OpenAPI/RPC 的关系。
6. 模型调用怎么限流、重试、降级。

阿里表达句：

```text
我不会把它只做成单个业务的脚本，而是会抽象成可复用的平台能力，比如工具注册、权限、审计、模型路由和 Prompt 版本管理。
```

### 4.2 阿里二面/系统设计

1 天公司权重提示：

1 天仍执行 `80 -> 74 -> 69/52/41 -> 77 -> 66 -> 78`。本段只替换下午 1-2 个专题：

- 模型网关 / Prompt 平台：选 `32`。
- MCP/OpenAPI 工具平台：选 `53`。
- 指标、灰度、成本异常：选 `54`。
- 白板系统设计：选 `51`。

白板题候选：

```text
设计一个企业级 Agent 平台。
设计一个模型网关。
设计一个 OpenAPI 转 Tool 的平台。
```

回答骨架：

```text
入口层：鉴权、租户、限流
编排层：Agent runtime、workflow、state
工具层：Tool registry、OpenAPI adapter、MCP server
模型层：model gateway、router、fallback
治理层：prompt version、eval、audit、cost
```

取舍候选：

- 平台通用性 vs 业务定制。
- 自由 Agent vs 显式工作流。
- 模型侧权限 vs 工具网关权限。
- Prompt 快速迭代 vs 稳定灰度。

### 4.3 阿里主管面

要强调：

- 如何从单点需求抽象出平台能力。
- 如何定义模块边界。
- 如何推动多个业务接入。
- 如何避免过度设计。

反问候选：

```text
团队当前的大模型应用更偏业务交付，还是偏平台底座建设？
Agent 工具接入目前是各业务自建，还是有统一网关/平台？
对于新人来说，最需要补的是业务理解、平台工程，还是模型应用经验？
```

## 5. 百度路径卡

百度风格关键词：

```text
检索、排序、知识增强、模型边界、效果评测
```

### 5.1 百度一面

2 小时专题替换槽：

```text
只替换 `74` 的 80-100 分钟专题槽，下面只选 1 个：
- JD 写 RAG / 知识库 / 搜索：选 `04`
- 二面深挖 RAG 进阶：选 `30`
- JD 写模型基础 / 微调：选 `06` 或 `31`
- 面试官偏平台/效果评估：选 `54`

禁止在 2 小时内连续刷 RAG 全家桶；其余时间仍按 `48 -> 80 -> 74 -> 78`。
```

候选回答：

1. RAG 完整链路。
2. chunk 大小怎么选。
3. 向量召回和 BM25 为什么要结合。
4. rerank 放在哪一层。
5. Recall@K、MRR、NDCG 怎么理解。
6. 什么时候 RAG，什么时候微调。

百度表达句：

```text
我会把问题拆成检索层和生成层。检索层看正确证据是否召回和排序，生成层看答案是否忠于证据，并用评测集而不是主观感觉判断效果。
```

### 5.2 百度二面

候选素材，不是本轮主路径：

- 多文档综合问答。
- 表格/PDF/图片解析。
- 向量索引选型。
- rerank 和 embedding 模型优化。
- 评测集构造。

系统设计题候选：

```text
设计一个企业级知识库问答系统。
设计一个搜索增强的智能客服。
设计一个能处理表格和 PDF 的 RAG 系统。
```

bad case 候选：

```text
正确文档不存在。
文档存在但解析失败。
正确 chunk 没召回。
召回到了但排序靠后。
正确证据在上下文里但模型幻觉。
引用不能支持答案。
```

## 6. 字节路径卡

字节风格关键词：

```text
指标、实验、效率、代码能力、快速迭代、成本延迟
```

### 6.1 字节一面

2 小时专题替换槽：

```text
替换 `74` 的 80-100 分钟专题槽：
字节一面/代码面优先选 `44`，只默写 LRU、限流、TopK 或 SSE 中 1 题。
非代码面优先选 `54`，准备指标、A/B 和成本排查。
项目表达仍按 `74` 默认路线完成。
```

候选回答：

1. 代码题复杂度。
2. 为什么这样设计缓存/限流。
3. 指标怎么定义。
4. A/B 怎么做。
5. 成本突然上涨怎么排查。
6. 项目中你最有价值的优化是什么。

字节表达句：

```text
我会先定义指标，再做实验验证。比如 RAG 优化不只看回答是否更顺，而是看 Recall@K、引用准确率、P95 延迟和成本有没有一起满足护栏。
```

15 秒指标模板：

```text
我不只看 answer good/bad，会拆成任务成功率、工具成功率、人工接管率、p95 延迟、单次成本和安全拦截率。
```

再压缩成一行：质量指标 + SLO 护栏 + 成本护栏，例如 `task_success_rate / p95_latency / cost_per_successful_task / unsafe_action_rate`。

### 6.2 字节二面

1 天公司权重提示：

1 天仍执行 `80 -> 74 -> 69/52/41 -> 77 -> 66 -> 78`。本段只替换下午 1-2 个专题：

- 代码题和小工程题：选 `44` 或 `45`。
- 系统设计 / 指标 / 成本：选 `32` 或 `54`。

系统设计重点：

- 高并发模型调用。
- 模型网关限流和 fallback。
- RAG 延迟优化。
- Agent 最大步数和循环防护。
- 日志和 trace。

取舍候选：

- topK 大小对准确率和延迟的影响。
- rerank 是否每次都调用。
- 缓存会不会影响知识更新。
- 小模型路由能省成本但可能损失质量。

## 8. 云厂商 / 企业服务路径卡

风格关键词：

```text
多租户、权限、审计、私有化、SLA、交付、可运维
```

### 8.1 一面

2 小时专题替换槽：

```text
替换 `74` 的 80-100 分钟专题槽：
云厂商/企业服务优先选 `32` 准备模型网关和平台治理。
如果 JD 写 MCP/OpenAPI，改选 `08`；如果写安全审计，改选 `71` / `54`。
只选一个专题，不展开完整平台复习。
```

候选回答：

1. 多租户怎么隔离。
2. MCP 能解决什么问题，不能解决什么问题。
3. 工具权限放在哪一层。
4. 模型网关如何限流和审计。
5. 私有化部署怎么考虑。
6. SLA 怎么保障。

表达句：

```text
企业服务场景里，模型效果只是其中一部分。真正落地还要考虑租户隔离、权限、审计、可观测、成本和私有化交付。
```

### 8.2 二面/架构面

系统设计题候选：

```text
设计一个企业大模型平台。
设计一个支持 MCP 的工具接入平台。
设计一个多租户知识库系统。
设计一个模型网关和 Prompt 管理平台。
```

架构面候选说明：

- 租户 ID 如何贯穿检索、工具、模型调用和日志。
- 权限过滤是在检索前还是检索后。
- 工具调用是否有风险分级。
- 调用链 trace 怎么串起来。
- Prompt 和模型版本如何灰度。
- 客户私有化环境如何接内部系统。

## 12. 反问按公司调整

腾讯：

```text
团队现在的大模型应用更关注用户体验提升，还是内部效率提升？
当前业务里 AI Agent 最大的落地难点是效果、延迟、成本，还是权限和安全？
```

阿里/阿里云：

```text
团队的大模型能力目前是偏单业务交付，还是在建设统一平台？
Agent 工具和模型网关这类能力是否已经平台化，还是各业务线分别建设？
```

百度：

```text
团队在 RAG/搜索增强方向更关注检索排序优化，还是模型生成质量？
评测体系现在更多依赖离线标注集，还是线上用户反馈？
```

字节：

```text
团队评估大模型应用效果时，最核心的业务指标和护栏指标分别是什么？
模型、Prompt 或检索策略变更通常怎么做实验和灰度？
```

云厂商/企业服务：

```text
客户落地大模型应用时，最常见的阻碍是数据接入、私有化部署、权限安全，还是效果评测？
团队对 MCP/OpenAPI 工具接入这类标准化能力是否有统一规划？
```
