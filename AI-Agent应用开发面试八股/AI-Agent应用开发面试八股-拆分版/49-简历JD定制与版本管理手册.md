# 简历 JD 定制与版本管理手册

> 目标：把同一个 AI Agent / RAG 项目，按不同 JD 改成不同简历版本，并保证面试时能防守。  
> 这份文件连接 `20-简历项目Bullet优化版.md`、`37-JD关键词匹配与投递策略.md`、`38-真实JD案例填充版.md` 和 `42-项目深挖追问防守库.md`。

## 1. 为什么要做简历版本管理

AI Agent 应用开发岗位很容易出现一个问题：

```text
同一个项目
  -> RAG 岗想看检索和评估
  -> Agent 岗想看状态和工具调用
  -> 平台岗想看网关、权限、审计
  -> 后端岗想看 FastAPI、SSE、并发、稳定性
  -> 算法岗想看 embedding、rerank、微调和评测
```

如果所有岗位都投同一版简历，会出现：

- JD 写 RAG，你简历重点却在 Agent。
- JD 写后端工程，你简历全是 Prompt。
- JD 写平台治理，你简历像 Demo。
- 面试官按你写的关键词追问，你却没准备。

所以建议维护：

```text
1 份母版简历
  -> 5 类岗位版本
  -> 每次投递 1 份 JD 定制版
  -> 面试前回看对应版本
```

## 3. JD 到简历版本的流程

每次投递按 6 步：

```text
读 JD
  -> 提取关键词
  -> 判断岗位主线
  -> 从母版挑素材
  -> 改 bullet 顺序和措辞
  -> 生成面试防守清单
```

### 3.1 提取关键词

```markdown
## JD 关键词
- RAG：
- Agent：
- Tool/MCP：
- Python 后端：
- 平台治理：
- 微调/算法：
- 业务场景：
```

### 3.2 判断主线

只选一个主线，不要每个都想押：

| JD 主线 | 简历标题/项目第一句重心 |
|---|---|
| RAG | 企业知识库 / 检索增强 / 答案引用 / 评测 |
| Agent | 多步骤任务 / LangGraph / 工具调用 / 状态管理 |
| 工具平台 | OpenAPI / MCP / Tool schema / 权限审计 |
| 后端工程 | FastAPI / SSE / asyncio / 限流缓存 / 稳定性 |
| 平台网关 | 模型网关 / 多模型路由 / PromptOps / EvalOps |
| 微调算法 | SFT / LoRA / 数据构造 / embedding / rerank |

## 4. 五类简历版本

### 4.1 RAG 应用版

适合 JD：

- 知识库问答。
- 文档检索。
- 向量数据库。
- RAG 效果优化。
- 企业内部知识助手。

项目 bullet：

```text
负责企业知识库 RAG 问答链路，完成文档解析、语义切分、向量召回、rerank、上下文组装、答案生成和引用溯源；通过评测集和 bad case 回流定位召回、排序和生成问题，提升核心问题命中率和答案可追溯性。
```

关键词：

```text
RAG / chunk / embedding / vector search / hybrid search / rerank / citation / evaluation / metadata filter
```

面试防守：

- chunk 怎么切？
- 召回不准怎么定位？
- rerank 放在哪里？
- 引用怎么校验？
- 权限过滤怎么做？

准备文件：

```text
04 + 30 + 42 + 14
```

## 6. 一份项目的 5 种表达

同一个项目，不同岗位这样换重心：

| 岗位 | 第一重心 | 第二重心 | 少讲 |
|---|---|---|---|
| RAG | 检索效果 | 引用和评测 | Agent 自动化 |
| Agent | 状态和工具 | 失败恢复 | 纯向量库细节 |
| MCP | 工具协议 | 权限审计 | prompt 小技巧 |
| 后端 | 接口稳定性 | 并发和流式 | 算法论文 |
| 平台 | 复用治理 | 成本和灰度 | 单个 Demo |

通用母句：

```text
这个项目本质是一个企业知识助手，但我会根据岗位强调不同层面：RAG 岗我讲检索和评测，Agent 岗我讲状态和工具，平台岗我讲治理和复用，后端岗我讲接口和稳定性。
```

- 面试官可能按哪条追。

## 9. 简历和面试防守绑定

每条 bullet 后面都要有防守材料：

```markdown
## Bullet

## 面试官会问
1.
2.
3.

## 我的防守答案
1.
2.
3.

## 对应文件
- `42-项目深挖追问防守库.md`
- `04-RAG与向量数据库.md`
```

规则：

```text
写进简历 = 准备被追问
没有证据 = 不要写
不会防守 = 降级成“参与/了解”
```

## 10. 简历风险词

谨慎使用：

| 风险词 | 风险 | 替代 |
|---|---|---|
| 精通 | 容易被深挖到底 | 熟悉 / 有实践 |
| 负责全部 | 会追问所有细节 | 负责核心链路 / 参与设计 |
| 显著提升 | 会问具体指标 | 提升 X 指标 / 优化某类 bad case |
| 上线大规模 | 会问流量和 SLA | 内部试点 / 小范围上线 / 生产验证 |
| 自研框架 | 会问架构细节 | 封装组件 / 设计工具接入层 |

## 11. 面试前简历回看清单

面试前 30 分钟看：

- [ ] 我投的是哪一版简历。
- [ ] 简历首页关键词和 JD 是否一致。
- [ ] 第一条项目 bullet 能否 2 分钟讲清。
- [ ] 每条 bullet 是否有 2 层追问答案。
- [ ] 指标是否真实且能解释。
- [ ] 不属于我负责的部分是否表达清楚。
- [ ] 反问是否和 JD 匹配。

## 12. 最后速记

```text
简历定制不是包装自己不会的东西，
而是把真实项目翻译成目标岗位最关心的语言。
```

一句话：

```text
简历负责打开面试入口，项目证据负责守住这个入口。
```
