# 69-JD 到模拟面题单生成器

> 目标：拿到 JD 或面试通知后，10 分钟内生成一套可直接陪练的模拟面题单。  
> 这份文件不讲新知识，只做“关键词 -> 题单 -> 追问 -> 验收”的转换。

边界说明：

- 本文件只生成“本轮模拟面题单”，不保存 JD 证据和趋势解释。
- JD 类型案例回 `38`，趋势权重回 `68`，公司轮次题型回 `46`。

适用场景：

- 明天面试，不知道今晚该练什么。
- JD 很长，关键词很多，无法判断哪些会被问。
- 想让同学/朋友扮演面试官，但对方不知道怎么追问。
- 自己录音练，需要一份固定题单和评分表。

配合文件：

- `80-JD实战转化闭环工单.md`：收到明确 JD 后先建工单，本文件只负责生成题单交付部分。
- `37-JD关键词匹配与投递策略.md`：识别 JD 关键词。
- `55-公司轮次面试路径卡.md`：确定公司和轮次打法。
- `68-近期JD趋势与面试押题增量.md`：校准近期岗位趋势。
- `52-面试官陪练脚本手册.md`：按脚本追问。
- `41-面试官评分Rubric与回答自检表.md`：评分。
- `66-面试上场包与成品验收清单.md`：分层验收口径。
- `73-DataAgent与NL2SQL面试手册.md`：生成自然语言查数、NL2SQL、指标口径和 SQL 安全题单。
- `75-公司风格模拟面评分矩阵.md`：按腾讯/阿里/百度/字节等目标公司做专项追问和扣分检查。
- `76-项目表达迁移与面试官视角改写手册.md`：把简历项目改写成目标岗位和目标公司版本。
- `77-模拟面闭环数据看板与弱点修复手册.md`：根据多轮模拟趋势决定下一轮题单。

## 2. 关键词到题型映射

| JD 关键词 | 必出题型 | 高频追问 | 主复习文件 |
|---|---|---|---|
| RAG / 知识库 / AI Search | RAG 链路 + bad case | 召回不准、引用不可信、权限过滤、评测集 | `04`、`30`、`42`、`54` |
| Agent / Workflow | Agent 边界 + 工具失败 | Agent vs workflow、状态、终止条件、人工接管 | `02`、`03`、`29`、`52` |
| Memory / Context Engineering | 记忆治理 + 状态设计 | 短期/长期/结构化状态、写入策略、过期、删除、冲突处理 | `02`、`30`、`71`、`23` |
| Data Agent / NL2SQL / 查数 | 数据分析系统设计 + SQL 安全 | schema linking、指标口径、SQL AST 校验、图表解释 | `73`、`71`、`23` |
| 多模态 / 语音 / 实时 Agent | 低延迟交互 + 安全确认 | ASR 错误、barge-in、流式事件、证据冲突、人工兜底 | `02`、`05`、`54`、`78` |
| LangGraph | 图编排 + 状态恢复 | StateGraph、条件边、checkpoint、interrupt | `03`、`29`、`56` |
| Tool Calling | schema + 参数校验 | tool choice、参数错、幂等、权限、审计 | `05`、`31`、`60` |
| MCP / OpenAPI | 协议边界 + 工具平台 | MCP vs OpenAPI、OpenAPI 转 Tool、工具注册 | `08`、`31`、`56` |
| 模型网关 / LLMOps | 平台系统设计 | 路由、限流、fallback、Prompt 灰度、成本 | `32`、`51`、`53` |
| Python / FastAPI | 后端基础 + 代码题 | asyncio、SSE、限流、缓存、超时取消 | `07`、`44`、`45` |
| 大模型基础 / Embedding | 模型基础快问 + RAG 深挖 | Transformer、token、上下文窗口、embedding、rerank、temperature | `72`、`04`、`06` |
| 微调 / LoRA | RAG vs 微调 + 评估 | 何时微调、数据构造、过拟合、DPO/RLHF | `06`、`31`、`60` |
| 多租户 / 权限 | 系统设计变体 | tenant_id、metadata filter、RBAC、审计 | `67`、`54` |
| 高并发 / 低延迟 / 成本 | 架构约束题 | 缓存、并行、topK、模型路由、降级 | `60`、`67` |
| 安全 / 合规 / 风控 | 安全追问 + 系统设计约束 | Prompt injection、RAG 越权、危险工具、MCP 授权、日志脱敏 | `71`、`05`、`08` |
| Agent 成功率 / 任务达成率 | Agent 评测题 | 成功定义、失败归因、trace、人工接管 | `54`、`77` |
| MCP / A2A / Agent-to-Agent | 协议边界题 | MCP vs A2A、授权、审计、责任边界 | `71`、`68`；`08`、`31` 只补 MCP/OpenAPI 背景 |
| 浏览器 / 终端 / 代码沙盒 | 高风险工具安全题 | 沙箱、审批、文件边界、命令白名单、回滚 | `71`、`23` |
| Computer Use / Browser Agent | 观察-动作-确认题 | DOM/截图观测、allowed_domains、click/type/download 策略、用户接管、回放 | `71`、`23`、`54` |
| Long-running Agent Job | 长任务作业系统题 | job 状态、队列、checkpoint、取消、恢复、成本预算 | `67`、`23`、`44` |
| Agent SLO / Alerting | 线上稳定性追问 | p95、timeout、queue_lag、cost_per_success、unsafe_action_rate、回滚 | `54`、`78`、`80` |

判断规则：

1. JD 中出现 3 次以上的关键词，必须进题单。
2. 岗位职责里出现的关键词，比任职要求里的关键词优先级更高。
3. 简历里写过的关键词，哪怕 JD 只提一次，也要准备追问。
4. 公司近期趋势里高频出现的关键词，参考 `68` 提权。
5. 如果关键词同时属于系统设计和项目深挖，优先按项目深挖准备，因为面试官更容易从简历切入。
6. JD 出现 BI、数据分析、经营分析、自然语言查数、指标问答、报表助手、NL2SQL 时，把 `73` 作为主文件；不要只按普通 Agent 准备。
7. JD 出现 MCP / A2A / Agent-to-Agent 时，必须加一道“协议边界 + 安全责任”题，避免只背名词。
8. JD 出现浏览器、终端、代码执行、自动化运维时，必须加一道高风险工具安全题。
9. JD 出现语音、实时对话、多模态、屏幕共享、会议助手、客服助手时，必须加一道“流式交互 + 打断恢复 + 高风险动作确认”题。
10. JD 出现 browser agent、computer use、网页操作、RPA、自动填表、自动测试时，必须加一道“观察通道 + 动作策略 + 接管审计”题。
11. JD 出现 memory、personalization、用户画像、长期偏好、上下文工程时，必须加一道“记忆写入策略 + 删除/过期 + 隐私边界”题。
12. JD 出现办公自动化、批量处理、运维排障、代码执行、报告生成、长任务时，必须加一道“job 队列 + checkpoint + cancel/recover”题。
13. JD 出现平台、云厂商、ToB、稳定性、SLA/SLO、监控告警时，必须加一道“SLO + 告警 + 事故复盘”题。

## 2.1 新趋势代码题库

当 JD 命中新趋势时，题单至少加入 1 道小工程题或伪代码题，避免只会讲概念。

| 命中关键词 | 代码/伪代码题 | 考察点 | 主复习文件 |
|---|---|---|---|
| Tool Calling / MCP | 写一个 Tool schema validator | JSON Schema、必填参数、类型校验、错误返回 | `05`、`23`、`44` |
| Data Agent / NL2SQL | 写 SQL AST readonly validator | parser、select/with、禁多语句、limit、权限 | `73`、`23` |
| 评测 / CI / 发布门禁 | 写 eval_gate(golden_set, thresholds) | 指标阈值、失败样本、阻断发布、灰度 | `54`、`23`、`44` |
| MCP / A2A / Agent-to-Agent | 写 A2A task contract validator | task_id、capability、scope、deadline、handoff、result_schema | `71`、`23` |
| 多模态 / 语音 / 实时 Agent | 写 streaming event merger | turn_id、partial/final、barge-in、timeout、confirm_required | `02`、`23` |
| 浏览器 / 终端 / 代码执行 Agent | 写 sandbox path allowlist | 路径规范化、workspace 边界、denylist | `71`、`23` |
| Computer Use / Browser Agent | 写 browser action guard | allowed_domains、动作白名单、download/form submit 确认、screenshot trace | `71`、`23` |
| 安全沙箱 / 凭据隔离 | 写 network sandbox policy | allowed_domains、blocked_private_ip、credential_scope、egress_log | `71`、`23` |
| 工具过载 / Agent 发现 | 写 tool_agent_retrieval | capability、risk、tenant scope、recent success、排序分 | `69`、`23`、`44` |
| 高风险工具 | 写 tool risk classifier | risk_level、require_confirm、audit log | `71`、`44` |
| Agent 成功率 / trace | 写 trace span builder | request_id、node、tool、latency、error_code | `54`、`77` |
| Agent loop | 写 max-step / retry controller | 最大步数、失败重试、人工接管、fallback | `02`、`29` |
| 上下文工程 / Memory | 写 conversation compactor 或 state store | 最近窗口、摘要、结构化状态、敏感字段过滤 | `02`、`30`、`44` |
| Memory Governance | 写 memory_write_policy | 可写字段、敏感拒写、TTL、用户删除、冲突处理 | `02`、`71`、`23`、`44` |
| Long-running Agent Job | 写 AgentJobStateMachine | pending/running/waiting_approval/cancelled、checkpoint、timeout | `67`、`23`、`44` |

加入规则：

```text
一面：选 1 道实现题。
二面：选 1 道伪代码 + 追问生产边界。
代码面：选 2 道，其中 1 道必须能讲复杂度和异常处理。
```

## 3. 轮次到题单结构

### 3.1 一面题单结构

目标：

```text
验证基础概念、项目真实性、代码基础。
```

30 分钟：

| 时间 | 模块 | 题目 |
|---|---|---|
| 0-3 分钟 | 开场 | 1 分钟自我介绍 |
| 3-10 分钟 | 项目 | 介绍一个最相关项目 |
| 10-18 分钟 | P0 八股 | RAG / Agent / Tool / Python 选 4 题 |
| 18-27 分钟 | 代码 | LRU / 限流 / SSE / schema 校验选 1 题 |
| 27-30 分钟 | 反问 | 1 个岗位相关反问 |

通过标准：

- 概念题能 30-60 秒答出主干。
- 项目能讲清背景、职责、链路、难点。
- 代码题能说复杂度和边界。
- 不夸大线上指标。

### 3.2 二面题单结构

目标：

```text
验证是否解决过真实问题，能否做系统设计和技术取舍。
```

60 分钟：

| 时间 | 模块 | 题目 |
|---|---|---|
| 0-5 分钟 | 开场 | 项目 2 分钟版 + 面试官追问主责 |
| 5-20 分钟 | 项目深挖 | 三层追问：链路、bad case、指标 |
| 20-35 分钟 | 专题深挖 | RAG / Agent / MCP / LangGraph 选 1 条连续追问 |
| 35-50 分钟 | 系统设计 | 企业知识库 / 工具平台 / 模型网关选 1 题 |
| 50-56 分钟 | 技术取舍 | RAG vs 微调、Agent vs workflow、MCP vs OpenAPI |
| 56-60 分钟 | 反问 | 2 个技术反问 |

通过标准：

- 每个项目结论都有证据、指标或日志。
- bad case 能讲定位过程，不只讲结果。
- 系统设计能讲入口、核心链路、治理、指标、兜底。
- 面试官追加约束时能按 `67` 调整。

### 3.3 主管面题单结构

目标：

```text
验证业务理解、owner 意识、取舍能力、协作成熟度。
```

45 分钟：

| 时间 | 模块 | 题目 |
|---|---|---|
| 0-5 分钟 | 开场 | 你做过最有价值的 AI 应用项目 |
| 5-15 分钟 | 业务价值 | 为什么这个项目值得做？怎么衡量价值？ |
| 15-25 分钟 | 取舍 | 准确率、延迟、成本、上线周期如何取舍？ |
| 25-35 分钟 | 失败复盘 | 讲一次失败或 bad case，你怎么推动修复？ |
| 35-42 分钟 | 团队协作 | 和产品/算法/后端/业务方冲突怎么处理？ |
| 42-45 分钟 | 反问 | 问团队目标、前三个月期望、线上挑战 |

通过标准：

- 不陷入细节堆砌，能讲业务价值。
- 承认边界和代价。
- 能讲推动过程，而不是只讲技术方案。
- 反问能贴合公司和岗位。

### 3.4 代码面题单结构

目标：

```text
验证 Python 后端基础、工程化思维和 AI 应用组件实现能力。
```

45 分钟：

| 时间 | 模块 | 题目 |
|---|---|---|
| 0-5 分钟 | 澄清 | 需求、输入输出、边界 |
| 5-25 分钟 | 编码 | LRU / 滑动窗口限流 / SSE / RAG pipeline / Tool schema 校验 |
| 25-35 分钟 | 复杂度 | 时间、空间、并发安全 |
| 35-42 分钟 | 生产增强 | 日志、超时、重试、限流、异常、监控 |
| 42-45 分钟 | 复盘 | 如果放到大模型网关或 Agent 平台怎么用 |

通过标准：

- 代码主干能跑通或清晰伪代码。
- 能主动补边界 case。
- 能把小题讲成生产组件。

## 4. 公司风格题单调权

### 4.1 腾讯

加权方向：

```text
真实业务、用户体验、稳定性、效果指标、线上兜底。
```

题单必须加入：

1. 用户为什么需要这个功能？
2. 如果用户觉得答案不可信，你怎么改？
3. 如果 Agent 误操作用户数据，怎么防？
4. 如果线上 QPS 放大 10 倍，哪些模块先出问题？
5. 你项目里哪个 bad case 最真实？

验收重点：

- 能讲用户体验和业务影响。
- 能讲线上兜底。
- 不只讲框架名。

### 4.2 阿里 / 阿里云

加权方向：

```text
平台化、抽象、规模化复用、多租户、治理、工程体系。
```

题单必须加入：

1. 如果把你的项目做成平台，核心模块怎么拆？
2. 多租户权限隔离怎么做？
3. MCP / OpenAPI / RPC 怎么统一接入？
4. Prompt、模型、工具版本怎么灰度和回滚？
5. 成本、审计、稳定性怎么治理？

验收重点：

- 能从单点项目上升到平台能力。
- 能讲多租户、权限、审计、版本。
- 能讲抽象边界，不只讲业务脚本。

### 4.3 百度

加权方向：

```text
AI 平台、搜索/RAG、模型效果、后端稳定性、trace 和排障。
```

题单必须加入：

1. RAG 召回不准怎么定位？
2. trace 在 Agent/RAG 里记录哪些字段？
3. Data Agent 如何防止危险 SQL 和越权查库？
4. 模型服务挂了怎么降级？
5. 如何评估 Agent 决策链路成功率？

验收重点：

- 能讲检索和效果评估。
- 能讲后端稳定性和 trace。
- 能把算法应用和工程平台连起来。

### 4.4 字节

加权方向：

```text
复杂系统、性能成本、实验迭代、代码能力、业务结果。
```

题单必须加入：

1. Agent 的 Planning、Memory、Reflection 怎么落地？
2. 多步工具调用如何避免无限循环？
3. Prompt 版本管理和 A/B 实验怎么做？
4. 成本降低 50% 怎么做？
5. 写一个限流/缓存/SSE/Tool schema 校验小题。

验收重点：

- 回答要短、密度高、有指标。
- 能讲实验和迭代。
- 代码题不能空。

### 4.5 美团 / 京东 / 快手

加权方向：

```text
业务落地、交易/客服/内容场景、稳定性、成本收益、工程效率。
```

题单必须加入：

1. 智能客服如何转人工？
2. 退款、改价、取消订单等高风险工具如何确认？
3. 大促期间并发高怎么办？
4. 如何证明 AI 应用提升了效率或转化？
5. 如果业务方频繁改需求，怎么保证系统可维护？

验收重点：

- 能讲业务流程和风险控制。
- 能讲成本收益。
- 能讲人工接管和审计。

## 5. 30 分钟快速模拟面模板

适合只剩 2 小时准备时使用。

```markdown
# 30 分钟快速模拟面

## 0-3 分钟：开场
1. 请做一个 1 分钟自我介绍。

## 3-10 分钟：项目入口
2. 介绍一个和 JD 最相关的项目。
3. 你在里面具体负责什么？

## 10-18 分钟：JD 关键词快问
4. [关键词 1] 是什么？完整链路是什么？
5. [关键词 2] 和 [相邻概念] 有什么区别？
6. 这个能力上线后怎么评估？

## 18-25 分钟：项目深挖
7. 讲一个真实 bad case。
8. 如果这个问题线上复现，你怎么排查？

## 25-28 分钟：约束追问
9. 如果 QPS 提升 10 倍 / 成本降低 50% / 要求多租户隔离，你怎么改？

## 28-30 分钟：反问
10. 你有什么想问我的？
```

评分：

| 维度 | raw_score | grade | display | close_level | A 档表现 | B 档风险 | C 档风险 |
|---|---|---|---|---|---|---|---|

## 10. 陪练执行规则

陪练者规则：

1. 每题先让候选人完整回答，不要中途提示。
2. 如果回答超过 2 分钟还没到重点，打断并要求 30 秒版。

5. 每个系统设计都追加一个约束：高并发、权限、成本、私有化、强审计。
6. 每个“我们做了”都追问“你具体做了什么”。
7. 每个“效果变好”都追问“指标是什么”。

候选人规则：

1. 不确定时先澄清，不要硬编。
2. 没上线就说没上线，但补离线评测和下一步上线方案。
3. 不要把框架名当答案。
4. 每题尽量落到流程、坑、优化、评估、兜底。
5. 被打断时先收束，再补关键点。
