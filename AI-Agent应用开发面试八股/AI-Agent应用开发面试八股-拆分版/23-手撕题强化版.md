## 1. 滑动窗口限流

### 题目

实现一个限流器：同一个用户在任意 60 秒内最多请求 100 次。

### 考点

- deque。
- 时间窗口。
- 按用户隔离。
- 清理过期请求。

### 代码

```python
from collections import defaultdict, deque
import time


class SlidingWindowRateLimiter:
    def __init__(self, limit: int, window_seconds: int):
        self.limit = limit
        self.window = window_seconds
        self.events = defaultdict(deque)

    def allow(self, user_id: str) -> bool:
        now = time.time()
        q = self.events[user_id]

        while q and now - q[0] >= self.window:
            q.popleft()

        if len(q) >= self.limit:
            return False

        q.append(now)
        return True
```

### 复杂度

- 单次均摊 O(1)。
- 空间 O(用户数 * 窗口内请求数)。

### AI 应用追问

Q：大模型应用为什么需要限流？

A：模型调用成本高且上游不稳定，要按用户、租户、模型和接口限流，防止单个用户打满 token 或工具资源。

## 1.1 Sandbox Path Allowlist

### 题目

实现一个路径校验函数：Agent 只能访问 workspace 内文件，禁止 `..` 越界、软链接逃逸和敏感文件。

### 代码

```python
from pathlib import Path


SENSITIVE_NAMES = {".env", "id_rsa", "credentials.json"}


def is_allowed_path(workspace: str, user_path: str) -> bool:
    root = Path(workspace).resolve()
    target = (root / user_path).resolve()

    try:
        target.relative_to(root)
    except ValueError:
        return False

    if any(part in SENSITIVE_NAMES for part in target.parts):
        return False

    return True
```

### 复杂度

- 路径解析和父路径判断通常是 O(path length)。
- 不依赖字符串前缀判断，避免 `/tmp/ws2` 伪装成 `/tmp/ws`。

### AI 应用追问

Q：为什么代码执行 Agent 需要这个？

A：浏览器、终端和代码执行 Agent 可能被 prompt injection 诱导读取密钥、改 workspace 外文件或访问生产配置。路径校验要用规范化后的真实路径，并配合命令白名单、网络边界、diff 审计和人工确认。

## 1.2 Network Sandbox Policy

> 和 `1.1` 不同：Path Allowlist 管文件系统边界，Network Sandbox 管出站网络和凭据边界。完整版见 `10.6`。

### 题目

浏览器/代码执行 Agent 发起网络请求前，校验域名、内网 IP、凭据范围和审计字段。

### 核心代码

```python
import ipaddress
from urllib.parse import urlparse


def is_private_ip(ip: str) -> bool:
    addr = ipaddress.ip_address(ip)
    return addr.is_private or addr.is_loopback or addr.is_link_local


def allow_egress(request: dict, policy: dict) -> bool:
    domain = urlparse(request["url"]).netloc
    if domain not in policy["allowed_domains"]:
        return False
    if request.get("resolved_ip") and is_private_ip(request["resolved_ip"]):
        return False
    if request.get("credential_scope") not in policy["allowed_credential_scopes"]:
        return False
    return True
```

### AI 应用追问

Q：为什么不能只做域名白名单？

A：域名可能解析到内网、localhost 或 link-local 地址。生产里要按解析后 IP 再拦截，并记录 egress log：url、resolved_ip、decision、reason、credential_scope、trace_id。

## 2. TTL Cache

### 题目

实现一个带过期时间的缓存。

### 代码

```python
import time


class TTLCache:
    def __init__(self):
        self.data = {}

    def set(self, key, value, ttl_seconds):
        expire_at = time.time() + ttl_seconds
        self.data[key] = (value, expire_at)

    def get(self, key):
        item = self.data.get(key)
        if item is None:
            return None

        value, expire_at = item
        if time.time() >= expire_at:
            self.data.pop(key, None)
            return None

        return value
```

### AI 应用追问

Q：RAG 答案缓存 key 怎么设计？

A：不能只用 query。至少要包含 tenant_id、user_permission_version、query_normalized、retrieval_strategy_version、prompt_version、model_name。否则可能权限泄漏或版本污染。

## 3. 带并发上限的异步任务执行器

### 题目

给一批 query，并发调用模型，但最多同时 5 个请求。

### 代码

```python
import asyncio


async def run_with_limit(items, worker, limit=5):
    sem = asyncio.Semaphore(limit)

    async def run_one(item):
        async with sem:
            return await worker(item)

    tasks = [asyncio.create_task(run_one(item)) for item in items]
    return await asyncio.gather(*tasks, return_exceptions=True)
```

### 追问

Q：`return_exceptions=True` 有什么用？

A：避免一个任务失败导致所有任务直接抛出。批量 embedding、批量评测时可以记录失败项并重试。

## 4. Tool Call 去重

### 题目

Agent 可能重复调用同一个只读工具，如何在一次会话内去重？

### 代码

```python
import json
import hashlib


def make_tool_call_key(tool_name: str, arguments: dict) -> str:
    normalized = json.dumps(arguments, sort_keys=True, ensure_ascii=False)
    raw = f"{tool_name}:{normalized}"
    return hashlib.sha256(raw.encode("utf-8")).hexdigest()


class ToolCallCache:
    def __init__(self):
        self.results = {}

    def get_or_call(self, tool_name, arguments, caller):
        key = make_tool_call_key(tool_name, arguments)
        if key in self.results:
            return self.results[key]

        result = caller(tool_name, arguments)
        self.results[key] = result
        return result
```

### 追问

Q：写工具能这样缓存吗？

A：不能。写操作要用幂等 key 和业务状态查询，而不是简单缓存结果。

## 5. 引用编号校验

### 题目

RAG 回答里要求引用 `[1] [2]`，如何校验引用是否来自本次上下文？

### 代码

```python
import re


def extract_citations(answer: str) -> set[int]:
    return {int(x) for x in re.findall(r"\[(\d+)\]", answer)}


def validate_citations(answer: str, context_docs: list) -> bool:
    cited = extract_citations(answer)
    valid_ids = set(range(1, len(context_docs) + 1))
    return cited.issubset(valid_ids)
```

### 追问

Q：引用编号合法就代表答案真实吗？

A：不代表。它只能防止编造不存在的引用。还要检查答案内容是否真的被引用片段支持，可以用规则、LLM-as-judge 或人工评测。

## 6. 文档去重

### 题目

入库前对文档 chunk 去重。

### 简单 hash 去重

```python
import hashlib


def normalize_text(text: str) -> str:
    return " ".join(text.lower().split())


def deduplicate_chunks(chunks):
    seen = set()
    result = []

    for chunk in chunks:
        normalized = normalize_text(chunk)
        digest = hashlib.md5(normalized.encode("utf-8")).hexdigest()
        if digest not in seen:
            seen.add(digest)
            result.append(chunk)

    return result
```

### 追问

Q：语义重复怎么处理？

A：hash 只能处理完全或近似文本一致。语义重复可以用 embedding 相似度聚类，但要小心误删不同版本、不同部门的文档。

## 7. TopK 小根堆

### 题目

从海量分数中找 top K。

### 代码

```python
import heapq


def top_k(items, k):
    heap = []
    for item, score in items:
        if len(heap) < k:
            heapq.heappush(heap, (score, item))
        elif score > heap[0][0]:
            heapq.heapreplace(heap, (score, item))

    return sorted(heap, reverse=True)
```

### 复杂度

- 时间 O(n log k)。
- 空间 O(k)。

### AI 应用追问

Q：向量数据库 top_k 是不是这样实现？

A：小规模精确检索可以类似 top_k；大规模向量检索通常用 ANN 索引，比如 HNSW、IVF、PQ，牺牲少量精度换速度。

## 8. 简单 BM25 评分骨架

### 题目

写一个简化 BM25 评分函数。

### 代码

```python
import math
from collections import Counter


def bm25_score(query_terms, doc_terms, df, total_docs, avgdl, k1=1.5, b=0.75):
    score = 0.0
    doc_len = len(doc_terms)
    tf = Counter(doc_terms)

    for term in query_terms:
        if term not in tf:
            continue
        n_q = df.get(term, 0)
        idf = math.log(1 + (total_docs - n_q + 0.5) / (n_q + 0.5))
        freq = tf[term]
        denom = freq + k1 * (1 - b + b * doc_len / avgdl)
        score += idf * (freq * (k1 + 1)) / denom

    return score
```

### 追问

Q：BM25 在 RAG 里有什么价值？

A：它对关键词、专有名词、编号、错误码、函数名更稳，能补向量检索在精确匹配上的短板。

## 9. Metric Contract Validator

### 题目

Data Agent 生成查询前，先校验指标口径：指标是否存在、用户是否有权限、时间粒度是否允许、权威来源是否冲突。

### 代码

```python
def validate_metric_contract(metric: dict, user_scope: dict) -> tuple[bool, str]:
    if not metric.get("metric_id") or not metric.get("owner"):
        return False, "missing metric identity"

    if metric.get("status") != "approved":
        return False, "metric not approved"

    if user_scope["role"] not in metric.get("allowed_roles", set()):

    return True, "ok"
```

### 追问

Q：为什么 Data Agent 不能直接让模型生成 SQL？

A：因为业务指标的难点经常不是 SQL 语法，而是口径、权限、时间粒度和权威来源。先校验 Metric Contract，再做 SQL AST 和权限过滤，才能避免“查出来了但口径错了”。

## 9.1 SQL 只读校验

### 题目

数据分析 Agent 生成 SQL 后，如何做简单只读校验？

### 简单版

```python
import re


FORBIDDEN = {
    "insert", "update", "delete", "drop", "alter",
    "truncate", "create", "replace", "grant", "revoke",
}


def is_readonly_sql(sql: str) -> bool:
    cleaned = re.sub(r"--.*?$|/\*.*?\*/", " ", sql, flags=re.S | re.M)
    tokens = re.findall(r"[a-zA-Z_]+", cleaned.lower())
    if not tokens:
        return False
    if tokens[0] not in {"select", "with"}:
        return False
    return not any(token in FORBIDDEN for token in tokens)
```

### 高分补充

生产不能只靠正则，应该用 SQL parser/AST 校验，限制表白名单、列权限、limit、执行超时和 cost。

如果面试官继续追问 Data Agent / NL2SQL 系统设计，用 `73-DataAgent与NL2SQL面试手册.md` 把这道手撕题扩展成完整链路：自然语言理解、schema linking、指标口径、SQL 生成、SQL 安全、权限过滤、查询执行、结果解释和审计。

### 伪 AST 版

```python
def validate_sql_ast(ast, allowed_tables: set[str], allowed_columns: dict[str, set[str]]) -> bool:
    if ast.type not in {"select", "with"}:
        return False
    if ast.has_multiple_statements:
        return False
    if ast.has_mutation_node:
        return False

    for table in ast.tables:
        if table not in allowed_tables:
            return False

    for table, column in ast.columns:
        if column not in allowed_columns.get(table, set()):
            return False

    if ast.limit is None or ast.limit > 1000:
        return False

    return True
```

面试解释：

```text
这段不是绑定某个 SQL parser，而是展示生产校验思路：只允许 select/with，拒绝多语句和 mutation node，再做表白名单、列权限和 limit。真正落地时还要加租户过滤、查询超时、cost 估算和审计。
```

## 10.1 Eval Gate 发布门禁

### 题目

RAG/Agent 每次发布前跑 golden set，低于阈值就阻断发布。

### 代码

```python
def eval_gate(results: list[dict], thresholds: dict) -> dict:
    if not results:
        return {"pass": False, "metrics": {}, "failed": [{"metric": "dataset", "reason": "empty"}]}

    total = len(results)
    p95_index = max(0, (95 * total + 99) // 100 - 1)
    metrics = {
        "task_success": sum(r["task_success"] for r in results) / total,
        "faithfulness": sum(r["faithfulness"] for r in results) / total,
        "safety_pass": sum(r["safety_pass"] for r in results) / total,
        "p95_latency_ms": sorted(r["latency_ms"] for r in results)[p95_index],
        "avg_cost": sum(r["cost"] for r in results) / total,
    }

    failed = []
    for name, threshold in thresholds.items():
        value = metrics[name]
        if name.startswith("p95_"):
            ok = value <= threshold
        elif name.startswith("avg_cost"):
            ok = value <= threshold
        else:
            ok = value >= threshold
        if not ok:
            failed.append({"metric": name, "value": value, "threshold": threshold})

    return {"pass": len(failed) == 0, "metrics": metrics, "failed": failed}
```

### 追问

Q：为什么这题对 AI Agent 岗重要？

A：生产里 prompt、模型、检索配置、工具 schema 改动都可能引入回归。发布门禁能把“感觉变好”变成可量化的 golden set、bad case 和安全阈值。

## 10.2 A2A Task Contract Validator

### 题目

多 Agent 委派任务前，校验 task contract，避免权限不清、交付物不清和责任边界不清。

### 代码

```python
REQUIRED_TASK_FIELDS = {
    "task_id", "from_agent", "to_agent", "capability",
    "scope", "deadline_ms", "input_schema", "result_schema",
}


def validate_a2a_task_contract(contract: dict, allowed_capabilities: set[str]) -> tuple[bool, str]:
    missing = REQUIRED_TASK_FIELDS - contract.keys()
    if missing:
        return False, f"missing fields: {sorted(missing)}"

    if contract["capability"] not in allowed_capabilities:
        return False, "capability not allowed"

    if contract["deadline_ms"] <= 0 or contract["deadline_ms"] > 30000:
        return False, "invalid deadline"

    scope = contract["scope"]
    if not scope.get("tenant_id") or not scope.get("permission_token"):
        return False, "missing auth scope"

    if contract.get("requires_human_approval") and not contract.get("approval_id"):
        return False, "missing approval_id"

    return True, "ok"
```

### 追问

Q：A2A 协议本身能解决安全吗？

A：不能。A2A 只提供 Agent 间任务委派和通信边界，生产里仍要做身份传递、授权范围、超时、审计、结果验收和高风险动作确认。

## 10.3 Streaming Event Merger

### 题目

实时语音/多模态 Agent 收到 partial、final、barge-in 事件，如何合并成稳定状态？

### 代码

```python
def merge_stream_event(state: dict, event: dict) -> dict:
    turn_id = event["turn_id"]
    turn = state.setdefault(turn_id, {"partial": "", "final": "", "cancelled": False})

    if event["type"] == "barge_in":
        turn["cancelled"] = True
        turn["partial"] = ""
        return state

    if turn["cancelled"]:
        return state

    if event["type"] == "partial_transcript":
        turn["partial"] = event["text"]
    elif event["type"] == "final_transcript":
        turn["final"] = event["text"]
        turn["partial"] = ""
    elif event["type"] == "tool_action":
        turn["pending_action"] = event
        turn["confirm_required"] = event.get("risk_level") == "high"

    return state
```

### 追问

Q：实时 Agent 的难点是什么？

A：难点不是流式输出本身，而是 ASR 错误、用户打断、跨模态证据冲突、低延迟预算和高风险动作确认。trace 里要保留 turn_id、partial/final、barge-in、置信度和审批结果。

## 10.4 Realtime Eval Gate

### 题目

实时 Agent 上线前，按事件日志计算首响延迟、打断恢复、误触发和安全确认，通过阈值才允许发布。

### 代码

```python
def realtime_eval_gate(events: list[dict], thresholds: dict) -> dict:
    turns = {}
    for e in events:
        turn = turns.setdefault(e["turn_id"], {"start": None, "first": None, "barge": 0, "unsafe": 0, "confirm": 0})
        if e["type"] == "user_start":
            turn["start"] = e["ts_ms"]
        elif e["type"] == "assistant_first_token" and turn["first"] is None:
            turn["first"] = e["ts_ms"]
        elif e["type"] == "barge_in":
            turn["barge"] += 1
        elif e["type"] == "unsafe_trigger":
            turn["unsafe"] += 1
        elif e["type"] == "confirm_required":
            turn["confirm"] += 1

    latencies = [
        t["first"] - t["start"]
        for t in turns.values()
        if t["start"] is not None and t["first"] is not None
    ]
    total = max(len(turns), 1)
    metrics = {
        "avg_first_token_ms": sum(latencies) / max(len(latencies), 1),
        "barge_in_rate": sum(t["barge"] > 0 for t in turns.values()) / total,
        "unsafe_trigger_rate": sum(t["unsafe"] for t in turns.values()) / total,
        "confirm_rate": sum(t["confirm"] for t in turns.values()) / total,
    }

    failed = []
    for name, threshold in thresholds.items():
        ok = metrics[name] <= threshold
        if not ok:
            failed.append({"metric": name, "value": metrics[name], "threshold": threshold})
    return {"pass": len(failed) == 0, "metrics": metrics, "failed": failed}
```

### 追问

Q：为什么实时 Agent 要单独评测？

A：实时场景的风险不只在答案质量，还在首响延迟、打断恢复、误触发和高风险动作确认。离线文本评测过了，不代表语音客服或会议助手能上线。

## 10.5 Tool Risk Classifier

### 题目

给一个工具调用请求，判断风险等级、是否需要确认，以及审计字段是否齐全。

### 代码

```python
HIGH_RISK_TOOLS = {"payment", "delete_file", "send_email", "execute_command"}
WRITE_PREFIXES = ("create_", "update_", "delete_", "send_")


def classify_tool_risk(call: dict) -> dict:
    name = call["tool_name"]
    args = call.get("args", {})
    risk = "low"
    reasons = []

    if name in HIGH_RISK_TOOLS or name.startswith(WRITE_PREFIXES):
        risk = "high"
        reasons.append("external side effect")
    if args.get("contains_secret"):
        risk = "high"
        reasons.append("secret exposure")
    if not call.get("idempotency_key") and risk == "high":
        reasons.append("missing idempotency_key")

    return {
        "risk_level": risk,
        "require_confirm": risk == "high",
        "audit_required": True,
        "reasons": reasons,
    }
```

### 追问

Q：为什么要单独做工具风险分类？

A：模型选择工具前后都可能出错。生产里要把读/写、内网/外部、副作用、敏感字段、幂等键和审批记录作为应用层规则，而不是让模型自己判断风险。

## 10.6 Browser Action Guard

### 题目

Browser Agent 准备执行网页动作前，校验域名、动作类型和风险等级。

### 代码

```python
from urllib.parse import urlparse


SAFE_ACTIONS = {"navigate", "read", "click", "type"}
CONFIRM_ACTIONS = {"submit", "download", "send_message", "payment", "delete"}


def guard_browser_action(action: dict, allowed_domains: set[str]) -> tuple[bool, str]:
    url = action.get("url", "")
    domain = urlparse(url).netloc
    if domain not in allowed_domains:
        return False, "domain not allowed"

    action_type = action.get("type")
    if action_type not in SAFE_ACTIONS | CONFIRM_ACTIONS:
        return False, "unknown action"

    if action.get("contains_secret"):
        return False, "secret exposure risk"

    if action_type in CONFIRM_ACTIONS and not action.get("approval_id"):
        return False, "approval required"

    if action.get("confidence", 1.0) < 0.8:
        return False, "low confidence, require takeover"

    return True, "ok"
```

### 追问

Q：为什么 Browser Agent 不能只靠模型判断是否点击？

A：网页内容可能包含 prompt injection，截图和 DOM 也可能被误读。动作策略必须在应用层硬校验，尤其是跨域、下载、提交表单、付款、删除、发送消息和暴露凭据这些有外部影响的动作。

```python
def trace_to_eval_case(trace: dict, label: dict, dataset_version: str) -> dict:
    failed_span = next(
        (span for span in trace["spans"] if span.get("status") == "failed"),
        trace["spans"][-1],
    )

    return {
        "case_id": f"case_{trace['trace_id']}",
        "trace_id": trace["trace_id"],
        "dataset_version": dataset_version,
        "input": trace["user_input"],
        "expected": label["expected"],
        "actual": trace.get("final_answer"),
        "failure_type": label["failure_type"],
        "failed_node": failed_span["node"],
        "span_id": failed_span["span_id"],
        "judge_version": label.get("judge_version", "human_v1"),
    }
```

### 追问

Q：为什么要把 trace 和 eval 关联？

A：否则线上问题只能靠人记忆修。关联后可以从失败 span 定位根因，把样本加入 bad case set，后续 prompt、模型、检索、工具 schema 变更都跑回归，防止同类问题反复出现。

## 10.8 Network Sandbox Policy

### 题目

浏览器/代码执行 Agent 发起网络请求前，校验域名、内网 IP、凭据范围和审计字段。

### 代码

```python
import ipaddress
from urllib.parse import urlparse


def is_private_ip(ip: str) -> bool:
    addr = ipaddress.ip_address(ip)
    return addr.is_private or addr.is_loopback or addr.is_link_local


def network_sandbox_decision(request: dict, policy: dict) -> tuple[str, str]:
    domain = urlparse(request["url"]).netloc
    if domain not in policy["allowed_domains"]:
        return "reject", "domain not allowed"

    resolved_ip = request.get("resolved_ip")
    if resolved_ip and is_private_ip(resolved_ip) and not policy.get("allow_private_ip"):
        return "reject", "private ip blocked"

    credential_scope = request.get("credential_scope")
    if credential_scope and credential_scope not in policy["allowed_credential_scopes"]:
        return "reject", "credential scope not allowed"

    if request.get("method") not in {"GET", "HEAD", "POST"}:
        return "reject", "method not allowed"

    if request.get("method") == "POST" and not request.get("approval_id"):
        return "require_confirm", "write-like request needs approval"

    return "allow", "ok"
```

### 追问

Q：为什么要同时校验域名和 IP？

A：域名可能解析到内网或本机地址，导致 SSRF 或访问生产内网。生产里还要记录 egress log：url、resolved_ip、decision、reason、credential_scope 和 trace_id。

## 10.9 Tool / Agent Retrieval

### 题目

工具或子 Agent 太多时，如何按能力、风险、租户范围和近期成功率排序，避免 tool overload？

### 代码

```python
def score_candidate(query_caps: set[str], candidate: dict, tenant_id: str) -> float:
    capability_match = len(query_caps & set(candidate["capabilities"]))
    if capability_match == 0:
        return -1.0

    if tenant_id not in candidate["tenant_scope"] and "*" not in candidate["tenant_scope"]:
        return -1.0

    risk_penalty = {"low": 0.0, "medium": 0.2, "high": 0.5}[candidate["risk_level"]]
    success_bonus = candidate.get("recent_success_rate", 0.5)
    latency_penalty = min(candidate.get("p95_latency_ms", 1000) / 10000, 0.3)

    return capability_match + success_bonus - risk_penalty - latency_penalty


def retrieve_tools(query_caps: set[str], candidates: list[dict], tenant_id: str, top_k: int = 5):
    scored = [
        (score_candidate(query_caps, c, tenant_id), c)
        for c in candidates
    ]
    valid = [(score, c) for score, c in scored if score >= 0]
    return [c for score, c in sorted(valid, key=lambda x: x[0], reverse=True)[:top_k]]
```

### 追问

Q：为什么不能把所有工具都塞给模型？

A：工具越多越容易选错、成本越高、提示越长，危险工具也更容易被误用。生产里应先做工具/Agent 检索和风险过滤，只把当前任务、租户和权限范围内最相关的少量候选暴露给模型。

## 10.10 Memory Write Policy

### 题目

Agent 想把一条信息写入长期记忆，如何判断允许、拒绝还是需要用户确认？

### 代码

```python
SENSITIVE_CATEGORIES = {"password", "token", "id_card", "bank_card", "medical"}
CONFIRM_CATEGORIES = {"preference", "profile", "long_term_goal"}


def memory_write_policy(candidate: dict, user_scope: dict) -> tuple[str, str]:
    if candidate.get("category") in SENSITIVE_CATEGORIES:
        return "reject", "sensitive memory"

    if candidate.get("source") not in {"user_explicit", "tool_verified"}:

    if candidate.get("tenant_id") != user_scope["tenant_id"]:
```

Q：用户要求删除记忆怎么办？

A：不能只在主库打标。要同步删除或失效主存储、向量索引、缓存和下游摘要，只保留脱敏审计记录，例如 memory_id、delete_time、operator、reason。

## 10.11 Memory Delete Policy

### 题目

用户要求删除长期记忆时，生成删除计划：主库删除、向量索引失效、缓存清理、摘要重建和脱敏审计。

### 代码

```python
def memory_delete_plan(memory: dict, requester: dict) -> tuple[bool, list[str]]:
    if memory["tenant_id"] != requester["tenant_id"]:
        return False, ["tenant mismatch"]
    if memory["user_id"] != requester["user_id"] and requester.get("role") != "admin":
        return False, ["permission denied"]

    steps = [
        f"delete_primary:{memory['memory_id']}",
        f"tombstone_vector:{memory['memory_id']}",
        f"purge_cache:{memory['memory_id']}",
        f"rebuild_summary:{memory['user_id']}",
        f"audit_delete:{memory['memory_id']}",

```

### 追问

Q：为什么不能只删数据库一行？

A：长期记忆通常会进入向量索引、缓存和摘要。只删主库会留下可召回残影，所以要做 tombstone、缓存清理、摘要重建和脱敏审计。

## 10.12 Agent Job State Machine

### 题目

长任务 Agent 支持提交、运行、等待审批、取消、失败和 checkpoint 恢复。

### 代码

```python
VALID_TRANSITIONS = {
    "pending": {"running", "cancelled"},
    "running": {"waiting_approval", "succeeded", "failed", "cancel_pending"},
    "waiting_approval": {"running", "cancel_pending", "failed"},
    "cancel_pending": {"cancelled", "failed"},
    "failed": {"pending"},
    "succeeded": set(),
    "cancelled": set(),
}


def transition(job: dict, next_status: str, **updates) -> dict:
    current = job["status"]
    if next_status not in VALID_TRANSITIONS[current]:
        raise ValueError(f"invalid transition: {current} -> {next_status}")

    new_job = {**job, **updates, "status": next_status}
    if "checkpoint_id" in updates:
        new_job["last_checkpoint_id"] = updates["checkpoint_id"]
    return new_job


def request_cancel(job: dict) -> dict:
    if job["status"] in {"succeeded", "cancelled"}:
        return job
    if job["status"] == "pending":
        return transition(job, "cancelled")
    return transition(job, "cancel_pending", cancel_requested=True)
```

### 追问

Q：为什么取消不直接 kill worker？

A：长任务可能正在执行外部写操作，直接 kill 会留下半完成状态。更稳的是标记 cancel_requested，让当前 step 在安全点停止；如果已经执行高风险动作，要走补偿、回滚或人工接管。

## 11. Prompt 版本选择

### 题目

### 代码

```python
class PromptRegistry:
    def __init__(self):
        self.prompts = {}

    def register(self, name, version, template):
        self.prompts[(name, version)] = template

    def get(self, name, version):
        key = (name, version)
        if key not in self.prompts:
            raise KeyError(f"prompt not found: {name}@{version}")
        return self.prompts[key]


def build_prompt(registry, task, version, **kwargs):
    template = registry.get(task, version)
    return template.format(**kwargs)
```

### 追问

Q：Prompt 为什么要版本化？

A：方便灰度、回滚、A/B 测试和 trace 复现。否则线上 badcase 很难知道当时用了哪个 Prompt。

## 13.1 State Store Update

### 题目

Agent 每轮对话后，把结构化状态写入 state store：保留最近消息、摘要历史、工具结果摘要，并过滤敏感字段。

### 代码

```python
SENSITIVE_KEYS = {"password", "token", "secret", "id_card"}


def update_state_store(state: dict, event: dict, max_recent: int = 6) -> dict:
    new_state = {**state, "version": state.get("version", 0) + 1}
    messages = new_state.setdefault("recent_messages", [])

    if event["type"] == "message":
        messages.append({"role": event["role"], "content": event["content"]})
        new_state["recent_messages"] = messages[-max_recent:]

    if event["type"] == "tool_result":
        safe_result = {
            k: v for k, v in event["result"].items()
            if k not in SENSITIVE_KEYS
        }
        new_state.setdefault("tool_summaries", {})[event["tool_name"]] = safe_result

    if event["type"] == "user_confirm":
        new_state.setdefault("confirmations", {})[event["action_id"]] = True

    return new_state
```

### 追问

Q：为什么要有结构化 state store？

A：摘要适合压缩自然语言历史，但订单号、审批状态、工具结果、权限范围这类关键状态必须结构化保存并版本化，否则长任务恢复和审计都不可靠。

## 14. 错误重试退避

### 题目

实现指数退避重试。

### 代码

```python
import time


def retry_with_backoff(fn, max_retries=3, base_delay=0.5):
    last_error = None
    for attempt in range(max_retries + 1):
        try:
            return fn()
        except Exception as e:
            last_error = e
            if attempt == max_retries:
                break
            time.sleep(base_delay * (2 ** attempt))
    raise last_error
```

### 追问

Q：所有错误都应该重试吗？

A：不是。参数错误、权限错误不应重试；网络抖动、限流、临时 5xx 可以重试。写操作要先保证幂等。
