# 75-公司风格模拟面评分矩阵

> 目标：把“公司风格”变成可执行的模拟面评分表。  
> 用法：每次模拟面前先选公司/方向，再按本文件抽题、追问、打分、生成补强任务。

这份文件不替代：

- `55-公司轮次面试路径卡.md`：负责准备路线。
- `69-JD到模拟面题单生成器.md`：负责生成题单。
- `41-面试官评分Rubric与回答自检表.md`：负责通用评分。
- `57-模拟面录音复盘与迭代训练手册.md`：负责复盘闭环。
- `76-项目表达迁移与面试官视角改写手册.md`：负责把同一项目改写成目标公司和岗位版本。

它只做一件事：让模拟面更像目标公司的真实追问方式。

---

## 1. 总评分模型

公司风格模拟面按 100 分评分：

| 维度 | 分值 | 看什么 |
|---|---:|---|
| 项目真实性 | 20 | 是否讲得出真实职责、模块、接口、数据、bad case |
| 技术主干 | 20 | RAG、Agent、Tool、MCP、LangGraph、模型基础是否清楚 |
| 工程治理 | 20 | 权限、评测、trace、成本、延迟、稳定性、灰度是否成体系 |
| 公司匹配 | 20 | 是否贴合目标公司的业务风格和岗位关键词 |
| 临场表达 | 20 | 是否结构化、能澄清、能承认边界、能接追问 |

评级：

```text
85-100：可上场，重点保持自然表达。
70-84：可面，但要补 1-2 个高风险短板。
60-69：容易被二面打穿，需要补项目证据或系统设计。
60 以下：不要继续泛读，先做一轮专项修复。
```

## 2. 腾讯模拟面矩阵

腾讯常见偏好：

- 真实用户场景。
- 体验、稳定性、兜底。
- AI 能力如何服务业务，而不是炫技术。
- 用户反馈、线上问题、投诉、人工接管。

### 2.1 腾讯一面抽题

| 题目 | 追问 | 评分点 |
|---|---|---|
| 介绍一个你做过的 RAG / Agent 项目 | 用户是谁？痛点是什么？ | 不只讲技术栈，能讲业务入口 |
| RAG 召回不准怎么办？ | 用户看到错答案会发生什么？ | 有定位、修复、兜底 |
| 客服 Agent 如何转人工？ | 什么时候必须转？怎么避免打扰？ | 风险分级和体验平衡 |
| 工具误调用怎么办？ | 用户已经受到影响怎么补救？ | 幂等、确认、审计、回滚 |
| 你怎么衡量效果？ | 有没有用户反馈或人工标注？ | 指标不是空泛准确率 |

### 2.2 腾讯二面追问

```text
你这个方案如果上线到千万级用户，会先出什么问题？
如果用户问的问题很模糊，你怎么追问澄清？
如果 RAG 答案正确但表达让用户误解，算不算 bad case？
如何设计人工接管和用户投诉闭环？
```

### 2.3 腾讯扣分项

- 只讲“模型能力强”，不讲用户体验。
- 只讲 Demo，不讲异常兜底。
- 所有问题都回答“加 prompt”。
- 没有线上指标、人工反馈或用户行为证据。

腾讯高分句：

```text
我会先从用户场景和失败兜底讲，而不是直接堆 RAG/Agent 技术。这个功能的关键不是模型能回答一次，而是用户在不确定、误答、超时和需要人工介入时都有可控路径。
```

## 3. 阿里 / 阿里云模拟面矩阵

阿里/阿里云常见偏好：

- 平台化和抽象能力。
- 多租户、权限、审计。
- 企业交付、私有化、稳定性。
- 组件复用、标准化、成本治理。

### 3.1 阿里一面抽题

| 题目 | 追问 | 评分点 |
|---|---|---|
| 你的 Agent 项目能否平台化？ | 哪些模块可复用？哪些不能？ | 能抽象租户、工具、模型、评测 |
| OpenAPI / RPC / MCP 的关系是什么？ | 企业内部系统怎么接入？ | 协议边界清楚 |
| 多租户权限怎么做？ | 缓存和日志会不会串租户？ | 权限贯穿链路 |
| 模型网关怎么设计？ | 如何做路由、限流、fallback？ | 有平台层思维 |
| 私有化部署怎么做？ | 数据不出域怎么保证？ | 部署边界清晰 |

### 3.2 阿里二面追问

```text
如果 20 个业务方都要接入你的 Agent 平台，接口和工具怎么标准化？
租户 A 的 prompt、知识库、工具和日志如何隔离？
客户要求私有化部署，但还要接云上模型，你怎么设计边界？
平台怎么做版本管理、灰度、回滚和审计？
```

### 3.3 阿里扣分项

- 只讲单业务 Demo，不讲平台复用。
- 不区分租户、用户、角色、资源权限。
- 把 MCP 当成完整安全系统。
- 不会讲日志、审计、配额和成本。

阿里高分句：

```text
我会把它拆成模型网关、工具注册、权限中心、工作流编排、评测监控和审计日志几层。业务侧看到的是可配置能力，平台侧保证多租户隔离、版本灰度、成本配额和可观测。
```

## 4. 百度模拟面矩阵

百度常见偏好：

- 搜索、检索、排序、RAG 链路。
- 数据质量、trace、评测。
- Agent 框架后端和平台能力。
- Data Agent / NL2SQL / 数据分析场景。

### 4.1 百度一面抽题

| 题目 | 追问 | 评分点 |
|---|---|---|
| RAG 的召回、重排、生成怎么配合？ | 每层怎么评估？ | 检索链路清楚 |
| embedding 和 rerank 的区别是什么？ | 为什么 rerank 更贵？ | 模型基础能落地 |
| trace 记录哪些字段？ | 怎么用 trace 定位 bad case？ | 排障链路清楚 |
| Data Agent 如何生成 SQL？ | schema linking 怎么做？ | 能接 `73` 的主链路 |
| Agent 框架后端要管什么？ | 状态、工具、权限、观测怎么设计？ | 框架思维 |

### 4.2 百度二面追问

```text
召回没命中、rerank 排错、生成幻觉，你怎么区分是哪一层的问题？
如何构建 RAG golden set？
Data Agent 生成了 SQL，但结果错了，你怎么定位？
如果指标口径冲突，系统应该相信模型还是指标平台？
```

### 4.3 百度扣分项

- RAG 只会说“向量库检索 + LLM 生成”。
- 不会讲召回率、命中率、引用准确率、faithfulness。
- 不会用 trace 定位问题。
- Data Agent 只讲 prompt，不讲 schema、SQL、安全和指标口径。

百度高分句：

```text
我会把问题拆到检索、排序、生成和后处理四层定位。每层都有独立指标和 trace 字段，bad case 回流时先判断是数据问题、召回问题、排序问题、prompt 问题还是权限/口径问题。
```

## 5. 字节模拟面矩阵

字节常见偏好：

- 工程实现、指标、实验。
- 低延迟、成本、快速迭代。
- Agent 调度、工具沙盒、稳定性。
- 代码能力和边界意识。

### 5.1 字节一面抽题

| 题目 | 追问 | 评分点 |
|---|---|---|
| Agent 多步调用如何避免无限循环？ | 最大步数之外还做什么？ | 有状态、终止、fallback |
| Prompt 版本怎么灰度？ | 回滚依据是什么？ | 实验和指标意识 |
| 成本突然翻倍怎么定位？ | token、模型、工具、重试怎么拆？ | 成本拆解清楚 |
| 流式接口怎么实现？ | 断连和重试怎么办？ | 后端基础 |
| 如何设计工具沙盒？ | 文件、终端、数据库权限怎么隔离？ | 安全边界 |

### 5.2 字节二面追问

```text
任务成功率从 80% 提到 90%，你怎么做实验？
如果平均延迟要求从 5 秒降到 2 秒，你先改哪一层？
Agent 调错工具但没有报错，你怎么发现？
如果线上 bad case 很多，如何自动聚类和回流？
```

### 5.3 字节扣分项

- 没有指标，只说“效果更好”。
- 不会拆 token 成本和工具成本。
- 不会讲实验、灰度、回滚。
- 代码题只写功能，不讲并发、异常、超时。

字节高分句：

```text
我会把优化拆成质量、延迟、成本和安全四组指标，每次只改一个变量，通过 prompt_version、model_version、tool_version 和 trace_id 关联实验结果，失败时能快速回滚。
```

## 6. 美团 / 京东模拟面矩阵

美团/京东常见偏好：

- 交易、订单、履约、客服。
- 高风险写操作。
- 稳定性、峰值流量、人工兜底。
- 业务规则复杂时的可控性。

### 6.1 抽题

| 题目 | 追问 | 评分点 |
|---|---|---|
| 设计一个订单客服 Agent | 退款、改价、取消订单怎么管？ | 高风险操作分级 |
| 如何避免 Agent 误操作交易系统？ | 用户确认够不够？ | 幂等、审批、回滚 |
| 大促高并发下 RAG/Agent 怎么降级？ | 哪些能力可以关？ | 降级策略 |
| 客服答案错了怎么补救？ | 如何记录投诉和复盘？ | 业务闭环 |
| 工具返回和用户描述冲突怎么办？ | 信谁？怎么解释？ | 数据权威源 |

高分句：

```text
交易链路里我不会让模型直接决定写操作。模型只做识别、建议和解释，真正执行要经过业务规则、用户确认、幂等校验、风险控制和审计。
```

## 7. ToB / 云厂商模拟面矩阵

ToB / 云厂商常见偏好：

- 私有化、合规、安全。
- 企业权限体系。
- 数据不出域、日志脱敏。
- 可运维、可审计、可交付。

### 7.1 抽题

| 题目 | 追问 | 评分点 |
|---|---|---|
| 私有化部署大模型应用怎么设计？ | 模型、向量库、日志放哪里？ | 部署边界 |
| 企业知识库权限怎么下推？ | 文档更新和缓存怎么处理？ | RAG 权限全链路 |
| 日志如何脱敏又能排障？ | prompt 要不要全量保存？ | 隐私和观测平衡 |
| 客户要接内部系统工具怎么办？ | OpenAPI/MCP 怎么授权？ | 工具接入治理 |
| 安全评测集怎么构建？ | 上线前拦截什么？ | 评测闭环 |

高分句：

```text
ToB 场景我会优先讲安全、权限、审计和部署边界。模型只是推理组件，真正决定能不能上线的是数据隔离、客户权限体系、日志合规、运维监控和可回滚能力。
```

## 8. 公司风格打分表

每次模拟后填：

| 公司/方向 | 维度 | A | B | C | 修正文件 |
|---|---|---|---|---|---|
| 腾讯 | 用户场景和兜底 | 能讲用户影响和补救 | 有场景但兜底弱 | 只讲技术 | `54`、`62` |

## 9. 30 分钟公司专项模拟模板

```markdown
# 公司专项模拟面

## 基本信息

- 公司/方向：
- 轮次：
- 岗位关键词：
- 简历项目：
- 本轮目标：

## 0-3 分钟：开场
1. 60 秒自我介绍。

## 3-10 分钟：项目和公司匹配
2. 介绍一个最贴合该公司的项目。
3. 这个项目为什么适合这个业务场景？

## 10-20 分钟：公司风格追问
4. 按本文件对应公司抽 3 个问题。
5. 每题至少追问 2 层：业务影响、工程实现、失败兜底。

## 20-27 分钟：系统设计或专项深挖
6. 设计一个和 JD 相关的 AI 应用系统。
7. 追加一个公司风格约束。

## 27-30 分钟：反问和评分
8. 准备 1 个贴合该公司的反问。
9. 按公司风格打分表记录 A/B/C。
```

## 10. 失败后怎么补

| 失败表现 | 说明 | 立刻补 |
|---|---|---|
| 公司风格答偏 | 没把技术映射到公司关注点 | `55`、本文件第 2-7 节 |
| 项目像编的 | 缺证据和职责边界 | `42`、`58`、`70` |
| 项目和岗位不贴 | 同一个项目没有按目标岗位重排 | `76`、`59` |
| 系统设计散 | 缺主链路和约束响应 | `51`、`67` |
| 只会概念 | 没有工程治理 | `54`、`60`、`71` |
| Data Agent 被打穿 | SQL、安全、指标口径没闭环 | `73`、`23`、`71` |
| 模型基础被追问卡住 | embedding、rerank、采样参数不稳 | `72` |
| 表达太长 | 没有 30 秒版 | `12`、`62`、`64` |

## 11. 最终速背

1. 腾讯看用户体验和兜底，别只讲技术。
2. 阿里/阿里云看平台化、多租户、权限和审计。
3. 百度看 RAG/搜索链路、trace、评测和 Data Agent。
4. 字节看指标、实验、成本、延迟和工程实现。
5. 美团/京东看交易链路和高风险写操作。
6. ToB/云厂商看私有化、安全、合规和可交付。
7. 公司专项模拟面不是背公司话术，而是把同一个项目换成目标公司关心的表达方式。
