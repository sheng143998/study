## 1. 简化版 RAG Pipeline

### 题目

写一个简化版 RAG 流程：输入用户问题，检索文档，构造 Prompt，调用模型，返回答案。

### 考点

- 检索和生成分层。
- top_k 控制。
- prompt 构造。
- 引用信息保留。
- 异常处理。

### 伪代码

```python
def rag_answer(question: str, user_id: str) -> dict:
    acl_filter = get_acl_filter(user_id)

    query = rewrite_query(question)
    docs = vector_store.search(
        query=query,
        top_k=20,
        filter=acl_filter,
    )

    ranked_docs = rerank(query, docs)
    selected_docs = ranked_docs[:5]

    context = "\n\n".join(
        f"[{i}] {doc.text}\nsource={doc.source}, page={doc.page}"
        for i, doc in enumerate(selected_docs, start=1)
    )

    prompt = f"""
你是企业知识库助手。只能基于 Context 回答。
如果 Context 中没有依据，回答不知道。
回答必须包含引用编号。

Question:
{question}

Context:
{context}
"""

    answer = llm.generate(prompt)
    return {
        "answer": answer,
        "sources": [doc.metadata for doc in selected_docs],
    }
```

### 追问

Q：如果召回为空怎么办？

A：可以返回无答案、扩大检索范围、改写 query 后重试，或转人工。不要让模型无依据硬答。

Q：如果引用编号是模型编的怎么办？

A：后处理校验引用编号是否来自 selected_docs，不合法则重试或拒答。

## 2. Hybrid Search 合并去重

### 题目

向量检索和 BM25 各返回一批结果，如何合并并排序？

### 考点

- doc_id/chunk_id 去重。
- 分数归一化。
- 加权融合。
- RRF。

### 简单加权版

```python
def normalize(scores):
    if not scores:
        return {}
    values = list(scores.values())
    min_v, max_v = min(values), max(values)
    if max_v == min_v:
        return {k: 1.0 for k in scores}
    return {
        k: (v - min_v) / (max_v - min_v)
        for k, v in scores.items()
    }


def merge_hybrid(vector_hits, bm25_hits, alpha=0.6):
    vector_scores = normalize({
        hit.chunk_id: hit.score for hit in vector_hits
    })
    bm25_scores = normalize({
        hit.chunk_id: hit.score for hit in bm25_hits
    })

    all_ids = set(vector_scores) | set(bm25_scores)
    merged = []
    for chunk_id in all_ids:
        score = (
            alpha * vector_scores.get(chunk_id, 0.0)
            + (1 - alpha) * bm25_scores.get(chunk_id, 0.0)
        )
        merged.append((chunk_id, score))

    return sorted(merged, key=lambda x: x[1], reverse=True)
```

### RRF 版

```python
def reciprocal_rank_fusion(rank_lists, k=60):
    scores = {}
    for rank_list in rank_lists:
        for rank, item in enumerate(rank_list, start=1):
            scores[item.chunk_id] = scores.get(item.chunk_id, 0.0) + 1 / (k + rank)
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)
```

## 3. Tool 参数校验与重试

### 题目

模型生成工具调用参数后，如何安全执行？

### 考点

- schema 校验。
- 鉴权。
- 超时。
- 重试。
- 错误返回给模型。
- 最大重试次数。

### 伪代码

```python
def execute_tool_call(user, tool_call, max_repair=2):
    tool = tool_registry.get(tool_call.name)
    if tool is None:
        return observation_error("unknown tool")

    for attempt in range(max_repair + 1):
        try:
            args = tool.schema.validate(tool_call.arguments)
            check_permission(user, tool, args)

            if tool.risk_level == "high":
                require_human_confirmation(user, tool, args)

            result = call_with_timeout(
                fn=tool.func,
                kwargs=args,
                timeout=tool.timeout,
            )
            return observation_success(result)

        except ValidationError as e:
            if attempt == max_repair:
                return observation_error(f"invalid arguments: {e}")
            tool_call = ask_model_to_repair_args(tool_call, str(e))

        except PermissionDenied:
            return observation_error("permission denied")

        except TimeoutError:
            return observation_error("tool timeout, please try later")
```

### 追问

Q：写操作能自动重试吗？

A：不能一概而论。非幂等写操作必须有 idempotency_key，并确认上一次是否成功。否则可能重复下单、重复扣款或重复发邮件。

## 4. JSON Repair

### 题目

模型输出 JSON 格式不稳定，如何处理？

### 考点

- structured output 优先。
- parse。
- repair prompt。
- 最大重试。
- fallback。

### 伪代码

```python
def parse_model_json(raw_text, schema, max_retry=2):
    text = raw_text
    for attempt in range(max_retry + 1):
        try:
            data = json.loads(extract_json_block(text))
            return schema.validate(data)
        except Exception as e:
            if attempt == max_retry:
                raise ValueError(f"invalid model output: {e}")

            text = llm.generate(f"""
下面的内容不是合法 JSON，或不符合 schema。
请只返回修复后的 JSON，不要解释。

schema:
{schema.json_schema()}

content:
{text}

error:
{str(e)}
""")
```

### 高分补充

生产中更推荐模型原生 structured output 或 function/tool calling，而不是依赖事后修 JSON。

## 5. FastAPI SSE 流式输出

### 题目

实现一个模型流式输出接口。

### 考点

- StreamingResponse。
- async generator。
- 异常处理。
- 断连处理。

### 伪代码

```python
from fastapi import FastAPI, Request
from fastapi.responses import StreamingResponse

app = FastAPI()


async def stream_answer(question: str, request: Request):
    try:
        async for chunk in llm.astream(question):
            if await request.is_disconnected():
                break
            yield f"data: {chunk}\n\n"
        yield "event: done\ndata: {}\n\n"
    except Exception as e:
        yield f"event: error\ndata: {str(e)}\n\n"


@app.get("/chat/stream")
async def chat_stream(question: str, request: Request):
    return StreamingResponse(
        stream_answer(question, request),
        media_type="text/event-stream",
    )
```

### 追问

Q：SSE 和 WebSocket 怎么选？

A：如果只是服务端向客户端推送 token，SSE 简单稳定；如果需要双向实时交互，WebSocket 更合适。

## 7. LRU Cache

### 题目

手写 LRU Cache。

### 考点

- 哈希表。
- 双向链表。
- O(1) get/put。

### Python 简化版

```python
from collections import OrderedDict


class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key):
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key, value):
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
```

### AI 应用关联

可用于缓存：

- 高频 query 的 RAG 结果。
- embedding 结果。
- rerank 结果。
- 模型回答。

注意缓存 key 要包含 tenant_id、权限版本和 prompt/model 版本。

```python
import heapq


def top_k_words(words, k):
    counter = Counter(words)
    return heapq.nlargest(k, counter.items(), key=lambda x: x[1])
```

## 9. 文档增量更新

### 题目

RAG 知识库中文档更新后，如何更新向量库？

### 考点

- doc_id。
- version。
- delete old chunks。
- upsert new chunks。
- 原子性。

### 伪代码

```python
def update_document(doc):
    old_version = metadata_store.get_version(doc.id)
    new_version = old_version + 1

    chunks = split_document(doc)
    records = []
    for chunk in chunks:
        records.append({
            "doc_id": doc.id,
            "chunk_id": f"{doc.id}:{new_version}:{chunk.index}",
            "version": new_version,
            "text": chunk.text,
            "vector": embedding_model.embed(chunk.text),
            "metadata": build_metadata(doc, chunk, new_version),
        })

    vector_store.delete(filter={"doc_id": doc.id})
    vector_store.upsert(records)
    metadata_store.set_version(doc.id, new_version)
```

## 10. Agent 最大步数控制

### 题目

写一个简单 Agent loop，避免无限循环。

### 考点

- max_steps。
- tool call。
- observation。
- finish 判断。

### 伪代码

```python
def run_agent(user_input, tools, max_steps=8):
    messages = [{"role": "user", "content": user_input}]

    for step in range(max_steps):
        decision = llm.decide(messages, tools=tools)

        if decision.type == "final":
            return decision.answer

        if decision.type == "tool_call":
            tool = tools[decision.tool_name]
            args = tool.schema.validate(decision.arguments)
            result = tool.call(**args)
            messages.append({
                "role": "tool",
                "name": decision.tool_name,
                "content": str(result),
            })
            continue

        return "无法处理该请求"

    return "任务步骤过多，已停止执行，请补充信息或转人工。"
```

### 追问

Q：max_steps 够了吗？

A：不够。还要有超时、token budget、重复工具调用检测、错误次数限制、人工确认和 fallback。
